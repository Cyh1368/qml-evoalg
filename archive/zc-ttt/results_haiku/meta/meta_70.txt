# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Global RZ-phase sharing  
  • Collapsing nine independent RZs into a single “rz_phase” parameter yields a ~0.03 uplift in validation accuracy (Gen61: val 0.59 → Current Best: val 0.68) while cutting parameters by eight.  
- Mixed two-qubit entanglement on nonadjacent pairs  
  • A fixed set of ∼12 combined parametrized (CRZ/CRY) and fixed (CZ/CNOT) gates (as in the Current Best program) achieves high expressivity with only 279 gates at depth 63, outperforming deeper designs (Gen61: depth 81, 297 gates).  
- Disjoint three-qubit blocks covering all qubits once  
  • Embedding exactly two ZZZ blocks ([0,4,8], [2,5,7]) and one CCRZ block ([1,3,6]) in a single layer minimizes overlap and drives the lowest generalization gap (Current Best gap 0.07 vs. Gen61 gap 0.12, Gen64 gap 0.10).  
- Four-stage layered architecture  
  • The sequence “per-qubit RY → shared RZ → mixed two-qubit entanglers → disjoint three-qubit interactions → final RY” underpins the top performer (Combined 0.61), matching and extending earlier best (Combined 0.61, test 0.64).  

## Ineffective Approaches  
- Deep, over-parameterized three-qubit layering  
  • Gen64 (“mirror_zzz_with_output_layer”) added mirrored ZZZ blocks and raised parameters to 186, yet only reached Combined 0.58 with depth 75 and 351 gates—score gains did not justify extra complexity.  
- Excessive circuit depth and gate count  
  • Gen61’s depth 81/297-gate design (Combined 0.54) and Gen64’s depth 75/351-gate variant confirm that pushing beyond ~63 depth/∼280 gates yields diminishing returns.  
- Parameter proliferation without targeted sharing  
  • Elevating parameter count (Gen61’s 138 → Gen64’s 186) without strategic tying led to zero parameter efficiency and marginal accuracy improvements.  
- Schema/key inconsistencies causing validation failures  
  • Generations 70, 72, and 73 all scored 0.0 due to mixing “wire” vs. “wires,” reusing parameter names, or mis‐specified gates—underscoring the need for strict spec syntax.  

## Implementation Insights  
- Consistent ANSATZ_SPEC key usage  
  • The Current Best program’s use of “wire” for single-qubit gates and “wires” for multi-qubit gates prevents the schema mismatches that broke Gen70 and Gen73.  
- Unique, enumerated parameter names  
  • Listing parameters as ry_0…ry_out_8, crz_0…crz_6, zzz_0…zzz_1, ccrz_0 ensures no collisions and clear gate–parameter mapping, avoiding the backend errors seen in failed variants.  
- Explicit spec listing vs. delegated builds  
  • Hard-coding the full ANSATZ_SPEC (instead of wrapping `_run(ANSATZ_SPEC)` or external specs) improves transparency and validation reliability, as demonstrated by the Current Best’s successful test passes.  
- Lightweight parameter sharing  
  • Reusing a single “rz_phase” across all qubits (instead of nine separate RZs) reduces parameter count and directly correlates with higher validation accuracy, confirming earlier findings.  

## Performance Analysis  
- Monotonic score progression with optimized complexity
