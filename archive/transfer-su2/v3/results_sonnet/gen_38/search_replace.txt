<DESCRIPTION>
The current candidate shares a single angle ("theta_ent") across CRZ and CRX gates applied to the SAME wire pairs in the antipodal shell (and across different-distance rings). This causes a near-total training collapse (accuracy stuck at 0.50, no convergence) because a Z-rotation and an X-rotation tied to the identical angle on the same qubits compose into a nearly input-independent net rotation, killing the gradient signal that should come from the entangled state. This reproduces the failure mode the task's recommendation points at.

Fix: revert to the previously validated structure (global RY + global RZ, with the RZ angle reused as the CRZ angle for the two short-range shells, which scored 0.61 with only 2 distinct params), and apply the specific recommended change — replace the distance-4 antipodal shell with genuine long-range coupling using IsingXX gates on a NEW dedicated shared parameter "theta_xx_long" instead of reusing theta_z or mixing CRZ/CRX with the same angle. This keeps generators cleanly separated (Z-type short-range, X-type long-range) so the two shells cannot destructively interfere, while adding only one extra parameter (3 distinct circuit params total, 5 with readout) to specifically target the hardest, most distance-separated correlations that the recommendation argues matter most for robust separation.

# Multi-axis shared-entangler ansatz.
#
# Design rationale:
# - A single global RY angle ("theta_ry") is applied to every qubit, and a
#   single global RZ angle ("theta_rz") is applied to every qubit. Together
#   these two shared parameters give every qubit an arbitrary rotation
#   direction (up to a global phase) once combined with the entangling
#   layers and the fact that the block is repeated 3 times.
# - A single global entangling angle ("theta_ent") drives ALL two-qubit
#   gates in the circuit, but the gate TYPE (CRZ vs CRX) and the pair
#   distance vary by "shell":
#     * Shell 1 (distance 1, nearest-neighbor ring): CRZ.
#     * Shell 2 (distance 2, skip ring): CRX.
#     * Shell 3 (distance 4, antipodal pairs): BOTH CRZ and CRX.
#   Reusing the same shared angle for gates on a different Pauli axis
#   (X vs Z) injects multi-axis correlations into the state without adding
#   a single new trainable parameter -- expressivity is added purely
#   through gate/wire structure, which is the cheapest way to broaden what
#   the circuit can represent while keeping parameter count (and therefore
#   overfitting risk on a tiny training set) unchanged.
# - Only 3 distinct circuit parameters total (+2 readout params = 5 total).
ANSATZ_SPEC = []

# Global single-qubit layer: one shared RY angle for all 8 qubits.
for _i in range(N_QUBITS):
    ANSATZ_SPEC.append({"gate": "RY", "wire": _i, "param": "theta_ry"})

# Global single-qubit layer: one shared RZ angle for all 8 qubits.
for _i in range(N_QUBITS):
    ANSATZ_SPEC.append({"gate": "RZ", "wire": _i, "param": "theta_rz"})

# Shell 1: nearest-neighbor ring (distance 1), Z-axis entangling, shared angle.
for _i in range(N_QUBITS):
    ANSATZ_SPEC.append({"gate": "CRZ", "wires": [_i, (_i + 1) % N_QUBITS], "param": "theta_ent"})

# Shell 2: skip ring (distance 2), X-axis entangling, same shared angle.
for _i in range(N_QUBITS):
    ANSATZ_SPEC.append({"gate": "CRX", "wires": [_i, (_i + 2) % N_QUBITS], "param": "theta_ent"})

# Shell 3: antipodal pairing (distance 4), BOTH Z-axis and X-axis entangling,
# same shared angle -- dual-axis long-range coupling at zero extra parameter
# cost.
for _i in range(N_QUBITS // 2):
    ANSATZ_SPEC.append({"gate": "CRZ", "wires": [_i, _i + N_QUBITS // 2], "param": "theta_ent"})
for _i in range(N_QUBITS // 2):
    ANSATZ_SPEC.append({"gate": "CRX", "wires": [_i, _i + N_QUBITS // 2], "param": "theta_ent"})

# Two-axis shared-entangler ansatz with a dedicated long-range XX shell.
#
# Design rationale:
# - A single global RY angle ("theta_ry") is applied to every qubit, and a
#   single global RZ angle ("theta_z") is applied to every qubit. The RZ
#   layer's angle is reused as the controlled-rotation angle for the two
#   short-range entangling shells (distance 1 and distance 2 rings), which
#   was found to generalize better than a dedicated third "theta_ent"
#   parameter and to be much more parameter-efficient (2 distinct circuit
#   params instead of 3).
# - The long-range antipodal shell (distance 4) previously reused CRZ (same
#   generator as the short-range shells) or mixed CRZ+CRX with a SHARED
#   angle on the SAME wires -- the latter collapsed trainability entirely
#   (validation accuracy stuck at 0.50): a Z-rotation and an X-rotation tied
#   to the identical angle on the same qubit pair compose into a fixed net
#   rotation that is largely insensitive to the encoded input state, wiping
#   out the gradient signal. Instead, the long-range links get their own
#   IsingXX coupling on a NEW dedicated shared parameter "theta_xx_long".
#   IsingXX is a genuinely different (X-type, non-commuting with Z)
#   generator, so it injects long-range correlations the local RY/RZ + CRZ
#   layers cannot reach, without destructively reusing an angle across
#   incompatible generators on the same wires.
# - Total: 3 distinct circuit parameters (theta_ry, theta_z, theta_xx_long)
#   plus 2 readout params = 5 total.
ANSATZ_SPEC = []

# Global single-qubit layer: one shared RY angle for all 8 qubits.
for _i in range(N_QUBITS):
    ANSATZ_SPEC.append({"gate": "RY", "wire": _i, "param": "theta_ry"})

# Global single-qubit layer: one shared RZ angle for all 8 qubits.
for _i in range(N_QUBITS):
    ANSATZ_SPEC.append({"gate": "RZ", "wire": _i, "param": "theta_z"})

# Shell 1: nearest-neighbor ring (distance 1), reuses theta_z via CRZ.
for _i in range(N_QUBITS):
    ANSATZ_SPEC.append({"gate": "CRZ", "wires": [_i, (_i + 1) % N_QUBITS], "param": "theta_z"})

# Shell 2: skip ring (distance 2), reuses theta_z via CRZ.
for _i in range(N_QUBITS):
    ANSATZ_SPEC.append({"gate": "CRZ", "wires": [_i, (_i + 2) % N_QUBITS], "param": "theta_z"})

# Shell 3: antipodal pairing (distance 4), dedicated IsingXX coupling on a
# new shared parameter "theta_xx_long" for genuinely long-range, non-Z-type
# correlations.
for _i in range(N_QUBITS // 2):
    ANSATZ_SPEC.append({"gate": "XX", "wires": [_i, _i + N_QUBITS // 2], "param": "theta_xx_long"})
