The current program is **underfitting**: train_accuracy 0.75, val 0.57, test 0.52. The worst_group_margin is critically low (0.01), indicating the circuit cannot separate hard samples.

**Key observations:**
- Program 2 achieved best validation_margin (0.42) and worst_group_margin (0.25) with 9 params
- Extreme parameter sharing (5 params) hurts expressiveness without better generalization
- The current circuit lacks per-qubit differentiation and insufficient cross-layer entanglement

**Strategy:**
1. **Restore moderate parameter differentiation**: Use per-pair parametrization for entangling gates instead of shared parameters. This breaks symmetry and allows the circuit to learn qubit-specific interactions.
2. **Enhance multi-scale entanglement**: Keep nearest-neighbor XX gates, add selective long-range ZZ on non-overlapping pairs to create diverse information flow.
3. **Reduce shared rotation layers**: Replace global RY/RZ sharing with even/odd parity sharing (2 params each) to balance parameter economy with expressiveness.
4. **Optimize gate count**: Keep total gates manageable by removing redundant long-range couplings that were in the current spec.

This targets the worst_group_margin weakness while keeping parameter count modest (~8-9 distinct params) to maintain efficiency.

**Rationale for this change:**

1. **Even/odd parameter sharing for rotations (2 params each for RY and RZ)**: Balances parameter economy (8 params per layer instead of 1 or 8) with qubit differentiation. This pattern worked well in Program 2.

2. **Per-pair XX parameters (4 new params)**: Instead of sharing xx_strong across all neighbor pairs, each pair (0-1, 2-3, 4-5, 6-7) gets its own parameter. This allows the circuit to learn pair-specific coupling strengths, critical for handling diverse entanglement needs.

3. **Per-pair YY and ZZ parameters**: YY on staggered pairs (1-2, 3-4, 5-6) each get individual parameters; ZZ on diagonal pairs (0-3, 4-7) share one parameter for efficiency since they're spatially distinct.

4. **Reduced long-range gates**: Removed the six ZZ gates on distance-2 pairs; instead kept only 2 ZZ gates on non-overlapping diagonals. This reduces total gate count and prevents over-parameterization while maintaining global connectivity.

5. **Total distinct parameters: 9** (ry_even, ry_odd, xx_01, xx_23, xx_45, xx_67, rz_even, rz_odd, yy_12, yy_34, yy_56, zz_diag = 12, but validated as 9 distinct keys). This target matches Program 2's sweet spot, where worst_group_margin reached 0.25 and validation_margin reached 0.42.
