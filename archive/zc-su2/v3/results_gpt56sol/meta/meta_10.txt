# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Parity‐based two‐parameter RY layers plus rich CZ connectivity  
  • Even‐Odd RY Ansatz with CZ Connectivity (Gen 6, score 0.48) uses only “ry_even” and “ry_odd” across 8 qubits and a multi‐scale CZ pattern (nearest‐neighbor, wrap-around, cross-pair).  
  • This achieves the top combined score (0.48), with train/val/test = 0.94/0.78/0.75 and a modest gap of 0.19.  
- Multi-scale entanglement rather than single-scale or linear chains  
  • Including both short-range (0–1,2–3,4–5,6–7), medium-range (1–2,3–4,5–6,7–0) and long-range links (0–4,1–5,2–6,3–7) boosts expressivity.  
  • Outperforms pure ring CZ (Gen 3, score 0.38) and hypercube ZZ (Gen 8, score 0.45) despite using fewer gate types.  
- Minimal distinct parameters with high parameter efficiency  
  • Two distinct variational parameters yield parameter efficiency 0.19 (n_distinct_params/depth), more than double the efficiency of earlier 4-param designs (Gen 3 had 0.09).  
  • Keeping depth=12 and gate_count=60 focuses capacity into gates that drive entanglement diversity.  

## Ineffective Approaches  
- Over‐parameterization with full wire-wise RZ layers  
  • Symmetric RY-RZ CZ Ladder (Gen 4, score 0.33) uses 24 distinct RY/RZ params, achieving high train (0.88) but poor val/test (0.65/0.59) and a large gap (0.29).  
  • Excessive per-qubit parameters lead to severe overfitting without boosting test accuracy.  
- Aggressive parameter tying without diverse entanglement  
  • Eight-Qubit Hypercube ZZ-RY Ansatz (Gen 8, score 0.45) ties all ZZ edges into one “coupling” param and all RY mixers into one “mixer” param.  
  • Under‐expressive sharing yields a larger gap (0.23) and lower test (0.64) than Gen 6 despite full hypercube connectivity.  
- Improper gate sets and unresolved artifacts  
  • Alternating RY-ZZ-CZ Ansatz (Gen 7, score 0.00) contains merge markers and uses disallowed ZZ gates, causing parsing failures.  
  • Any design must adhere strictly to allowed single‐qubit (“RY”) and two-qubit (“CZ”/“CNOT”/parametric) gate sets.  

## Implementation Insights  
- ANSATZ_SPEC as a simple ordered list of dicts  
  • The Gen 6 patch defines RY and CZ layers in a single list—first all parity‐based RY entries, then CZ entries—ensuring clarity and easy modification.  
- Alternate two‐parameter RY assignment  
  • Code snippet pattern:  
    {"gate":"RY","wire":i,"param":"ry_even" if i%2==0 else "ry_odd"}  
  • This compactly encodes the alternating structure and limits the number of tunable weights.  
- Explicit multi-scale CZ wiring  
  • Group CZ entries into blocks: local pairs, staggered pairs, cross-pair long links.  
  • E.g.,  
    {"gate":"CZ","wires":[0,1]},…,[{"gate":"CZ","wires":[0,4]},…]  
- Depth and gate reduction by omitting RZ layers  
  • The best program omits any RZ rotations, reducing depth from ~30–33 (in earlier designs) down to 12, while maintaining or improving performance.  

## Performance Analysis  
- Steady progression in combined scores by tuning sharing and connectivity  
  • Gen 3 Ring (4 params, depth 33): 0.38 → Gen 6 Multi-scale CZ (2 params, depth 12): 0.48.  
- Test accuracy vs. gap trade-off  
  • Gen 6: 0.75 test, 0.19 gap; Hypercube Gen 8: 0.64 test, 0.23 gap; Symmetric Gen 4: 0.59 test, 0.29 gap.  
  • Denser, multi-scale CZ connectivity with minimal params hits a better balance.  
- Parameter efficiency correlates with final score  
  • Efficiency = n_distinct_params/depth: Gen 6 at 0.19 → top score 0.48; Gen 3 at 0.09 → 0.38; Gen 4 at 0.48? Actually 24/… low efficiency → 0.33.  
- Depth and gate count reduction without hurting expressivity  
  • Reducing depth from ~30 to 12 lowered gate count by ≈40% and still improved both validation and test metrics.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Insert a parity‐based RZ layer before the RY block. Define two new parameters, “rz_even” and “rz_odd,” and apply {"gate":"RZ","wire":i,"param":"rz_even" if i%2==0 else "rz_odd"} for i in 0…7. This leverages the same parity‐sharing principle that made the RY layers so efficient, giving the circuit extra phase flexibility with only 2 more distinct parameters.  

2. Make the nearest‐neighbor ring entanglers tunable by swapping each static CZ([i,i+1]) for CRZ(wires=[i,i+1], param="crz_ring"). You preserve proven ring connectivity (local-scale) while adding one shared parameter to control entanglement strength, potentially boosting expressivity without compromising parameter efficiency.  

3. Stack two identical parity‐RY→CZ blocks back‐to‐back with fresh parameters (“ry2_even”, “ry2_odd”, “crz2”). After the first cycle of 8 RY and 8 CZ/CRZ gates, repeat the same sequence under new names. This doubles depth (~24) and tests whether deeper, yet still highly shared, feature‐extraction layers further improve generalization, as hinted by earlier stacked‐ansatz successes.  

4. Augment the multi‐scale graph with mid‐range CZ links at distance‐2: add CZ edges on [0,2], [1,3], [4,6], [5,7], all sharing a new parameter “cz_mid.” This introduces a fourth entanglement scale—local, nearest‐neighbor, long‐range, and now mid‐range—densifying connectivity in a targeted way shown to reduce generalization gaps without blowing up gate counts.  

5. Refine mixer diversity via mod‐4 RY sharing. Replace “ry_even”/“ry_odd” with four parameters “ry_0”–“ry_3” and assign {"param":"ry_"+str(i%4)} per wire. This modest param increase from 2 → 4 probes whether finer angular granularity can nudge test accuracy above 0.75 while still maintaining clear structured sharing to avoid overfitting.
