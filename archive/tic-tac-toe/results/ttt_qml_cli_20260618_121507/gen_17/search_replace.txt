<DESCRIPTION>
The current ansatz only couples corners to their adjacent edges and edges to the center. But the two diagonal winning lines (0,8,4) and (2,8,6) directly connect corners to the center. The grid adjacency allows corner-center coupling only via edges, but in fact the legal edge set does NOT contain corner-center edges, so we must route diagonal info differently.

Instead, I add a dedicated trainable corner→edge "diagonal context" CRY layer that distinguishes the two diagonals from the rows/columns by using a *separate* shared parameter (`cry_diag_context`). The diagonal lines pass through specific corner-edge-center paths. Since corners (0,2,4,6) each sit on exactly one diagonal through the center, and the center is reached via edges, I strengthen the center's diagonal sensitivity by adding a second, independently-parametrized center→edge broadcast that uses a distinct parameter from the existing one. This breaks the over-sharing of the single `cry_center_to_mid` parameter and gives the model more expressivity for the draw class (which is the hardest to separate), at the cost of just 1 extra parameter per block (6 total).

This is a low-cost, symmetry-respecting expressivity boost targeting the diagonal patterns that the current line-segment-only entanglers cannot represent. It also reduces parameter over-sharing that may be limiting train accuracy (currently only 0.43).
</DESCRIPTION>
