<DESCRIPTION>
The current ansatz uses only RY single-qubit rotations and CRY on a subset of edges. The model is underfitting (train acc 0.43 < val 0.56), so we need more expressivity per block while staying parameter-efficient.

Two targeted changes:

1. Add a trainable RZ phase layer right after the RY decode layer. Although RZ commutes with the Z readout *at the end*, here it sits before the CRY entanglers, where it rotates amplitude in the X-Y plane before entanglement. This gives each qubit a genuine 2-axis local frame (RY then RZ) before mixing, adding only 3 shared params (corner/edge/center orbits).

2. Use the *full set* of adjacent grid edges for the perimeter CRY entanglers (currently only one direction per edge). Adding the missing perimeter directions (1->0, 1->2, 3->2, 3->4, 5->4, 5->6, 7->6, 7->0) under a separate shared parameter doubles the perimeter information flow (bidirectional coupling along each winning-line segment) at the cost of just 1 new shared parameter.

Together this raises N_PARAMS_PER_BLOCK from 12 to 16 (N_PARAMS 72->96), still well within budget, and should improve fitting capacity and reduce loss while respecting D4 symmetry and adjacency constraints.
</DESCRIPTION>
