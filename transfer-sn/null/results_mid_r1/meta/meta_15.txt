# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Layered re-uploading with minimal entangling (3 uploads × 2 repeats): The current best 8-Qubit Re-Uploading Ansatz Classifier (Gen 9) used N_UPLOADS = 3 and N_REPEATS = 2 to achieve combined_score_raw = 1.00, perfect 100% accuracy, zero gap, depth 75, 180 gates, converging in ~150 steps.  
- Controlled-X only entanglement: Restricting two-qubit parameterized gates to CRX in a staggered even/odd pattern matched full classification performance (Gen 9: 98 params) without the overhead of CRY/CRZ layers seen in deeper designs.  
- Single-axis single-qubit rotations (RY only): Initial per-qubit RY layers in each block sufficed to load trainable angles onto all qubits; omitting RZ/RX in the ansatz block reduced depth and accelerated convergence.  
- Early stopping with best-weights restoration: All top performers (Gen 1, Gen 9) used validation-loss early stopping (patience = 75) and restored the best-found parameters, ensuring zero generalization gap and robust convergence.

## Ineffective Approaches  
- Overparameterized two-qubit networks: Adding CRZ/CRY layers and long-range couplings (e.g., Gen 4 “crz_entanglement_efficiency” with 140 params, depth 93, score 0.99; Gen 11 with 98 params, depth 93, score 0.97) inflated resource use without improving test accuracy.  
- Alternating RY–RZ brickwall entanglement: Gen 8’s mixed RY/RZ + CNOT ansatz (depth 81, 228 gates) slowed convergence (~390 steps) and scored lower (combined 0.96) than the simpler CRX-only pattern.  
- Excessive parameter sharing without streamlining gates: Gen 13’s symmetric shared-parameter ring (50 params, depth 87) failed to reach the 0.90 convergence threshold (train 86%, test 78%), illustrating that sharing must be paired with a concise entanglement layout.  
- Deep mirrored architectures without gate reduction: Although Gen 14’s mirror_dual_axis achieved perfect accuracy, its depth 81 and 228 gates yielded low parameter efficiency (0.01) and offered no speed or accuracy gains over the shallower Gen 9.

## Implementation Insights  
- ANSATZ_SPEC + validate_ansatz_spec pattern: Defining each block as a dict list and auto-validating/generating parameter-to-index maps (as in Gen 9) makes gate swaps trivial and enforces consistency across candidates.  
- Decoupled gain/bias calibration: Splitting circuit parameters from readout gain and bias stabilized gradients and simplified the QNode signature—used uniformly in top programs (Gen 1, Gen 4, Gen 9).  
- Uniform re-upload loop:  
  “for upload_index in range(N_UPLOADS): feature_map(); for repeat_index in … apply_ansatz_block()”  
  ensures balanced feature encoding and ansatz application; Gen 9’s streamlined block leveraged this pattern to minimize gate count.  
- Metadata via qml.queuing.AnnotatedQueue: Automated capture of depth and gate_count (e.g., Gen 9’s 75 and 180) enables rapid correlation of resource metrics to performance, guiding ansatz pruning.

## Performance Analysis  
- Depth vs. combined_score_raw: Only circuits with depth ≤ 75 (Gen 9) attained the perfect combined_score_raw = 1.00. Designs ≥ 81 depth peaked at 0.99 (Gen 4) or lower.  
- Gate count efficiency: Gen 9’s 180 gates delivered flawless classification; adding gates up to 300 (Gen 11, Gen 12) saw no accuracy gains and marginally slower convergence.  
- Parameter count vs. test accuracy: Increasing from 98 (Gen 9) to 122–140 parameters (Gen 6, Gen 4) did not raise combined_score_raw, confirming diminishing returns beyond ~100 params.  
- Convergence speed tied to ansatz simplicity: Gen 9 (CRX-only) converged in ~150 steps, whereas more complex blocks (Gen 8’s mixed rotations) needed ~390 steps to approach similar loss levels.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Parameter Sharing Across Repeats  
   Modify the mapping in apply_ansatz_block so that the two repeats within each upload use the same set of 16 trainable angles (i.e. index by `upload_index` only, not `block_index`). This cuts the circuit parameters from 98 to 50 (+2 readout), probes whether repeated application of the same transformation boosts expressivity via depth rather than fresh angles, and directly tests true parameter efficiency while keeping depth≈75.  

2. Cyclically Shifted CRX Connectivity Across Uploads  
   In the EVOLVE-BLOCK, keep the even/odd two-layer CRX pattern but for each upload offset all wire indices by `upload_index` modulo 8 (e.g. upload 0: (0,1),(2,3)…; upload 1: (1,2),(3,4)…; etc.) using the same `crx0…crx7` keys. This preserves the light-weight per-block structure and parameter count while systematically sampling all nearest-neighbor couplings over the full circuit.  

3. Lean Block Variant with Increased Uploads  
   Remove the second CRX layer (odd pairs) from each block—so each block has 8 RY + 4 CRX gates—and raise `N_UPLOADS` to 4 (keep `N_REPEATS=2`) to maintain depth≈75. This tests whether more frequent, simpler ansatz blocks accelerate convergence or improve generalization by emphasizing feature re-uploads over entanglement density.  

4. Mid-Circuit Shared-Parameter RZ Phase Injection  
   After each feature_map call and before the first RY in every block, insert eight `RZ` gates on wires 0–7 all sharing a single new parameter key `"rz_mid"`. This lightweight, 8-gate, 1-parameter layer lets the circuit fine-tune qubit phases mid-circuit without inflating depth beyond 75, building on the success of solo single-qubit rotations.  

5. Final Shared-Parameter Entangling “Refresher”  
   Append, just before measurement, a final layer of four CRX gates on even pairs `[(0,1),(2,3),(4,5),(6,7)]` all using one new parameter `"crx_end"`. This 4-gate, 1-parameter global entanglement injection preserves the total gate count ≲180 and depth ≤75, offering a last-moment expressivity boost without the overhead of additional parameter types.
