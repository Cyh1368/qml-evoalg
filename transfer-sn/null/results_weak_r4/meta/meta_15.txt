# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- RY–CZ-ring–RX block with 3 uploads × 2 repeats  
  • Current best program (combined_score_raw 0.99, test_acc 1.00, gap 0.00, depth 81, gates 228, 74 params) mirrors Generation 11 and 15, showing that alternating a fixed IsingZZ feature map with RY input rotations, two staggered CZ-ring layers, and RX output rotations is highly expressive yet trainable.  
- Shared RX parameters across qubit pairs  
  • By pairing qubits under shared RX keys (rx_0…rx_3), N_PARAMS_PER_BLOCK drops from 16→12, reducing total params to 74 without any loss in accuracy or generalization (parameter_efficiency 0.01 versus 0.01 for 98-param designs).  
- Nearest-neighbour CZ entanglement only  
  • All top performers (current best, Gen 11, Gen 13, Gen 15) restrict two-qubit gates to staggered CZ on ring bonds, achieving the “sweet spot” circuit depth 81 and gate_count 228 that correlates with combined_score_raw 0.99.  
- Multi-upload, multi-repeat layout  
  • Consistently, N_UPLOADS=3 × N_REPEATS=2 delivers perfect classification (train/validation/test = 1.00) and zero generalization gap in ~150 optimizer steps, balancing expressivity and trainability.  

## Ineffective Approaches  
- Parameterized cross-layer two-qubit gates (CRZ/CRX/CRY)  
  • Generation 16’s six-block ansatz with CRZ couplings (24 params/block, total 146 params, depth 105, gates 276) saw combined_score_raw drop to 0.95, indicating that added entanglers inflate depth/gates without boosting expressivity.  
- Over-parameterized SU(2) blocks  
  • The Shared-Pair 8-Qubit classifier (Gen 9) used 98 trainable rotations plus gain/bias (depth 150, gates 348) and achieved only combined_score_raw 0.97, showing diminishing returns beyond ~100 params.  
- Hybrid CZ+CNOT layouts  
  • Earlier mixed-entangler designs spiked gate_count to ~306 and depth to ~111, slowed convergence (~390 steps), and fell to combined_score_raw 0.94.  
- Excessive parameter sharing  
  • Aggressively collapsing all rotations into ~50 parameters (Gen 8) undercut expressivity, yielding a combined_score_raw 0.73 and poor accuracy despite low resource use.  

## Implementation Insights  
- Modular ANSATZ_SPEC with validate_ansatz_spec and key_to_position  
  • Abstracting each gate into a dict and auto-extracting PARAMETER_KEYS_PER_BLOCK enforces consistent parameter ordering and makes swapping gate types (e.g., RZ→RX) trivial.  
- Shared-parameter definitions in ANSATZ_SPEC  
  • Explicitly assigning the same “param” key to multiple “RX” entries (e.g., wires [0,1]) cuts N_PARAMS_PER_BLOCK from 16 to 12 while preserving expressive freedom.  
- Automated resource metrics via qml.queuing.AnnotatedQueue  
  • Computing depth and gate_count directly from the queued operations allows immediate feedback on the impact of ansatz edits, guiding the move to two-layer CZ rings.  
- Decoupled feature_map vs. apply_ansatz_block  
  • Separating fixed IsingZZ encoding from trainable ansatz logic enabled rapid prototyping of entanglement patterns, leading to the discovery of the optimal RY–CZ-ring–RX construct.  

## Performance Analysis  
- Parameter count versus combined_score_raw  
  • Shrinking total params from 146→98→74 correlates with rising combined_score_raw: 0.95 (Gen 16)→0.99 (Gen 11/15)→0.99 (current best), highlighting a regime where ≤100 params is optimal.  
- Circuit depth/gate_count sweet spot at 81/228  
  • All circuits hitting combined_score_raw 0.99 share depth 81 and 228 gates; deeper or more entangled variants plateau or regress.  
- Convergence behavior  
  • Best configurations (74–98 params) reach validation_accuracy≥0.90 in ~150 steps, faster than over-entangled designs (~390) and slightly slower than minimal SU(2) ones (~120), indicating an ideal expressivity-trainability trade-off.  
- Parameter efficiency (~test_acc/N_PARAMS)  
  • Peak efficiency (~0.01) emerges for 74–98 param circuits achieving perfect test accuracy; over-parameterized ansätze dilute this metric.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Replace the odd-bond CZ layer in each ansatz block with shared-parameter CRZ gates. In your ANSATZ_SPEC, change the eight entries for the odd-ring bonds from  
   `{"gate":"CZ","wires":[i,j]}`  
   to  
   `{"gate":"CRZ","wires":[i,j],"param":"ent"}`  
   so that all eight CRZs in a block use the same “ent” key. This injects one trainable entangling angle per block, preserving depth=81 and gate_count≈228, and tests whether light parametrization of the second CZ layer boosts expressivity without bloating resources.  

2. Tie the input RY rotations across repeats within each upload to cut redundant local-mixing parameters. Rename the RY keys so that both repeats under upload 0 use “ry0_0”…“ry0_7”, upload 1 uses “ry1_0”…“ry1_7”, and upload 2 uses “ry2_0”…“ry2_7”. This collapses 6×8=48 per-block RY parameters into just 3×8=24, reducing N_CIRCUIT_PARAMS while keeping the proven RY–CZ–RX block structure.  

3. Add a per-upload global phase layer immediately after each feature_map by broadcasting one RZ on every qubit. For upload k, insert eight entries  
   `{"gate":"RZ","wire":q,"param":"phi_k"}`  
   for q=0…7, introducing only three extra “phi_0/1/2” parameters. This lets the circuit learn to rescale or shift each re-upload’s phase encoding strength without altering CZ connectivity or depth.  

4. Diversify the output-shaping layer by mixing RX and RY rotations across the four qubit pairs, while still sharing one angle per pair. For example, in ANSATZ_SPEC replace RX on wires [0,1] and [4,5] with RX_shared keys “rx0” and “rx2”, and use RY_shared on [2,3] and [6,7] with keys “ry1” and “ry3”. This keeps four trainable parameters but enriches the final local rotations’ axis diversity, potentially capturing correlations that pure RX can miss.  

5. Upgrade the readout from a uniform mean to pair-weighted averaging by learning one weight per qubit pair. In predict_batch, compute  
   raw = ∑_{j=0}^3 w_j·(z_{2j}+z_{2j+1})/2  
   instead of raw=mean(z), adding four “w_0”…“w_3” parameters alongside gain and bias. This medium-grain calibration retains parameter efficiency (<100 total) while giving the model finer control over which qubit groups drive the classification.
