# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Re-uploading interleaved with minimal rotation–entanglement blocks delivers top performance.  
  • Current Best (“Seed”/Gen 7): 3 feature-map uploads × 2 repeats of an RY→pre-RZ→CZ-chain→post-RZ block (24 params/block) → depth 99, gate_count 270 → combined_score_raw 0.85, gap 0.07.  
- Linear CZ chain with two-stage single-qubit rotations maximizes expressivity per parameter.  
  • Seed program (0.85) and Gen 0 “Feature-Reupload Ansatz” (0.85) both use only RY/RZ+CZ and match or beat more complex variants at lower depth.  
- Light parameter sharing can shrink parameter count with modest gap improvement but must preserve local phases.  
  • Gen 11 “collapsed_rz_param_sharing”: shared pre/post RZ reduced n_params to 86, gap 0.08, but raw 0.78, indicating too aggressive sharing hurts expressivity.  
- Readout calibration via two trainable gain/bias parameters on mean-Z expectation yields stable convergence.  
  • All top performers embed FEATURE_SCALE·IsingZZ + gain/bias and converge by ~750 steps with negligible std deviation across seeds.  

## Ineffective Approaches  
- Circular/CNOT-ring entanglement layers under-perform and inflate generalization gap.  
  • Gen 12 “cnot_ring_parameter_efficient_ansatz”: 3 uploads×2 repeats of RY/RZ+CNOT ring → depth 120, gates 276 → raw 0.68, gap 0.17.  
- Mid-circuit RX layers and checkerboard entanglers add overhead without score gain.  
  • Gen 9 “checkerboard_ryrx_block”: added RX mixers around CZs → depth 87, gates 276 → raw 0.76, gap 0.12, param_eff 0.01.  
- Parameterized two-qubit gates and long-range CNOTs increase depth/gate count with only marginal benefit.  
  • Gen 15 “expressive_controlled_rotations”: CRY/long-range CNOTs → depth 142, gates 300 → raw 0.72.  
  • Gen 14 “bidirectional_crz_skip_mixing”: skip-CRZ links → raw 0.83 vs seed 0.85, despite higher depth 117 and gates 294.  
- Over-parameterized ansätze yield low parameter efficiency (~0.01) and do not close generalization gap.  

## Implementation Insights  
- Decoupling ansatz spec from execution via `validate_ansatz_spec` and an ordered `PARAMETER_KEYS_PER_BLOCK` ensures robust, offset-based parameter lookup in `apply_ansatz_block`.  
- Using `qml.queuing.AnnotatedQueue` + `tape.graph.get_depth()` yields exact depth and gate counts, enabling precise cost/performance trade-offs.  
- A concise ANSATZ_SPEC (24 params/block) balances expressivity and resource cost, accelerating convergence (seed program hits threshold by step 750).  
- Fixed IsingZZ feature map plus two readout params (gain, bias) on the mean Z-expectation standardizes calibration across architectures and stabilizes training.  

## Performance Analysis  
- Inverse correlation between circuit depth and combined_score_raw:  
  • Depth 99 → raw 0.85 (seed) vs. depth 117 → raw 0.83 (Gen 14) vs. depth 120–142 → raw 0.68–0.78 (Gen 9/11/12/15).  
- Gate count beyond ~280 yields diminishing returns: top models cluster at ~270 gates; 300+ gates do not improve raw score.  
- A moderate generalization gap (~0.07–0.08) aligns with best performance; larger gaps (>0.10) correspond to poorer raw scores (Gen 9/12).  
- Parameter efficiency remains uniformly low (~0.01); highest raw score achieved without increasing parameter count beyond 146.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Implement intra-upload weight tying for single-qubit rotations. In your ANSATZ_SPEC and parameter-indexing logic, map the RY and pre-RZ/post-RZ parameters of the two repeats within each upload to the same parameter keys (e.g. rename `ry_i_repeat0` and `ry_i_repeat1` both to `ry_i`). This will halve the unique RY/RZ parameters per upload (from 24 to 12) without changing depth or gate count, boosting parameter efficiency while preserving the proven block structure.  

2. Alternate CZ-chain direction between blocks. In `apply_ansatz_block`, detect when `block_index % 2 == 1` and apply the CZ gates in reverse order (wiring `[7,6], [6,5], …, [1,0]` instead of `[0,1], [1,2], …, [6,7]`). This bidirectional nearest-neighbor entanglement exploits the same gate budget but enhances information propagation, building on the success of linear CZ chains.  

3. Inject sparse next-nearest-neighbor CZs on alternating blocks. After the standard linear CZ chain, for blocks with `block_index % 2 == 0`, append CZ(a, a+2) for even a in {0,2,4,6}. This adds only four extra gates per selected block (~16 total CZs across the circuit) and introduces higher-order entanglement correlations with minimal depth overhead.  

4. Experiment with a 4×2 re-upload layout. Increase `N_UPLOADS` from 3 to 4 while keeping `N_REPEATS = 2`, yielding a 4×2 pattern of feature-map uploads and minimal rotation–CZ blocks. Track depth and gate count (should rise by ~50 gates) against combined_score_raw to see if the extra nonlinearity in the 4×2 schedule surpasses the 3×2 baseline.  

5. Coarse-grained phase sharing in RZ layers. Replace the 16 independent pre/post-CZ RZ angles per block with four shared parameters—one per spatial half of the register for each layer (e.g. `rz_pre_lo`, `rz_pre_hi`, `rz_post_lo`, `rz_post_hi`). This reduces per-block parameters from 16 to 4, testing whether grouped global phase adjustments maintain expressivity while improving parameter efficiency in line with light sharing successes.
