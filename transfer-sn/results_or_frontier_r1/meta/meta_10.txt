# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Shared-parameter single-qubit rotation layers (“collective” RY/RZ/RX) dramatically cut parameter count without sacrificing accuracy  
  • 8-Qubit Complete-Graph Variational Classifier: 20 params → combined_raw 0.93, test 0.94, gap 0.02  
  • 8-Qubit Cycle-Graph Ansatz Classifier: 20 params → combined_raw 0.90, test 0.90, gap 0.01  
- High-connectivity CZ entanglement schemes boost expressivity in shallow, low-param circuits  
  • Complete-graph CZ on all qubit pairs (depth 135, 396 gates) → top test accuracy  
  • Degree-3 “perfect-matching” cycle-graph CZ (depth ≈93, 300 gates) → strong score with minimal params  
- Repeated feature-map uploads (N_UPLOADS = 3) interleaved with small ansatz repeats (N_REPEATS = 2) stabilize training and enforce data encoding consistency across top performers  
- Maintaining low N_PARAMS_PER_BLOCK (<10) plus global readout calibration yields tight generalization and high parameter efficiency (>0.045)  

## Ineffective Approaches  
- Large per-block parameter counts (>50) without sharing led to overfitting and poor generalization  
  • 8-Qubit Layered Ansatz Classifier: 242 params → combined_score –1.26 (test 0.79), gap 0.11  
  • 8-Qubit Hypercube RY-CZ Ansatz: 194 params → combined_raw 0.76, gap 0.10  
- Deep, hardware-efficient or chained entanglers with no symmetry increased depth/gate count (≥160 depth, ≥420 gates) but failed to improve accuracy  
  • Evolved Ansatz Classifier (194 params, depth 97) → combined_raw 0.83, gap 0.09  
- Excessive block repeats or custom gate layers without parameter sharing produced training instability  
  • High-param custom blocks often did not converge before early stopping, yielding sub-optimal combined scores  

## Implementation Insights  
- Declarative ansatz specifications (ANSATZ_SPEC) combined with validate_ansatz_spec and key-to-position mapping support rapid iteration and parameter sharing  
- Leveraging Pennylane’s autograd/backprop differentiation in QNodes drives fast convergence (≈150 steps for the complete-graph ansatz)  
- Early stopping on validation loss with best-weight restoration is critical for low-parameter models to avoid overfitting  
- Using AnnotatedQueue and circuit_metadata to extract exact depth and gate counts guides informed trade-offs between entanglement topology and resource overhead  

## Performance Analysis  
- Combined scores rose sharply as architectures moved from 194–242 params to 20 params with shared rotations and symmetric entanglers:  
  hypercube_ry_cascade 0.76 → layered 0.79 → cycle_matching_entangler 0.90 → symmetric_graph_mixer 0.93  
- Parameter efficiency improved ~10× when cutting params from ~200 to 20 (0.004 → 0.05) while boosting test accuracy  
- Generalization gap inversely tracks parameter sharing and symmetry: large-param designs gap 0.09–0.11 vs small-param shared designs gap 0.01–0.02  
- Circuit depth alone did not predict performance; ansatz topology and parameter economy were the dominant factors in achieving top scores.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Parameterize entanglers with a shared CRZ angle  
   – In your ANSATZ_SPEC, replace each fixed “CZ” entry with a “CRZ” gate using a single common key (e.g. `"collective_crz"`) per block. Update ALLOWED_PARAM_TWO_QUBIT_GATES and apply_ansatz_block to map that key to one trainable angle. This keeps N_PARAMS_PER_BLOCK≈3–4 while giving the circuit tunable entanglement strength, leveraging the success of collective single-qubit rotations without blowing up the parameter count.

2. Learn upload‐specific feature scales  
   – Replace the global FEATURE_SCALE constant with a small vector of N_UPLOADS trainable parameters (`"scale_u0"`, `"scale_u1"`, `"scale_u2"`) and modify feature_map to use `feature_scale[upload_index]` for each data‐reupload. This adds only three extra degrees of freedom but lets the ansatz adapt its encoding strength over successive uploads, building on the stability gains seen with repeated uploads.

3. Share ansatz parameters across repeats  
   – To reduce parameter redundancy, change apply_ansatz_block so that blocks within the same upload all draw from the same offset (i.e. `offset = upload_index * N_PARAMS_PER_BLOCK`, ignoring repeat_index). This halves the number of unique parameter blocks (from 6→3) while preserving six block applications, further tightening the generalization gap by enforcing symmetry across repeats.

4. Explore a K4,4 bipartite symmetric entangler  
   – In ANSATZ_SPEC, replace the complete-graph CZ layer with three CZ matchings of the K4,4 bipartite graph: [(0,4),(1,5),(2,6),(3,7)], then shift each matching by one qubit to get two more layers. Keep the same collective RY/RZ/RX before/after. This tests whether balanced degree-4 connectivity can rival the complete graph’s expressivity at lower depth/gate count.

5. Rebalance uploads vs. local depth: N_UPLOADS=2, N_REPEATS=3  
   – Change the hyperparameters so that you perform two feature‐map uploads (N_UPLOADS=2) each followed by three ansatz repeats (N_REPEATS=3). This maintains six total blocks (and the same N_PARAMS) but shifts workload toward deeper local processing per encoding, probing whether denser ansatz stacks after each upload can boost accuracy without sacrificing parameter efficiency.
