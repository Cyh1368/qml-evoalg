<DESCRIPTION>
The current architecture (110 parameters) underperforms compared to the prior programs (74 parameters, combined_score 0.27 vs 0.13). The issue is over-parameterization: the current ANSATZ_SPEC uses 18 unique parameters per block, compared to 12 in the prior architecture.

While the formal recommendation to tie parameters across repeats within `apply_ansatz_block` would require modifying code outside EVOLVE-BLOCK markers (which is prohibited), we can instead simplify the ANSATZ_SPEC to use more aggressive parameter sharing, reducing to approximately 10 unique parameters per block.

Key improvements:
1. Return to the mirror-symmetric parameter sharing pattern from prior programs (which achieved 0.27 combined_score)
2. Replace the 8-gate CRZ ring with a fixed-gate CZ scaffold (reducing controlled rotations from 8 to 4)
3. Consolidate RY and RZ layers to use 2 shared parameters each instead of 4
4. This reduces N_PARAMS_PER_BLOCK from 18 to 10, cutting total params from 110 to ~62 (plus 2 readout = 64)

This aligns with the parameter efficiency insight: the prior 74-param architecture was already over-parameterized, so reducing further should help unless it sacrifices expressivity. By combining the CZ scaffold (proven architecture) with mirror symmetry (proven parameter sharing), we recover efficiency while maintaining expressivity.
