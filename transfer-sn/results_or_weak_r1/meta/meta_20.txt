# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Coarse-grained parameter sharing across qubit halves  
  – Gen 13 (“Shared-parameter Re-uploading Ansatz”): by grouping RY and RZ rotations into two sets (wires 0–3 vs 4–7) with just 6 unique params per block, the model reached combined_score_raw = 0.90, test = 0.89, gen_gap = 0.00 with only 38 trainable weights.  
- Elimination of trainable two-qubit gates in favor of fixed CZ rings  
  – Gen 13 dropped all CRX/CRZ layers and used only interleaved CZ entanglers. This preserved high expressivity (test 0.89) at a compact depth of 99 and 276 gates.  
- Three uploads × two repeats layout  
  – Across top performers (Gen 13, Gen 15), N_UPLOADS = 3 and N_REPEATS = 2 yielded the optimal depth (≈99–105) and gate count (≈276–300), consistently outperforming variants with more or fewer repeats.  
- Decoupling feature map from ansatz parameters  
  – All top-scoring designs (Gen 13, Gen 15) used a fixed IsingZZ data encoding separate from the variational block, focusing trainable capacity entirely on single-qubit rotations.  

## Ineffective Approaches

- Mid-level parameter counts with parameterized two-qubit rotations  
  – Gen 16 (56 params, +CRX layer) suffered combined_score_raw = 0.86 and gen_gap = 0.06 despite moderate depth (99) and low gate count (252).  
  – Gen 14 (80 params, paired entanglement) only hit 0.87 combined, with gen_gap = 0.04 and depth 111.  
- Over-parameterized ansätze (>60 weights)  
  – Gen 17 (62 params) and Gen 18 (74 params) both plateaued at combined ≈0.87 and parameter_efficiency = 0.01–0.02, indicating diminishing returns above ~40 weights.  
- Increased depth/gate count without accuracy gains  
  – Adding CRZ/CRX layers or long-range chords pushed depth >110 and gate_count >348 (e.g., Gen 19) but only reached combined_score_raw = 0.88, below the Gen 13 baseline.  

## Implementation Insights

- ANSATZ_SPEC + `validate_ansatz_spec` → deterministic param ordering  
  – Gen 13 defines exactly six param keys (“ry_h”, “ry_h2”, “rz_pre_h”, “rz_pre_h2”, “rz_post_h”, “rz_post_h2”), which map cleanly via `key_to_position` and an offset (block_index × N_PARAMS_PER_BLOCK) to 36 circuit params.  
- `apply_ansatz_block` offset indexing  
  – This generic pattern supports arbitrary N_UPLOADS×N_REPEATS without bespoke slicing, making re-uploading trivial and error-free.  
- Separation of trainable and fixed gates  
  – By reserving all two-qubit entanglers as fixed CZs and parameterizing only single-qubit rotations, Gen 13 concentrates expressivity into fewer weights, boosting parameter efficiency to 0.02.  
- Compact spec definitions drive code simplicity  
  – Grouping wires via shared param keys (e.g., four RY ops under “ry_h”) requires only 2 lines per group yet controls 8 rotations, dramatically reducing boilerplate.  

## Performance Analysis

- Parameter count vs. combined_score_raw  
  – As N_PARAMS fell from 80→62→56→38, combined_score_raw rose from 0.87→0.87→0.86→0.90, underscoring lean ansätze.  
- Parameter efficiency correlates with generalization  
  – Models with efficiency ≈0.02 (Gen 13, Gen 16) outperformed those at ≈0.01, but only Gen 13 paired that efficiency with the ideal depth/gate count corridor.  
- Depth/gate_count sweet spot  
  – All top-scoring variants lie in [95–105] depth and [270–300] gates. Gen 13 at (99, 276) sits at the center, whereas deeper (>110) or shallower (<95) designs underperform.  
- Zero generalization gap only in ultra-shared designs  
  – Gen 13’s aggressive sharing yielded gen_gap = 0.00, while all richer parametrizations incurred gaps ≥0.02, confirming that fewer, well-placed weights improve robustness.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Merge the pre- and post-RZ rotations into a single coarse-grained Z-rotation per half-block. In your ANSATZ_SPEC, replace both “rz_pre_h”/“rz_post_h” with a single key “rz_h” (and likewise “rz_pre_h2”/“rz_post_h2”→“rz_h2”) applied in both positions. This cuts N_PARAMS_PER_BLOCK from 6→4 (total N_PARAMS→26) while preserving the same two Z-rotations per half, testing whether further parameter reduction maintains Gen-13’s zero generalization gap.  
2. Introduce two trainable feature-scale factors in feature_map, one per qubit half. Add keys “fs_h” and “fs_h2” to PARAMETER_KEYS_PER_BLOCK, then multiply FEATURE_SCALE by fs_h when you encode features on qubits 0–3 and by fs_h2 on 4–7 before calling qml.IsingZZ. This injects only 2 extra weights but lets the model adapt the strength of its fixed data embedding, probing whether flexible encoding boosts test accuracy without increasing circuit depth.  
3. Add a shared RX layer immediately after each RY stage, with one parameter per half. In ANSATZ_SPEC, insert eight RX gate entries—wires 0–3 using “rx_h,” wires 4–7 using “rx_h2”—directly following the existing RY ops in each block. This introduces just 2 new parameters per block (≈44 total) and explores whether coarse-grouped rotations around an orthogonal axis can increase expressivity while keeping depth ≈100.  
4. Inject a minimal cross-half entangler via shared CRZ chords. After the two fixed CZ rings in each block, append four CRZ gates on wires [3,4], [2,5], [1,6], [0,7] all sharing the same “phi_cross” key. This single extra parameter per block tests whether a tunable coupling between halves can improve expressivity beyond fixed CZ alone, without pushing gate count above ∼300.  
5. Hierarchically share single-qubit parameters across the two repeats in each upload. Redefine your parameter keys to include an upload index (e.g. “ry_h_u0” shared by both repeats in upload 0, “ry_h_u1” for upload 1, etc.) so that each upload uses only 4–6 unique keys instead of 6×2. This reduces total circuit parameters by ≈1/3 and examines whether higher-level sharing preserves the zero generalization gap seen in Gen 13’s aggressive grouping.
