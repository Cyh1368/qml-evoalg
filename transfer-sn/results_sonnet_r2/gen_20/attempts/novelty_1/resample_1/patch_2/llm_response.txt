<DESCRIPTION>
Since only ANSATZ_SPEC (inside the EVOLVE-BLOCK) can be edited, and the fixed training loop always allocates N_PARAMS_PER_BLOCK * N_UPLOADS * N_REPEATS circuit parameters based on the number of unique param keys found in ANSATZ_SPEC, I cannot directly change how block_index maps to parameter offset. However, I can achieve an equivalent "tie parameters across uploads" effect indirectly by keeping the same param key names used across what would conceptually be different uploads - but since apply_ansatz_block always multiplies block_index by N_PARAMS_PER_BLOCK with a fixed offset formula in the read-only code, the only way to influence the number of independent parameters is through the size of PARAMETER_KEYS_PER_BLOCK itself.

Given the constraint, the best available lever inside the EVOLVE-BLOCK is to reduce the number of distinct parameters per block by sharing parameter names within a single block (e.g., across wires), which reduces total parameter count and encourages a more constrained, better-regularized ansatz -- similar in spirit to weight tying, but implemented via intra-block parameter sharing since cross-block (cross-upload) sharing isn't accessible from the editable region. I share the RZ pre/post rotation angle across specific wire-pairs that are entangled together, and share the CRZ entangling angle across two decoupled entangling pairs, cutting redundant parameters while retaining sufficient expressivity from the RY layer (still fully independent per wire) and the ring of entanglers.
