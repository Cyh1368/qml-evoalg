# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Parameter sharing via repeated parameter keys  
  • The current “8-Qubit ShinkaEvolve Ansatz Classifier” halves its parameter count (110 vs. ≥146) by reusing the same “rz_pre_i” keys for both pre- and post-RZ rotations. This delivers a combined score of 0.86 (train 0.94/val 0.88/test 0.88)—+0.01 over the prior best—while cutting N_PARAMS by ~25%.  
- Ring-CRZ entanglement on a linear chain  
  • All top performers (current program, Gen 6: combined 0.85, 156 params, depth 120; previous best: combined 0.85, 146 params, depth 99) use a single ring of CRZ couplings (no CZ), achieving strong test accuracy (0.87–0.88) and low generalization gaps (0.06–0.07).  
- Triple IsingZZ feature-map re-uploads  
  • Fixed two-qubit IsingZZ phases, uploaded three times, appear in every ≥0.85 circuit (e.g. current: 0.86; Gen 17: 0.86), balancing expressivity against overfitting.  
- Trainable readout gain and bias  
  • Adding two calibration parameters at the end yields consistent generalization gaps of ~0.06–0.08, as seen in the current classifier and prior top models (Gen 17–20).

## Ineffective Approaches

- Mixing CZ with CRZ entanglers  
  • Generation 19 (alternating CRZ/CZ, 170 params) achieved only combined 0.85 with a larger gap (0.08) and higher depth (120), showing richer entanglement didn’t improve test accuracy over a pure CRZ ring.  
- Over-parameterized ansätze  
  • Generations 13 and 18 (218 params, depth 142, combined 0.79/0.76) matched train accuracy (~0.94) but underperformed on validation/test, indicating diminishing returns beyond ~150 params.  
- Parameterized two-qubit rotations beyond CRZ  
  • Introducing CRX/CRY (Gen 18) neither improved combined score nor narrowed the gap, suggesting extra two-qubit parameters add complexity without new useful expressivity.

## Implementation Insights

- Systematic SPEC validation and key ordering  
  • Calling `validate_ansatz_spec` to build a unique `PARAMETER_KEYS_PER_BLOCK` list ensures zero SPEC_ERRORS and provides a deterministic mapping from `param` names to positions.  
- Dynamic offset + key-to-position lookup  
  • The pattern `offset = block_index * N_PARAMS_PER_BLOCK` combined with a `key_to_position` dict inside `apply_ansatz_block` cleanly supports block reuse—even when sharing parameters across multiple gates—without manual index arithmetic.  
- Parameter reuse by re-specifying keys in ANSATZ_SPEC  
  • Duplicating `"param": "rz_pre_i"` entries for both pre- and post-RZ rotations halves the number of unique parameters with no code changes elsewhere, demonstrating an easy “ansatz pruning” trick.  
- Backprop gradients on default.qubit  
  • Using `@qml.qnode(..., diff_method="backprop")` over stacked Z-expectations yields gradient std ≈ 0.00 and stable convergence within ~150 steps (current), accelerating early stopping decisions.

## Performance Analysis

- Combined score gains vs. parameter reductions  
  • The current program’s 0.86 combined score surpasses the previous best (0.85) despite using 110 params vs. 146. This shows that smart parameter sharing can outperform brute-force depth or gate count increases.  
- Depth vs. generalization trade-off  
  • Although the current depth (120) is higher than the prior optimal (99), its generalization gap (0.06) is slightly lower than the best-depth circuit’s 0.07, implying depth penalties can be offset by parameter efficiency.  
- Parameter efficiency improvement  
  • Test-accuracy-per-parameter: current is 0.88/110 ≈ 0.008, compared to 0.87/146 ≈ 0.006 for the previous best. This ~30% efficiency boost underscores the value of param reuse.  
- Consistent feature-map reuploads stabilize validation  
  • All programs with three IsingZZ uploads (current, Gen 6, Gen 17) maintain validation accuracy ≥ 0.88, confirming this as a robust expressivity mechanism.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Alternate CRZ-ring direction per upload  
   In `apply_ansatz_block`, detect `upload_index = block_index // N_REPEATS` and, whenever `upload_index % 2 == 1`, traverse your CRZ ring in descending wire order (`[7,6],[6,5],…,[0,7]`) instead of ascending. This zero-cost bidirectional entanglement builds on the pure‐CRZ ring success, diversifies correlation pathways every other upload, and may boost expressivity without adding parameters.  

2. Share block parameters across repeats  
   Change your block offset logic to  
     `offset = (block_index // N_REPEATS) * N_PARAMS_PER_BLOCK`  
   so both repeats in each upload reuse the same parameter vector. This halves unique circuit-body parameters (from 110→55+2 readout), directly testing if stronger weight tying tightens generalization further, as seen in other top performers.  

3. Introduce sparse long-range CRZ links in odd uploads  
   After your regular ring of nearest-neighbor CRZs, add in blocks where `upload_index % 2 == 1`:  
     `qml.CRZ(params[offset + key_to_position["long_crz"]], wires=[0,4])`  
   with a single new key `"long_crz"`. This injects one trainable global entangler per odd upload, probing if sparse long-range coupling can capture nonlocal patterns without over-parameterization.  

4. Per-upload CRZ strength parameters  
   Instead of global `"crz_a"`/`"crz_b"`, expand to `"crz_a_u{u}"` and `"crz_b_u{u}"` for each upload `u ∈ {0,1,2}` in your `ANSATZ_SPEC`. This adds just 4 extra keys (total params +4) but lets each feature-map reupload tune its entanglement strength independently, testing upload-specific expressivity gains observed in other multi-upload models.  

5. Multi-upload readout calibration layer  
   Replace your single gain/bias with per-upload gains and biases: allocate `gains = params[N_CIRCUIT_PARAMS : N_CIRCUIT_PARAMS+3]` and `biases = params[N_CIRCUIT_PARAMS+3 : N_CIRCUIT_PARAMS+6]`. Compute each upload’s raw mean `raw_u` and predict via `pred = ∑_u gains[u] * (raw_u - biases[u])`. This 4× readout calibration (6 vs. 2 params) can adapt decision thresholds per upload, leveraging the strong pattern that readout tuning reduces generalization gaps.
