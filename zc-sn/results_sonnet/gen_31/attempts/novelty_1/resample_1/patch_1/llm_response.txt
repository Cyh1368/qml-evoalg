shared_param_entangling_ring

<DESCRIPTION>
The best-performing prior program achieved a higher score (0.87) primarily by using parameter sharing on the entangling ring (alternating even/odd shared CRZ parameters) rather than fully independent parameters, which reduced parameter count and improved generalization gap (0.06 vs 0.08). The current candidate instead uses many independent RZ parameters (16 total) plus a mixed CZ/CRZ entangling layer, which increased parameter count to 212 and hurt validation/test accuracy and gap.

This edit applies the same parameter-sharing philosophy to the current architecture: it replaces the 8 independent "rz_pre" and 8 independent "rz_post" single-qubit rotations with 2 shared parameters each (alternating even/odd wires), and replaces the mixed CZ+CRZ entangling layer with a full 8-qubit ring of CRZ gates using two shared parameters (alternating even/odd edges, matching the proven pattern from the best prior program). This cuts total parameter count substantially (from 212 down to roughly 8+2+2+8+2 = ~40 per block instance) while preserving full ring connectivity, which should reduce overfitting, shrink the train-test gap, and speed convergence, consistent with the evidence that parameter-efficient shared-rotation ansätze generalize better on this task.
</DESCRIPTION>
