# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Five‐layer hierarchical ansatz repeated over three data uploads and two repeats, combining:  
  1) pre‐entanglement RZ (corner/edge/center symmetry groups)  
  2) RY (corner/edge/center)  
  3) single‐parameter CRX ring on the outer eight qubits  
  4) single‐parameter CRY hub from center to edges  
  5) post‐entanglement RZ (corner/edge/center)  
  This pattern (the “seed” program) achieved the top combined score of 0.60 (train 0.57, val 0.65, test 0.50, gap 0.07) with 66 parameters, depth 70, gate_count 261.  
- Single shared parameter for all outer‐ring CRX gates concentrates entangling power efficiently. Splitting the ring into multiple CRX parameters (e.g. Gen 73’s “two_param_ring_diversification,” 78 params) dropped the combined score to 0.45.  
- Single shared parameter for all center‐to‐edge CRY couplings preserves entanglement expressivity without inflating parameter count. Program Generation 72 (“crx_ring_and_hub_shared”) used this pattern but deviated in other layers and only scored 0.47.  
- Distinct pre- and post-entanglement RZ rotations for corner, edge, and center (six symmetry‐shared parameters) maintain rotational symmetry while preserving circuit expressiveness—key to the seed’s high validation accuracy (0.65) vs. underfitting models.  

## Ineffective Approaches  
- Fragmenting shared entanglement parameters undermines learning: Gen 71 (“ring_reinforcement_crx_ring,” 72 params) saw its combined score fall to 0.49, and Gen 73 (78 params) to 0.45. More entanglement parameters did not translate to better performance.  
- Replacing parameterized CRX ring gates with non‐parametric CZ gates (Gen 75 “swap_center_edge_crz_for_center_rz,” 66 params) led to severe underfitting (combined score 0.32, test accuracy 0.15). Parameterized rotations are crucial for capturing tic-tac-toe patterns.  
- Over-aggressive or excessive parameter sharing that reduces distinct rotation angles can underfit. Gen 74 (“edge_orientation_symmetry_refinement,” 90 params but with stricter sharing) achieved only a 0.44 combined score despite increased parameter budget.  
- Deviating from the five‐layer motif by adding or removing layers yielded diminishing returns. None of the tested variants with extra layers or deeper circuits exceeded the seed’s 0.60.  

## Implementation Insights  
- Building a param‐key→index map (`key_to_position`) once per `apply_ansatz_block` call achieves O(1) parameter lookup, minimizing Python overhead in the hot loop of repeated block applications.  
- A front‐loaded `validate_ansatz_spec` prevents wasted compute on malformed circuits (no SPEC_ERRORS in the seed versus prior Gen 69 blocking execution).  
- Using `qml.queuing.AnnotatedQueue` plus `QuantumScript.from_queue` yields accurate depth and gate counts (depth 70, gate_count 261 for the seed), guiding designs toward the empirically optimal sweet spot.  
- Encoding the ANSATZ_SPEC entirely within the EVOLVE‐BLOCK and keeping training, data splits, and measurement code fixed ensures fair comparisons across candidates and isolates the impact of ansatz changes.  

## Performance Analysis  
- The seed’s combined score of 0.60 stands well above all variants: Gen 71 (0.49), Gen 72 (0.47), Gen 73 (0.45), Gen 74 (0.44), Gen 75 (0.32).  
- Parameter budget≈66 is optimal: increasing to 72, 78, or 90 parameters consistently lowered combined scores by ≈0.10–0.20.  
- Depth≈70 and gate_count≈261 correlate strongly with higher scores; none of the deeper circuits (e.g., Gen 74’s depth 78) outperformed the seed.  
- A generalization gap around 0.07 (seed: train 0.57→test 0.50) aligns with robust learning; models with very low gaps (< 0.03) all exhibited near-random test accuracy, indicating underfitting.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Subdivide the CRX‐ring parameter across uploads while preserving budget by merging the two center RZ keys  
   – In `ANSATZ_SPEC`, replace the single `"crx_ring"` key with `"crx_ring_0"`, `"crx_ring_1"`, and `"crx_ring_2"`, each shared across the two repeats of uploads 0, 1, and 2 respectively.  
   – At the same time, merge `"rz_pre_center"` and `"rz_post_center"` into a single `"rz_center"` parameter (used in both layers) to keep the total count at 66.  
   Rationale: this adds controlled flexibility in ring entanglement per upload—building on the proven shared‐ring motif—while retaining the optimal parameter budget and five‐layer structure.  

2. Alternate the direction of the CRX‐ring on every other repeat to diversify entanglement patterns without extra parameters  
   – In `apply_ansatz_block`, branch on `repeat_index % 2`: if even, apply the eight CRX gates in ascending order `[0→1,1→2,…]`; if odd, apply them in descending order `[7→0,6→7,…]`, all still using the same `"crx_ring"` key.  
   – No changes to `ANSATZ_SPEC` or parameter count.  
   Rationale: directional diversity can enrich the circuit’s expressivity while leveraging the same shared‐parameter entangler that proved critical in the seed.  

3. Introduce a symmetry‐shared mid‐layer of RZ rotations between the RY and CRX stages  
   – After the existing RY rotations in `_build_hierarchical_ansatz_spec`, append three gates:  
     • `{"gate": "RZ", "wire": i, "param": "rz_mid_corner"}` for i ∈ CORNERS  
     • same for EDGES with `"rz_mid_edge"`, and for CENTER with `"rz_mid_center"`.  
   – To preserve parameter budget, merge `"rz_pre_center"` and `"rz_post_center"` into `"rz_center"` as above (dropping one key) so the net parameter count stays at 66.  
   Rationale: a brief phase‐adjustment layer immediately before entanglement can fine‐tune the RY‐prepared states, leveraging the power of symmetry‐shared RZ rotations demonstrated in the seed.  

4. Mix entanglement modalities on the hub layer without adding parameters  
   – In `apply_ansatz_block`, for the four center–edge connections, use `qml.CRY` when `block_index % 2 == 0` and `qml.CRX` when `block_index % 2 == 1`, both with the shared `"cry_hub_edge"` key.  
   – No change to `ANSATZ_SPEC` or parameter count—just swap the gate class in the hot loop.  
   Rationale: alternating between CRY and CRX on the same hub‐edge wires may capture complementary correlation patterns while holding the parameter budget and depth constant.  

5. Add a small learned offset to the `"ry_edge"` rotations on the second repeat of each upload
