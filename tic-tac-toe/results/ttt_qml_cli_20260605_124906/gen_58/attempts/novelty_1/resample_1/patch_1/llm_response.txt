<DESCRIPTION>
The current program uses a fixed FEATURE_SCALE (2π/3) for encoding board values across all data re-uploads. Prior runs show validation accuracy around 0.55–0.65 but test accuracy lags significantly (0.48–0.52), indicating poor generalization.

The recommendation to make the feature-map scale upload-adaptive is well-motivated:
1. **Gradient smoothing**: Different uploads can learn different encoding sensitivities. Early uploads might benefit from aggressive encoding, while later uploads refine with gentler scaling.
2. **Convergence acceleration**: Upload-specific deltas allow the optimizer to adjust encoding per stage without adding circuit depth.
3. **Reduced overfitting**: Adaptive encoding can help the model learn more robust representations, narrowing the train-test gap.

Implementation:
- Replace the fixed `FEATURE_SCALE` constant with a trainable `feature_scale_base` parameter.
- Add three per-upload delta parameters: `feature_scale_delta_0`, `feature_scale_delta_1`, `feature_scale_delta_2`.
- In the `feature_map` function, compute each wire's angle as `(feature_scale_base + feature_scale_delta_upload_index) * board[wire]`.
- Initialize `feature_scale_base` to the original 2π/3 and deltas to small values (e.g., ±0.01).

This adds only 4 new trainable parameters (1 base + 3 deltas) per block, scaling to 24 total parameters across all 6 blocks (3 uploads × 2 repeats). The modest parameter increase should improve generalization without significant computational overhead.

Expected improvements:
- Smoother gradient flow during training
- Better test accuracy by learning upload-specific encoding strategies
- Reduced generalization gap
- Faster convergence in early epochs
</DESCRIPTION>
