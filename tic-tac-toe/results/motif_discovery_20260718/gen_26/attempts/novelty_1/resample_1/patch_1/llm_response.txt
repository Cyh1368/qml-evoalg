<DESCRIPTION>
The previous candidate used a fixed set of parameter keys for every ansatz block across all data re-uploads. While this is parameter-efficient, it forces the circuit to apply the same transformation regardless of where it sits in the serial embedding chain. 

I am lifting this symmetry by introducing distinct parameter pools for each of the 3 uploads (u0, u1, u2). By giving each upload its own local rotation parameters (RY and RZ), following the recommendation to break full across-upload symmetry, we allow the model to learn different weighting strategies for the same input features as they are re-introduced to the system. This increases the total parameter count to 102 but allows for significantly more expressive non-linear mappings. I have kept the motif gates (ZZZ, CCRZ) and the center-controlled spokes (CRZ) shared within the block to maintain regularized entanglement.
</DESCRIPTION>

def _get_lifted_keys():
    errors, base_keys = validate_ansatz_spec(ANSATZ_SPEC)
    lifted = []
    for u in range(N_UPLOADS):
        for k in base_keys:
            if any(rot in k for rot in ["ry_", "rz_"]):
                lifted.append(f"{k}_u{u}")
            else:
                lifted.append(k)
    return errors, list(dict.fromkeys(lifted))
