shared_two_param_entangler_with_mixer

<DESCRIPTION>
The current 5-distinct-parameter even/odd + ZZ-ring + CRZ-long + RZ-all spec underperforms (score 0.52) relative to the simpler 2-parameter global-RY + global-RZ + 3-shell CRZ-entangler spec (score 0.61) from prior generations. Parameter economy is explicitly rewarded ("fewer distinct trainable parameter names ALWAYS scores higher"), so we revert to that proven 2-parameter backbone (theta_ry for local rotations, theta_z shared between the RZ layer and all three CRZ entangling shells — nearest-neighbor, skip, and antipodal rings on the 8-qubit cycle).

On top of that proven structure we add a mixer-style closing single-qubit RY layer that REUSES the existing "theta_ry" parameter (no new trainable parameter introduced) rather than introducing a fresh "theta_ry_out" parameter as the naive QAOA-mixer recommendation suggests. This gives the circuit an extra alignment layer after the entangling shells — letting the pre-existing rotation angle also act as a final Bloch-vector alignment step before measurement — sharpening class separability without paying any parameter-count cost. Because parameters are tied across all 3 repeats, this simply changes the per-repeat gate sequence (RY-theta_ry, RZ/CRZ-theta_z shells, RY-theta_ry again) while keeping N_CIRCUIT_PARAMS at 2, matching the best-performing configuration's economy while giving optimization one more nonlinear knob to exploit the same 2 parameters, which should help robust separation on the hardest validation group and reduce the train/validation gap.
</DESCRIPTION>
