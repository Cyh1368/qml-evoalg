# Scientific validity audit

Reproduce with `python3 research/audit.py` (NumPy only). Computed results are in `audit_results.json`. No candidate code is executed and no cluster/API resources are used.

## Confirmed findings

1. **Historical test leakage affects selection, not merely reporting.** In the original `experiments/transfer-sn/evaluate.py`, `score_result` used `abs(train_accuracy - test_accuracy)` with weight 0.15 even when `USE_TEST_IN_SCORE=0`. Public feedback also disclosed test accuracy, test loss, a test-derived generalization gap and test-derived parameter efficiency. `initial_program.py` computes those latter two fields from test accuracy. Historical test performance therefore measures an adaptively reused development set, and cannot establish held-out generalization. Fresh final data are necessary.

2. **The dataset has no exact duplicates across splits**, and each split is balanced: 450 training, 300 validation, 600 test, each with 50% positives. `make_dataset.py` shares a `seen` set across splits. This checks labeled feature vectors only; graph-isomorphism orbit overlap is not excluded. For a claim of generalization to unseen graph structures, split by graph-isomorphism class and report orbit overlap separately. For ordinary IID graph sampling, orbit overlap is a different estimand rather than automatically a leak.

3. **An extremely cheap invariant baseline is already strong.** Fit a single edge-count threshold on training only (choose smallest maximizing threshold). The rule predicts connected iff the graph has at least 9 edges. Accuracies: training 84.22%, validation 83.00%, reused historical test 86.33%. This is a diagnostic baseline, not a new confirmatory held-out result. It indicates density is a substantial shortcut under the class-balanced Erdos–Renyi sampling scheme. Future evaluation should include density-matched classes, shifted edge probabilities, degree/isolated-vertex baselines and exact classical connectivity as a task-solvability reference. Quantum advantage is not established by this task.

4. **563 selected proposals are not 563 independent experiments.** The frozen labels contain 854 rows; the report's own/parsed and generation-at-most-20 scratch filter leaves 563: weak 300, mid 182, frontier 73, frontier-no-gpt 8. `analysis/report/compute_stats.py` uses proposal-level bootstraps and Mann–Whitney comparisons for circuit structures, while proposals share ancestry, task data, initialization protocols and adaptive selection. Use run-level resampling/cluster models, retain failed proposals in budget accounting, and report scratch and continuation separately.

5. **Model capability is not an identified continuous variable.** Ensemble membership jointly changes model identity, reasoning effort, provider mix, monetary cost and adaptive UCB exposure (README). Three ordered labels do not establish a scaling law. Mid/weak equality is compatible with uncertainty, search bottlenecks or a threshold mechanism. A prospective design needs individual-model arms or balanced randomized proposal assignment, matched budgets, repeated runs and an independently specified continuous predictor. Do not choose a predictor after examining the symmetry outcomes.

6. **Structural labels are not certificates.** Gate coverage and parameter sharing do not in general guarantee unitary commutation because gate order matters for noncommuting controlled rotations. The README's general claim that shared bidirectional controlled rotations on all pairs are individually invariant needs gate-family-specific proof. Test the implemented operator or its channel under the group, and distinguish ansatz-family, trained-unitary and predictor invariance. Patch-note matches are observable language features, not evidence of internal reasoning or causal understanding.

## Prospective patch and its boundary

The evaluator now uses the selected primary accuracy for the gap term (validation by default), removes public test accuracy/loss, and recomputes public gap and parameter efficiency from validation. Its docstring labels the scoring change v2. `audit.py` executes the actual evaluator function AST without importing Shinka and asserts that changing every test-derived field leaves the default score, public metrics and feedback unchanged. This regression passed.

`USE_TEST_IN_SCORE=1` remains an explicitly leaky legacy mode. Raw result files and private outputs still retain test values, and candidate training still loads/evaluates the historical test. Consequently this patch fixes the ordinary public-feedback path, but does **not** create a security boundary or a valid final holdout. Prospective search must use a development-only dataset; a separately controlled final evaluator must load fresh data only after candidate and analysis choices are frozen. Do not compare v2 scores numerically with historical scores. Historical affine anchors are merely a display transform and do not retain their original baseline interpretation under v2.

## Minimum confirmation protocol

Predefine the task distribution, symmetry representation, mathematical defect, primary outcome and search budget. Freeze at least one task family for transfer. Randomize matched interventions that vary symmetry while controlling parameter count, gate count and trainability as far as possible; also report where these controls cannot be achieved. Use independent training seeds nested within independent search runs, report all attempted evaluations, and reserve unseen final graph orbits/distribution shifts. Treat the current dataset and all retrospective analyses as exploratory.
