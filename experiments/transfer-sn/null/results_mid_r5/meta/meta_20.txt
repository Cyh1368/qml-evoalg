# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Aggressive parameter sharing with a minimal key set (ry_a, ry_b, rz_0, rz_1, rz_2) combined with a linear CZ entanglement chain drove raw score from 0.99→1.00. The current best (Seed program) uses exactly this pattern (32 params, depth 93, gate_count 222) and converged to perfect 1.00/1.00/1.00 accuracy in ~480 steps with zero generalization gap.

- Consistently using N_UPLOADS = 3 and N_REPEATS = 2 reupload stages (as in Generations 17, 19, and the Seed) sufficed for full expressivity; deeper or additional repeats (e.g., Generation 19’s depth 120) did not improve accuracy.

- A two-parameter gain/bias calibration on the mean Pauli-Z readout was essential: all perfect‐accuracy programs (Generation 17, Seed) included trainable gain and bias and achieved validation/test loss ≈ 0.00.

- Shared RY rotations across even/odd wires plus a symmetric three-key RZ scheme (rz_0 on wires 0,2,6; rz_1 on 1,3,5; rz_2 on 4,7) maximized expressivity per parameter. This appears in both Generation 17 and the Seed and underpins the jump to combined_score_raw = 1.00.

## Ineffective Approaches

- Fully distinct per-wire rotations (no sharing) bloated parameter counts without improving accuracy. Generation 15’s 26-param “compact_small_world_ansatz” reached only 0.95 raw score, while over-parameterized circuits (122–164 params) peaked around 0.97 with parameter efficiency ~0.01.

- Adding sparse long-range CRZ links (Generation 17’s “shared_sparse_crz_reduction”) increased depth to 111 and gate_count to 240 but yielded only marginal combined_score = 1.53 (raw accuracy remains 1.00), with no parameter-efficiency gain over the linear CZ chain.

- Ring-topology entanglers (Generation 18) plateaued at raw 0.71 with a generalization gap of 0.08, showing that circular C-Z layouts underperform linear chains per layer.

- Excess depth (>120) or gate counts (>250), as in Generation 19, slowed convergence and provided no accuracy uplift, limiting parameter efficiency to 0.03 despite perfect or near-perfect accuracy.

## Implementation Insights

- Defining ANSATZ_SPEC as a flat list of gate dictionaries with shared param keys, then extracting ordered keys via validate_ansatz_spec, enables a compact, fully shared parameter vector (32 parameters) and simplifies gradient application.

- Computing a key_to_position map once per block and indexing into a flat `params` array in apply_ansatz_block minimizes Python overhead and clarifies the mapping from spec to circuit.

- Structuring the qnode with nested loops—`for upload in range(3): feature_map(); for repeat in range(2): apply_ansatz_block()`—ensures uniform block application and makes N_UPLOADS/N_REPEATS easy to tune globally.

- Implementing readout as `raw = mean(z)`, then `gain*(raw - bias)`, consistently reduced validation/test loss to zero; this pattern appears in every top‐scoring program and is critical for perfect calibration.

## Performance Analysis

- Combined raw score climbed from 0.71 (Generation 18) → 0.93 (Generation 16) → 0.96 (Generation 19) → 0.99 (long-range CRZ variants) → 1.00 (Seed). The leap to 1.00 coincides with minimal shared-param design and linear CZ chains.

- Parameter efficiency doubled from ~0.01 in over-parameterized models to ~0.03 in the 32-param Seed, without loss in accuracy.

- Convergence slowed as parameters were trimmed: high-param circuits converged in ~240 steps, whereas the Seed converged in ~480 steps, trading per-step speed for maximal final accuracy and efficiency.

- A “sweet spot” of depth ≈ 90–100 and gate_count ≈ 220–230 (Seed: 93/222) correlates with fastest convergence to perfect accuracy; deviating deeper or shallower compromised either training speed or final performance.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Introduce per‐upload feature‐map scaling  
   After each call to feature_map(records), multiply the FEATURE_SCALE by a trainable scalar α_upload[upload_index]. Concretely, replace  
     qml.IsingZZ(FEATURE_SCALE * x, wires=…)  
   with  
     qml.IsingZZ(α_upload[upload_index] * FEATURE_SCALE * x, wires=…)  
   This adds only 3 parameters and lets the circuit learn the optimal embedding strength for each of the three uploads, building on the proven stability of the fixed map in the Seed program.  

2. Alternate forward/reverse linear CZ chains  
   In ANSATZ_SPEC, define two CZ‐gate sequences—forward ([0–1,1–2,…,6–7]) and reversed ([7–6,6–5,…,1–0])—and apply them on alternating blocks (e.g. even block_index uses forward, odd uses reversed). This preserves depth (≈93) and gate count (≈222) while enriching entanglement patterns within the proven linear‐chain paradigm.  

3. Add minimal dual‐axis RX rotations  
   Immediately after each CZ chain in ANSATZ_SPEC, insert RX gates on every qubit using two new shared parameters {rx_even, rx_odd}, assigned respectively to even and odd wires. This adds just 2 parameters, complements the existing RY/RZ sharing strategy, and injects a second rotation axis per block to boost expressivity without appreciable depth increase.  

4. Two‐tier RY/RZ sharing across repeats  
   Instead of one global set of {ry_a, ry_b, rz_0, rz_1, rz_2}, define separate key‐sets for the first and second repeat within each upload—e.g. {ry_a_0, ry_b_0, rz_0_0, rz_1_0, rz_2_0} for repeat 0 and {ry_a_1, ry_b_1, rz_0_1, rz_1_1, rz_2_1} for repeat 1. This doubles block-shared keys from 5 to 10, allowing the two repeats to specialize their rotation patterns while retaining aggressive sharing and keeping total parameters lean.  

5. Parity‐weighted linear readout  
   In predict_batch, replace raw = mean(z) with  
     raw = (w_even * sum_{w even} z_w + w_odd * sum_{w odd} z_w) / (4*(w_even + w_odd))  
   and then apply the existing gain and bias. Adding only 2 weights (w_even, w_odd) leverages the critical gain/bias calibration step while giving the model the ability to emphasize even- versus odd-wire signals—an efficient middle ground between a flat mean and full per-qubit weighting.
