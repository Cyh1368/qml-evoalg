# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Feature re-uploading with fixed IsingZZ couplings before each ansatz block consistently boosts expressivity. The current best “8-Qubit Re-uploading Phase Coupling Classifier” (combined_score_raw = 0.97, convergence ≈ 180 steps) and other top performers (Programs 2 and 6, both 0.97) all use three uploads.  
- Layered per-qubit rotations (RY, RZ-pre, CZ entanglers, RZ-post) in a linear chain, repeated twice per upload, achieved the highest combined_score_raw (0.97) and fastest convergence (~180 steps). This pattern outperformed both circular CNOT layouts (Program 1 at 0.96) and more complex entanglement.  
- A simple global calibration layer (trainable gain and bias) on the mean Pauli-Z output lowered test loss to 0.12 in the current best, matching or improving upon all other designs.  
- Favoring CZ entanglers over CNOT rings yielded a measurable +0.01 gain in combined_score_raw (current best 0.97 vs Program 1: 0.96), suggesting linear CZ chains better balance entanglement depth and parameter count.  

## Ineffective Approaches  
- Adding parametric long-range CRZ “skip” couplings (Program 4) increased circuit parameters from 146 to 182 and depth from 99 to 111, yet dropped combined_score_raw to 0.96 and slowed convergence to ~240 steps.  
- Ring-topology CNOT entanglement (Program 1) achieved rapid convergence (~120 steps) but plateaued at 0.96 combined_score_raw, indicating less expressivity than the CZ-chain layout.  
- Over-parameterization (Programs 2, 4, 6 with 182–228 gates and 146–182 params) uniformly yielded low parameter efficiency (~0.01) without boosting test accuracy beyond 0.99.  
- Excessively deep or repeated blocks (Program 2 converged in ~390 steps at depth 99) produced stable fits but incurred long training times with no accuracy gain over the current best.  

## Implementation Insights  
- Defining the ansatz as a list of gate dictionaries (ANSATZ_SPEC) and mapping parameter keys to flat parameter arrays via a block-offset lookup made it easy to iterate repeats and maintain consistent indexing—critical for the current best’s clean 146-parameter implementation.  
- Wrapping each upload in a `for upload_index` loop that calls `feature_map` followed by `apply_ansatz_block` yields a modular, re-usable pipeline; this structure underpins the rapid convergence (~180 steps) of the top performer.  
- Employing PennyLane’s backprop QNode with `pnp.array(..., requires_grad=True)` enabled efficient mini-batch Adam updates and autograd differentiation, outperforming more cumbersome tape-based gradients.  
- Early stopping on validation loss (min_delta 1e-4, patience 75) with best-weight restoration consistently capped the generalization gap at 0.01 in the current best, preventing overfitting despite deep circuits.  

## Performance Analysis  
- The current best model’s combined_score_raw = 0.97 (train/val/test = 1.00/0.99/0.98, depth 99, gates 270, params 146) leads the pack, outperforming Program 1 (0.96) and Program 4 (0.96) with heavier or alternate entanglement.  
- Reducing parameters from 182 (Program 4) to 146 (current best) preserved peak accuracy (0.99 test) while trimming convergence by ~60 steps.  
- Depth trimming from 114 (Program 6) to 99 (current best) incurred no accuracy loss, indicating that adding extra ring entanglers was superfluous.  
- A clear correlation emerged: models with lower param counts and moderate depth (current best) converged fastest (~180 steps), whereas over-parameterized designs (Program 2) required ~390 steps for similar test accuracy.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Introduce per-feature trainable scaling factors in the feature map. Add a vector `feature_scale_params` of length `N_FEATURES` so that each upload calls  
   ```python
   qml.IsingZZ(FEATURE_SCALE * feature_scale_params[k] * records[..., k], wires=[a, b])
   ```  
   This adds only 28 parameters but lets the model adapt the embedding strength of each feature, building on the success of fixed IsingZZ couplings.

2. Alternate the direction of the CZ chain between repeats. In your `ANSATZ_SPEC`, define two versions of the CZ block—one forward (0–1,1–2,…,6–7) and one backward (7–6,…,1–0)—and apply them in alternating repeats within each upload. This covers bidirectional entanglement without increasing gate count and exploits the proven efficacy of linear CZ chains.

3. Tie ansatz parameters across uploads to boost parameter efficiency. Instead of allocating separate `N_PARAMS_PER_BLOCK` parameters for each of the 3 uploads, share the same parameter block by indexing `block_index % N_REPEATS` in `apply_ansatz_block`. This reduces `N_CIRCUIT_PARAMS` by a factor of three while preserving the expressive triple-upload structure that converged in ~180 steps.

4. Upgrade the global readout calibration to per-qubit gain and bias. Replace the two scalars with vectors of length `N_QUBITS` so that  
   ```python
   raw = pnp.stack(circuit_z_expectations(...)).T  # (B, N_Q)
   calibrated = gain_vec * (raw - bias_vec)        # element-wise
   predictions = pnp.mean(calibrated, axis=1)
   ```  
   Since a simple global layer cut test loss to 0.12, per-qubit calibration may further tighten the generalization gap.

5. Inject sparse, shared CRZ couplings on high-correlation feature pairs. Identify the top 2–3 most informative FEATURE_PAIRS and append a single `{"gate":"CRZ","wires":[a,b],"param":"crz_shared"}` to `ANSATZ_SPEC`, using one trainable `crz_shared` parameter shared across all blocks. This controlled long-range entanglement builds on the CRZ motif without the over-parameterization pitfalls of Program 4.
