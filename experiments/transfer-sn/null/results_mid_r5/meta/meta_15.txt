# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Aggressive parameter sharing via a minimal key set (ry_a, ry_b, rz_0, rz_1, rz_2) in the ANSATZ_SPEC block yielded the current best result: combined_score_raw = 1.00, perfect 1.00/1.00/1.00 accuracies, parameter efficiency = 0.03 with only 32 trainable parameters (depth 93, gate_count 222).  
- A linear CZ-chain entanglement pattern immediately following shared RY layers (CZ on [0,1],[1,2],…,[6,7]) consistently delivered full separability and zero generalization gap, as seen in both the seed program and prior top circuits (Programs 6 and 11).  
- The 3×2 layout—three fixed IsingZZ feature-map uploads interleaved with two ansatz repeats—proved sufficient for perfect classification. Both the current best program and earlier high-scorers (Programs 2, 6, 11) used N_UPLOADS = 3, N_REPEATS = 2.  
- A simple two-parameter gain/bias calibration on the mean Pauli-Z output was essential for minimizing validation/test loss to ~0.00, consistently featured in all perfect-accuracy models, including the current best.

## Ineffective Approaches

- Fully distinct per-wire RY/RZ rotations bloated parameter counts (122–164) without improving beyond combined_score_raw ≈ 0.97 (Programs 7 and 8), resulting in poor efficiency (~0.01).  
- Introducing long-range CRZ “skip” links (Program 9’s hybrid_ring_shared_crz) increased depth to 120 and gate_count to 252 but only reached raw 0.99 and slowed convergence to ~240 steps, showing no accuracy gain.  
- Ring-topology CNOT entanglers (Program 1) plateaued at raw 0.96 with a 1% generalization gap, underperforming compared to CZ chains in expressivity per layer.  
- Excessively deep (>120 layers) or gate-heavy (>250 gates) circuits gave no accuracy boost yet increased training burden.

## Implementation Insights

- Representing the ansatz as a flat ANSATZ_SPEC list of dicts with shared parameter keys and deriving `PARAMETER_KEYS_PER_BLOCK` via `validate_ansatz_spec` enables bulk sharing and a compact parameter vector, as in the 32-param seed.  
- Structuring the circuit with nested loops—`for upload in range(3): feature_map(); for repeat in range(2): apply_ansatz_block()`—allows systematic exploration of depth vs. reuse, simplifying modifications to N_UPLOADS/N_REPEATS.  
- Early stopping on validation loss (patience = 75, min_delta = 1e-4) with best-weight restoration stabilized training and ensured zero generalization gap, particularly effective in the current best program that converged by ~480 steps.  
- Alternating shared RY parameters across even/odd wires and distributing three shared RZ keys symmetrically (rz_0 on wires 0,2,6; rz_1 on 1,3,5; rz_2 on 4,7) maximizes expressivity per parameter and simplifies gradient application.

## Performance Analysis

- Combined_score_raw improved from 0.96 (Program 1, ring-CNOT, depth 120) → 0.99 (Program 9, added CRZ links, depth 120) → 1.00 (Programs 11 & current best, 32 params, depth 93), demonstrating that leaner, shared-param designs outperform bulky ones.  
- Parameter efficiency (accuracy/N_PARAMS) doubled from ~0.01 in over-parameterized circuits (122–164 params) to 0.03 in the 32-param shared-parameter ansatz, with no loss in accuracy.  
- A depth/gate_count “sweet spot” around 90–100 depth and ~220–230 gates—realized by the current best program (depth 93, gate_count 222)—delivered fastest convergence to perfect accuracy; deviating deeper or shallower degraded performance or training speed.  
- Trimming parameters increased convergence steps (from ~180 in 146-param models to ~480 in the 32-param seed) but yielded maximal final accuracy and efficiency, highlighting a trade-off between per-step speed and parameter economy.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Introduce upload‐specific feature‐map scaling  
   After each feature_map call, multiply the IsingZZ angles by a small trainable scalar α_upload per upload index. Concretely, replace  
     qml.IsingZZ(FEATURE_SCALE * records[..., k], wires=[a,b])  
   with  
     qml.IsingZZ(α_upload[upload_index] * FEATURE_SCALE * records[..., k], wires=[a,b])  
   This adds only 3 parameters and lets the circuit learn the optimal embedding strength for each of the three upload cycles, building on the proven fixed‐map success in the best program.  

2. Alternate forward/reverse CZ chains between repeats  
   Define two CZ patterns in ANSATZ_SPEC—one linking (0–1,1–2,…,6–7) and one reversed (7–6,…,1–0)—and apply them alternately in each of the six blocks (e.g. forward on block_index % 2 == 0, reverse otherwise). This keeps the same gate count/depth while enriching entanglement diversity, leveraging the demonstrated power of linear CZ chains without adding extra parameters.  

3. Append a shared long‐range CRZ to each block  
   At the end of every ansatz block, insert  
     qml.CRZ(γ, wires=[0,7])  
   with a single new trainable parameter γ. This one extra gate per block injects global end‐to‐end entanglement in a parameter‐efficient way, drawing on the limited CRZ motifs that previously nudged accuracy upward without bloating depth.  

4. Add dual‐axis RX rotations with minimal sharing  
   Extend ANSATZ_SPEC by inserting an RX on each qubit immediately after the CZ chain, using two shared parameters {rx_even, rx_odd} assigned respectively to even and odd wires. This adds just 2 parameters and gives the ansatz a second rotation axis—complementing the existing RY/RZ sharing strategy to boost expressivity with negligible depth change.  

5. Replace the simple mean readout with learnable per‐qubit weights  
   In predict_batch, instead of raw = mean(z), compute  
     weighted = ∑ₙ wₙ·zₙ / ∑ₙ wₙ  
   then apply gain and bias as before. Here w is an 8-dimensional positive weight vector (plus the existing global gain and bias), adding 8 parameters. This per-qubit aggregation has higher capacity than a flat mean, building on the readout calibration success in the current best program.
