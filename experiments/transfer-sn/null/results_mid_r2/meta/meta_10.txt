# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Ring‐CRX entanglement plus fixed CZ couplers with single‐qubit RY rotations (Generation 1 “compact_crx_ansatz” / current best): 98 parameters, depth 130, gate_count 228 ⇒ combined_score_raw 0.99, perfect 1.00 accuracy across splits, zero generalization gap.  
- Three feature‐upload rounds interleaved with two ansatz repeats (N_UPLOADS = 3, N_REPEATS = 2): consistently yields zero generalization gap (Gen 1 & Gen 4), enabling fresh data embedding before each parametrized block.  
- Trainable gain & bias readout on mean Pauli-Z measurement: stabilizes output scaling, contributing to flawless classification in top models (Gen 1 & current best).  
- Balanced circuit depth (~130) mixing single- and two-qubit gates delivers high expressivity with fast convergence (~150 optimizer steps), outperforming both shallower (< 100) and deeper (> 150) variants.  

## Ineffective Approaches  
- Aggressive parameter sharing (Gen 7 “reduce_params_for_efficiency”): 26 parameters, depth 81, gate_count 228 ⇒ combined_score_raw –1.47, test_accuracy 0.76. Shared rotations cripple expressivity, leading to large performance drop.  
- Minimal two-qubit parameterization (Gen 6 “ring_parity_compact”): 24 parameters, depth 114, gate_count 228 ⇒ combined_score_raw 0.73, train/val/test accuracies ~0.83/0.78/0.76. Insufficient entanglement diversity prevents convergence within epoch limit.  
- Excessive parameter counts without structural gains (Gen 4 “enhanced_parametrized_entanglement”): 158 parameters, depth ≈130, gate_count 306 ⇒ combined_score_raw 0.99 but converged in ~210 steps vs ~150 for Gen 1, wasting 40% more resources.  
- Shallow, narrow ansatz without mid-circuit reuploads (Gen 2 “butterfly_symmetry”): though high accuracy (0.98–0.99), over-parameterized depth 117, gate_count 396, parameter_efficiency 0.02 suggests room for pruning.  

## Implementation Insights  
- Automate parameter indexing via a central ANSATZ_SPEC and key→position map to replicate blocks across uploads/repeats without manual offset errors (used in current best).  
- Employ a ring of CRX gates (one parameter per adjacent qubit pair) plus parallel CZ couplers for full‐circuit correlation—each block adds 8 two-qubit parameters yet captures long‐range entanglement efficiently.  
- Fixed IsingZZ feature map at scale π/2 over three uploads ensures robust, repeatable data embedding that synergizes with the CRX/CZ ansatz for high expressivity.  
- Separate circuit parameters from readout calibration (gain & bias as distinct trainable params) simplifies backprop and yields consistent accuracy across train/validation/test.  

## Performance Analysis  
- The best ansatz (Gen 1) with 98 params outperforms both more parameter-heavy (158 params, same accuracy but slower convergence) and leaner variants (74 params, combined_score 0.96–0.97).  
- Depth ≈130 is a “sweet spot”: deeper circuits (depth > 150) add no accuracy gain but slow training; shallower circuits (depth < 100) lose 0.02–0.03 in combined score.  
- Convergence speed tracks expressivity: Gen 1 converges in ~150 steps; Gen 4 (158 params) in ~210; compact yet under-expressive models (Gen 5) require ~750 steps or fail to reach thresholds.  
- Parameter efficiency (test_accuracy/n_params) peaks at ~0.01 in top models; dropping below this (too few params) or above (too many) correlates with lower scores or wasted resources.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Alternate two‐qubit rotation axes in successive ansatz blocks  
   Mutate ANSATZ_SPEC so that for block_index % 2 == 0 you use CRX on each ring edge, and for block_index % 2 == 1 you use CRY on the same wire pairs (i, i+1). Keep the same single‐qubit RY pre‐rotations and fixed CZ couplers, so total depth and gate count remain ≈ 130/228, but you introduce axis diversity that has been shown to enrich expressivity and accelerate convergence without adding parameters.  

2. Promote fixed CZ couplers to trainable CRZ gates  
   In each block of ANSATZ_SPEC, replace every “CZ” entry with a parameterized “CRZ” gate, assigning it a unique key (e.g. “crz_0”…“crz_7”). Update PARAMETER_KEYS_PER_BLOCK accordingly so you add 8 trainable coupling strengths per block. This builds on the synergy of fixed IsingZZ feature maps and CRX rings by giving the optimizer direct control over long‐range entanglement, which can further tighten your decision boundary.  

3. Append an RZ layer post‐entanglement in every block  
   Immediately after the last CZ/CRZ gate in each ansatz block, insert single‐qubit RZ rotations on all 8 wires with new parameters “rz_post_0”…“rz_post_7.” This adds only 8 parameters per block and a few gates to the depth, but breaks any residual symmetry left by RY + CRX/CRY + CZ, leveraging the known benefit of extra single‐qubit rotations without pushing depth beyond the Gen 1 sweet spot.  

4. Make the feature‐map scale trainable per upload  
   Replace the constant FEATURE_SCALE (π/2) with a small trainable vector of length N_UPLOADS (e.g. scale[0], scale[1], scale[2]) or even per‐feature if you wish. In feature_map, use qml.IsingZZ(scale[upload_index] * records[..., k], wires=[a, b]) so the network can learn optimal embedding strengths at each reupload. This builds on the robust repeatable embedding of Gen 1 while giving data‐map amplitudes direct gradient feedback.  

5. Share CRX parameters across repeats within each upload  
   In apply_ansatz_block’s indexing logic, map both repeats of the same upload to the same set of CRX parameters (i.e. for block indices 0 & 1 use keys crx_0…crx_7, for 2 & 3 use crx_8…crx_15, etc.), while keeping RY (and any new RZ/CRZ) fully unshared. This halves the two‐qubit parameter count from 16→8 per upload, yielding a more parameter‐efficient variant that still preserves fresh data uploads and expressivity of single‐qubit adjustments.
