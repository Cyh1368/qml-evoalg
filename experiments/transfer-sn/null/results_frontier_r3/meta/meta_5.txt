# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Repeated data re-uploads of the fixed IsingZZ feature map (N_UPLOADS = 3) interleaved with small ansatz blocks drove top scores (combined_raw = 0.98). Both Generation 1 (“Repeated-CZ Ansatz…”) and the current best program used this pattern to achieve perfect validation/test accuracy.  
- A brick-layer CZ entangling pattern in a closed ring (even pairs 0–1,2–3,… then odd pairs 1–2,3–4,…7–0) sandwiched between RY and RZ rotation layers produced highly expressive yet moderate-depth circuits (depth = 81, gates = 228).  
- Alternating single-qubit rotation layers (first an RY layer, then CZ, then an RZ layer, then the complementary CZ brick) yielded rapid convergence (~210 gradient steps to reach accuracy ≥0.90) and stable optimization.  
- A simple two-parameter output calibration (trainable gain and bias on the mean Pauli-Z) ensured tight margins and negligible generalization gap (~0.01).  

## Ineffective Approaches  
- Overparameterized ansätze (e.g. Generation 0’s 3-upload, 2-repeat RY–CZ–RZ chains with 144 parameters, depth = 99) scored lower (combined_raw = 0.97) and had poor parameter efficiency (~0.01). Simply stacking more repeats did not improve accuracy.  
- Replacing CZ-based entanglers with CNOT couplings in the custom block (Generation 2’s alternating RY–CNOT–RZ design) yielded a lower combined_raw = 0.96 despite matching parameter count and depth, suggesting the CZ ring closure better captures the binary feature correlations.  
- Attempts to collapse RY and RZ into commuting RZ-sharing moves (Generation 3, depth = 99) regained combined_raw = 0.97 but at unchanged low parameter efficiency, indicating that commuting optimizations alone did not suffice without reducing repeats or parameters.  
- Introducing parameterized two-qubit gates (CRX/CRY/CRZ) was not tested in top-scoring variants, but their absence in the best programs suggests the simpler CZ entangler suffices for this task.  

## Implementation Insights  
- Defining the ansatz via a declarative `ANSATZ_SPEC` and a generic `apply_ansatz_block` harnesses a consistent key-to-index mapping (via `PARAMETER_KEYS_PER_BLOCK`), simplifying iteration over repeats and re-uploads without bespoke gate calls.  
- Extracting circuit metadata through a Pennylane `AnnotatedQueue` and `QuantumScript` allows on-the-fly measurement of depth and gate count, facilitating rapid feedback on the cost of ansatz modifications.  
- Freezing the feature map encoding (fixed `qml.IsingZZ` couplings) decouples data encoding from variational search, focusing optimization on the minimal rotation-CZ-rotation topology that proved most effective.  
- Early-stopping with best-weight restoration and an L₂ loss on a trainable gain/bias output layer stabilized training across random seeds, consistently reaching high accuracy with minimal overfitting.  

## Performance Analysis  
- Moving from a 99-depth, 270-gate, 144-parameter design (Gen 0, combined_raw = 0.97) down to an 81-depth, 228-gate, 98-parameter CZ-ring design (Gen 1/current) raised combined_raw to 0.98. Reducing depth and parameters correlated with both higher accuracy and better parameter efficiency.  
- The current best (Gen 1) matched or beat all other variants on train/validation/test accuracy (0.99/1.00/1.00) and generalization gap (0.01) while using ~32% fewer gates than the initial program.  
- Substituting CNOT for CZ (Gen 2) or commuting RZs (Gen 3) degraded combined_raw by 0.01–0.02 despite preserving overall depth, underscoring the specificity of the rotation-CZ-rotation sequence with ring closure.  
- The highest parameter efficiency observed (~0.02) came from a later 56-parameter variant (Gen 5) that retained the CZ-ring and re-upload pattern, suggesting further parameter pruning without altering the core layer pattern can boost efficiency while preserving perfect accuracy.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Introduce parameter sharing across re-uploads and repeats to cut down on total parameters. For example, reuse the same `ry_i`/`rz_i` keys in each block by naming them identically in `ANSATZ_SPEC`, so that all N_UPLOADS×N_REPEATS blocks draw from one set of 16 rotation angles. This will reduce N_PARAMS by ~40% (toward the ~56-parameter Gen 5 design) while preserving the CZ-ring structure that achieved perfect accuracy.

2. Inject sparse learnable two-qubit couplings by replacing every other CZ gate in each brick layer with a small-angle `qml.CRZ` gate. Initialize those CRZ angles at π/2 (to match the fixed CZ strength) and let them train alongside the rotations. This tests whether a light sprinkling of parameterized entanglers can boost expressivity—and potentially generalization—without increasing circuit depth.

3. Fuse the separate RY→RZ single-qubit layers into `qml.U3` gates on each wire to reduce gate count. In `ANSATZ_SPEC`, replace each RY+RZ pair with a single U3 block carrying three internal parameters (θ, φ, λ), keeping the same qubit ordering and brick-layer CZs. This consolidation should lower depth and gate_count by ~25% while retaining the block’s expressivity profile.

4. Vary the feature re-upload vs. ansatz repetition schedule: experiment with N_UPLOADS = 2 and N_REPEATS = 3 (or vice versa), keeping the total block count near 6. The current best uses 3 uploads×2 repeats; swapping to 2×3 shifts more ansatz depth per encoding. Compare convergence steps and parameter efficiency to see if deeper per-upload circuits or more frequent data embeddings drive faster training.

5. Apply post-training magnitude-based pruning on rotation angles below a small threshold (e.g. |θ|<0.05) and then fine-tune the remaining parameters. This mimics the higher parameter efficiency (~0.02) seen in later experiments without touching the core CZ-ring pattern. By removing negligible rotations and re-optimizing, you may further compress the circuit—reducing both gate count and parameters—while holding test accuracy at 1.00.
