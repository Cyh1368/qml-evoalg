# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- CRZ-only entangling blocks on adjacent and skip-2 neighbors  
  • Seen in the current best program (three uploads × two repeats of ANSATZ_SPEC with CRZ on (0-1,2-3,4-5,6-7) and skip-2 CRZ on (1-3,3-5,5-7)), matching Generation 8 and Generation 16. Achieves combined_raw = 1.00, depth = 90, gate_count = 222, convergence ≃ 210 steps.  
- Final shared-parameter RZ layer  
  • Collapsing eight RZ rotations into one “rz_final” key (via dict.fromkeys in validate_ansatz_spec) reduces N_params_per_block from 23→16 and N_total from ≥120→98, with no loss in accuracy (Gen 8, Gen 16 both at 1.00).  
- Three feature re-uploads interleaved with two ansatz repeats  
  • The N_UPLOADS=3, N_REPEATS=2 layout consistently yields zero generalization gap (Gen 8, Gen 16), versus deeper variants (e.g. Gen 12 depth 120) that do not improve test accuracy.  
- Calibrated linear readout (trainable gain + bias)  
  • Present in every zero-gap classifier (Gen 7, Gen 8, Gen 16). Stabilizes decision thresholds to reach 100% test accuracy and generalization_gap=0.00.  

## Ineffective Approaches  
- Over-parameterized mixed-axis entanglers  
  • Gen 12 (“dense_rotational_entanglement_ansatz”, 146 params, depth 120) plateaued at combined_raw = 0.99 and incurred a nonzero generalization gap (0.01). Additional CRY/RY layers added depth without benefit.  
- High-depth, gate-heavy designs  
  • Gen 15 (“spiral_entanglement_quantum_ansatz”, 246 gates, depth 106) scored only 0.98 despite richer connectivity. Extra gates accelerated convergence slightly (~150 vs. 210 steps) but did not improve final accuracy.  
- Excessive parameter sharing in sparse layouts  
  • Gen 18 (“efficient_shared_parametrized_entangler”, 62 params) and Gen 19 (“shared_crz_skip_mixer”, 98 params) both underperformed (combined_raw ≤ 0.98) or converged very slowly (≈2,100 steps). Over-sharing entangler parameters reduced expressivity.  
- Under-parameterizing below ~90 total parameters  
  • Designs with ≤62 parameters (Gen 18) consistently dropped to combined_raw ≈ 0.98, indicating a lower bound on expressivity for perfect classification.  

## Implementation Insights  
- validate_ansatz_spec + dict.fromkeys for unique key ordering  
  • Generates ordered_unique_keys and automatically merges duplicate “rz_final” entries, directly yielding N_PARAMS_PER_BLOCK=16 in the best program.  
- Dynamic key-to-position mapping in apply_ansatz_block  
  • The `{key: index}` lookup decouples gate specification from parameter indexing, enabling safe additions/removals in ANSATZ_SPEC without re-calculating offsets.  
- Shared-parameter final RZ via repeated “param” strings  
  • Reusing the same `"param": "rz_final"` for all RZ gates implements weight sharing succinctly and cuts seven parameters per block.  
- AnnotatedQueue for accurate circuit profiling  
  • Using `qml.queuing.AnnotatedQueue` and `QuantumScript.from_queue` extracts exact depth and gate_count, ensuring reliable performance comparisons.  

## Performance Analysis  
- 98-parameter sweet spot → perfect score  
  • Both Gen 8 and the current best program use 98 trainable parameters, achieve combined_raw = 1.00, 0.00 generalization gap, depth = 90, gate_count = 222, and converge in ≃ 210 steps.  
- Depth >100 offers no accuracy gain  
  • Circuits with depth ≥106 (Gen 12, Gen 15, Gen 18) add gates and parameters but never exceed combined_raw = 0.99, and sometimes introduce generalization gaps or slower convergence.  
- Parameter efficiency plateaus at ~0.01  
  • Even the best 98-parameter models report parameter_efficiency ≈0.01; further reductions (e.g. 62 params) lower combined score, suggesting ~100 parameters are needed for full expressivity on this task.  
- Zero generalization gap tied to readout calibration  
  • Only designs with trainable gain and bias in the readout layer (Gen 7, Gen 8, Gen 16) achieve test_accuracy = 1.00 and generalization_gap = 0.00, underscoring its necessity for stable performance.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Collapse entangler parameters into shared keys  
   In your ANSATZ_SPEC, replace the four adjacent CRZ gates’ distinct params (`crz_01`,`crz_23`,…) with a single `"crz_adj"` key and collapse the three skip-2 CRZs into one `"crz_skip2"` key (using `dict.fromkeys` in `validate_ansatz_spec`). This cuts per-block params from 16→10 without changing connectivity. Both Gen 8/16 showed that weight-sharing on final RZs preserves accuracy, so the same principle on entanglers should improve parameter efficiency while retaining expressivity.  

2. Tie parameters across repeats (but keep upload-specific blocks)  
   Modify `apply_ansatz_block` so that the offset is `offset = upload_index * N_PARAMS_PER_BLOCK` (dropping `repeat_index`), causing each upload to reuse the same two-block ansatz. This reduces total circuit parameters from 98→50 + 2 readout and tests whether per-repeat heterogeneity is truly needed. Given the zero‐gap programs all converge in ≃210 steps, this ablation probes the minimal block diversity for perfect classification.  

3. Inject a single mixed-axis CRX per block  
   In each `ANSATZ_SPEC` block, replace one of the skip-2 CRZs (e.g. the middle link on wires [3,5]) with a `{"gate":"CRX","wires":[3,5],"param":"crx_35"}` entry and let `dict.fromkeys` collapse duplicates so you only add one new parameter per block. This brings orthogonal entanglement into the proven CRZ backbone at minimal depth overhead. Prior tests (Gen 12) showed that adding broad mixed-axis layers without constraint hurt performance—this targeted single-link CRX explores expressivity gains without over-parameterization.  

4. Augment blocks with a sparse long-range CRZ link  
   Append to each block’s `ANSATZ_SPEC` a `{"gate":"CRZ","wires":[0,4],"param":"crz_04"}` (and include `"crz_04"` in your key list). Collapsed via `dict.fromkeys`, this adds one global coupling per block to capture long-distance correlations. Evidence from sparse nonlocal links improving correlation suggests this minimal overhead may boost generalization without increasing depth beyond 90.  

5. Test 4 uploads with single repeat  
   Change to `N_UPLOADS=4`, `N_REPEATS=1` while preserving the 16-param CRZ-only block and shared final RZ. This interleaves data encoding more frequently (feature_map → ansatz_block cycles), keeping total blocks at 4 and N_PARAMS ≃66 + 2 readout. Earlier deeper variants converged faster when data was re-uploaded more often—this layout may both accelerate convergence and reveal whether deeper repeats add value beyond fresh feature injections.
