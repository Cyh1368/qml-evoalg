# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Interleaving feature re-uploads with compact RY–CRY variational blocks  
  • “8-Qubit Reuploading RY-CRY Quantum Classifier” (Gen 7) achieves combined_score_raw 0.99, 1.00/1.00/1.00 accuracies with only 98 parameters, depth 93, gate_count 222.  
  • Matches the expressivity of larger 146-param models (Gen 4, 6, 11) while trimming gate count by ∼18%.  
- Nearest-neighbor chain of parametrized two-qubit gates  
  • Replacing ring-CRZ (Gen 6: 146 params, 228 gates) with a linear CRY chain (Gen 7: 98 params, 222 gates) retained perfect separability and stable convergence.  
- Shared-parameter naming for per-block collapses  
  • All final RZ rotations use a single key “rz_final,” reducing N_PARAMS_PER_BLOCK by 7 versus unique per-qubit RZ keys with no loss in accuracy or convergence speed.  
- Calibrated linear readout (gain + bias)  
  • Present in every model with zero generalization gap (e.g. Gen 7: gap = 0.00), stabilizing decision thresholds and ensuring perfect test performance.  

## Ineffective Approaches  
- Over-parameterized deep ansatzes with 146 trainable parameters  
  • Gen 4 (controlled_multiscale_entanglement), Gen 6 (ry_crz_rx_circular_ansatz), Gen 11 (mixed_axis_ring_ansatz) each hit combined_score_raw 0.99 but parameter_efficiency remained ~0.01, indicating resource waste.  
- CZ-only entangling meshes without parameterized two-qubit rotations  
  • Gen 5 “8-Qubit Layered Quantum Binary Classifier” achieved only 0.75 test accuracy and a 0.09 generalization gap. Unparameterized CZ blocks failed to learn the boundary.  
- Excessive depth and symmetry (interleaved CZ heavy layouts)  
  • Gen 3 reached depth 132 and 348 gates for combined_score_raw 0.99—no accuracy gain justified nearly triple the gate count of leaner models.  
- Aggressive parameter pruning below ~90 total parameters  
  • Gen 10 “compact_parity_mixer” with 62 params saw combined_score_raw drop to 0.98 and validation accuracy slip to 0.99, suggesting a lower capacity limit for flawless classification.  

## Implementation Insights  
- Shared-parameter keys via dict.fromkeys in `validate_ansatz_spec`  
  • Collapses redundant entries (e.g. 8 RZ gates → one “rz_final”), shrinking `PARAMETER_KEYS_PER_BLOCK` without altering circuit topology.  
- Dynamic key-to-position mapping in `apply_ansatz_block`  
  • `{key: index}` lookup cleanly supports multiple uploads/repeats and avoids manual offset errors as N_UPLOADS or N_REPEATS scale.  
- Automated metadata extraction with `qml.queuing.AnnotatedQueue`  
  • Accurately logs depth and gate_count for each candidate, enabling fair comparisons (e.g. Gen 7’s depth 93, gates 222).  
- Balanced circuit capacity demonstrated by Gen 7  
  • Combines 16 params per block (8 RY, 7 CRY, 1 shared RZ) over 3 uploads × 2 repeats → 96 circuit params + 2 readout params = 98 total, hitting perfect accuracy with minimal overhead.  

## Performance Analysis  
- Score plateau at combined_score_raw ≈0.99 once parameters ≥98  
  • Larger models (146 params) do not exceed this plateau, confirming over-parameterization beyond ~100 params.  
- Gate-count vs. convergence trade-off  
  • Ring-CRZ models (Gen 6, Gen 11) converge in ~120 steps; linear CRY (Gen 7) requires ~300 steps but saves ∼6 gates and 48 params.  
- Parameter efficiency stabilizes near 0.01 for all perfect classifiers  
  • Reducing from 146→98 params did not improve parameter_efficiency_mean (remains ~0.01), indicating diminishing returns once resource threshold is reached.  
- Generalization gap zeroed by readout calibration across all top designs  
  • Consistent gain+bias layer ensures test_accuracy = train_accuracy = 1.00 in every 1.00-accuracy model.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Tie ansatz‐block parameters across repeats  
   Modify `apply_ansatz_block` so that all repeats share the same parameter slice by forcing `offset = upload_index * N_PARAMS_PER_BLOCK` (i.e. drop the `repeat_index` in its calculation). This collapses the circuit parameters from 98→(16 × 3)+2 = 50, directly testing whether expressivity truly comes from block heterogeneity and pushing parameter efficiency below the current ∼0.01 plateau.  

2. Alternate CRX/CRY nearest‐neighbor entanglers  
   In `ANSATZ_SPEC`, replace every second CRY gate with CRX (e.g. swap `"cry_12"`→`"crx_12"`, `"cry_34"`→`"crx_34"`, etc.) and add the new `"crx_*"` keys to `PARAMETER_KEYS_PER_BLOCK`. Keep the same linear ordering (RY→CR*→RZ) and shared `"rz_final"`. This mixed‐axis chain preserves depth/gate count while introducing orthogonal two‐qubit couplings that may capture correlations missed by pure CRY.  

3. More frequent feature re‐uploads with a shallower block  
   Change `N_UPLOADS = 4` and `N_REPEATS = 1` so the circuit alternates four (feature_map → one ansatz block) rounds instead of three double‐blocks. Retain the existing `ANSATZ_SPEC`. Empirical insights show interleaving data injections drives expressivity, and trading one repeat for an extra upload may speed convergence and reduce over‐stacking.  

4. Insert a sparse long‐range entangler per block  
   Augment each block in `ANSATZ_SPEC` by adding a single `{"gate":"CRZ","wires":[0,4],"param":"crz_04"}` entry immediately before the final RZs (and include `"crz_04"` in the key list). This adds only one two‐qubit gate per block but introduces non-local connectivity shown to boost correlation capture without high overhead, following our successful skip-link pattern.  

5. Learnable feature‐map scaling per upload  
   Replace the constant `FEATURE_SCALE` with a small trainable vector `feature_scales` of length `N_UPLOADS`, and in each upload use `qml.IsingZZ(feature_scales[upload_index] * records[..., k], wires=[a,b])`. This adds only 3 extra parameters and lets the model adjust encoding strength per re-upload—an evidence‐backed enhancement for tighter feature–ansatz synergy.
