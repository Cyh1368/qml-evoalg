# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- CRZ-only entangling blocks with nearest-and-bridge couplings  
 • Generation 8 “enhanced_crz_entanglement” (combined_raw 1.00, 100%/100%/100%, depth 90, gates 222, 98 params, 210 steps) shows that a bank of just CRZ gates on pairs (0-1,2-3,4-5,6-7 plus bridges 1-3,3-5,5-7) delivers maximal expressivity with minimal overhead.  
- Shared final-RZ parameter  
 • Collapsing eight RZ rotations into one key (“rz_final”) via dict.fromkeys (as in Gen 8) cuts 7 params per block without harming convergence or accuracy.  
- Three data-uploads × two ansatz repeats  
 • The N_UPLOADS=3, N_REPEATS=2 layout in Gen 8 attains perfect generalization (gap 0.00) at depth 90, versus deeper variants (e.g. Gen 17 depth 120) with no score gain.  
- Calibrated linear readout (gain + bias)  
 • Present in every zero-gap classifier (Gen 7, 8, 9, 13, 14) and crucial for stabilizing decision thresholds to achieve 100% test accuracy.  

## Ineffective Approaches  
- Over-depth nonlocal entanglers  
 • Gen 17 “nonlocal_cnot_crz_ansatz” (depth 120, gates 252) only combined_raw 0.97—extra CNOT/CRZ layers on distant qubits added depth and gates without accuracy gains.  
- Under-parameterized minimalist chains  
 • Gen 14 “aggressive_parameter_sharing_entangling_layer” (62 params, depth 93) peaked at combined_raw 0.97—pruning below ~90 params sacrifices expressivity.  
- Mixed-axis rings without capacity reduction  
 • Gen 13 “alternating_cry_crx_shared_rz” (104 params, depth 114) matched 100% accuracy but incurred +24 gates and +14 params versus Gen 8, offering no score improvement.  
- Over-parameterized deep ansatzes  
 • Models with ≥146 params (e.g. Gen 4, 6, 11) plateau at combined_raw 0.99–1.00 but parameter efficiency remains ~0.01, indicating wasted resources.  

## Implementation Insights  
- validate_ansatz_spec + dict.fromkeys for key collapsing  
 • Gen 8 uses `ordered_unique_keys = list(dict.fromkeys(parameter_keys))` to merge identical “rz_final” entries, directly reducing N_PARAMS_PER_BLOCK from 23→16.  
- Dynamic key-to-position mapping  
 • The `{key: index}` lookup in `apply_ansatz_block` uncouples gate ordering from parameter layout, making it trivial to add or remove gates in ANSATZ_SPEC without offset bugs.  
- AnnotatedQueue metadata extraction  
 • All top programs (e.g. Gen 8) rely on `qml.queuing.AnnotatedQueue` to auto-compute depth/gate_count, ensuring accurate profiling in head-to-head comparisons.  
- Balanced block sizing  
 • Gen 8’s 16-param block × 6 blocks + 2 readout = 98 params hits the empirically optimal “expressivity plateau” (~100 params) for perfect classification.  

## Performance Analysis  
- Parameter “sweet spot” around 96–104  
 • Gen 7 (98 params) and Gen 8 (98 params) both reach combined_raw 1.00; models above ~100 params add gates/depth without higher scores.  
- Depth vs. convergence trade-off  
 • Gen 8 (depth 90) converges in ~210 steps; Gen 13 (depth 114) converges faster (~150 steps) but at cost of +24 gates and +6 params—no net score gain.  
- Gate count minimum is 222  
 • Both Gen 7 and Gen 8 achieve 222 gates; any reduction below 222 (e.g. Gen 9’s 228 gates at 62 params) correlates with drop to combined_raw 0.98.  
- Zero generalization gap tied to readout calibration  
 • All classifiers with gain+bias readout (Gen 7, 8, 9, 13, 14) report gap = 0.00, confirming its critical role in stable test performance.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Tie block parameters across repeats  
   Modify `apply_ansatz_block` so that you compute `offset = upload_index * N_PARAMS_PER_BLOCK` (i.e. drop the `repeat_index` in the offset calculation). This collapses the six distinct 16-parameter blocks into three shared blocks (N_UPLOADS = 3), reducing circuit parameters from 98→50+2 readout. By testing whether heterogeneity across repeats is necessary for expressivity, you probe the true source of performance gains while cutting parameter count by ~50%.

2. Introduce a single CRX bridge per block  
   In each `ANSATZ_SPEC` block, replace one of the existing bridge CRZ gates—say the middle link on wires [3,5]—with a CRX gate: `{"gate":"CRX","wires":[3,5],"param":"crx_35"}` (and add “crx_35” to the key list). Collapse any duplicate “crx_35” via `dict.fromkeys` so you still only add one extra parameter per block. This mixed-axis coupling injects orthogonal entanglement with minimal overhead, leveraging the success of pure CRZ backbones while exploring additional correlations.

3. Add a sparse long-range CRZ skip link  
   Augment each block in `ANSATZ_SPEC` by inserting `{"gate":"CRZ","wires":[0,4],"param":"crz_04"}` immediately before the final RZs, and include “crz_04” in `PARAMETER_KEYS_PER_BLOCK`. Collapsing duplicates keeps the per-block parameter increase to +1. Empirical patterns show that one well-chosen nonlocal coupling can capture long-distance correlations without blowing up depth or gate count.

4. Swap to 4 uploads and 1 repeat  
   Change the upload/repeat layout to `N_UPLOADS = 4`, `N_REPEATS = 1` while keeping the 16-param CRZ-only block and shared final‐RZ. This alternates four (feature_map → ansatz_block) cycles rather than three double-blocks, interleaving data more frequently. Prior insights suggest that more uploads at shallower depth can speed convergence and avoid over-stacking.

5. Make feature-map scale learnable per upload  
   Replace the scalar `FEATURE_SCALE` with a trainable array `feature_scales` of length `N_UPLOADS`, and in `feature_map` do  
     `qml.IsingZZ(feature_scales[upload_index] * records[..., k], wires=[a, b])`.  
   This adds only 3 parameters (one per upload) plus two readout params, letting the circuit adapt encoding strength on each re-upload. Evidence from calibrated readouts shows that small per-cycle tunable weights can tightly align feature encoding with ansatz expressivity.
