# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Interleaved feature re-uploading with compact variational blocks  
  • 8-Qubit Evolving Ansatz Classifier (Generation 2) achieved perfect 1.00/1.00/1.00 accuracies and combined_score_raw 0.98 using just 98 parameters, depth 93, gate_count 222.  
  • The current best program repeats (feature map → ansatz) 3 × 2 times with 8 RY, a linear CRZ chain, and shared RZ—striking a balance between expressivity and circuit complexity.  
- Linear “chain” of parameterized two-qubit gates  
  • Replacing CZ-only entanglers with CRZ in a nearest-neighbor chain (gen2) matched or exceeded performance of deeper ring/cross-link layouts (gen3), reducing gate count by ∼36% (222 vs. 348) without loss of accuracy.  
- Simple per-qubit rotation layers bookending entanglers  
  • All top performers (gen0, gen1, gen2) begin with RY layers on every qubit and end with RZ layers, ensuring good expressivity with minimal depth.  
- Calibrated linear readout (gain + bias)  
  • Every perfect-accuracy model (gen0, gen1, gen2) incorporated two trainable readout parameters, yielding zero generalization gap and stabilizing predictions across batches.  

## Ineffective Approaches  
- Deep CZ-only entanglement with unparameterized layers  
  • 8-Qubit Layered Quantum Binary Classifier (Generation 5) used only CZ entanglers interleaved with RY/RZ/RX; it attained just 0.84/0.76/0.75 accuracies and a 0.09 generalization gap. The heavy, unparameterized two-qubit blocks failed to capture the decision boundary.  
- Overly symmetric, high-depth ansatzes  
  • 8-Qubit Interleaved Ansatz (Generation 3) reached 1.00/0.99/1.00 accuracies but at depth 132 and gate_count 348, yielding low parameter efficiency (0.01) identical to leaner models—no accuracy gain justified the extra complexity.  
- Excessive parameter repetition per block  
  • The initial linear-chain classifier (gen0) used 24 unique parameters per block (144 total) for a 0.97 score, but Gen 2 halved that to 16 per block (96 total) and improved combined_score_raw to 0.98, showing diminishing returns beyond ∼100 parameters.  

## Implementation Insights  
- Shared-parameter naming to collapse redundant rotations  
  • In the current best program, all final RZ gates use the same “rz_final” key, cutting eight distinct parameters down to one per block without harming model capacity.  
- Dynamic parameter indexing via key-to-position mapping  
  • The `validate_ansatz_spec` → `PARAMETER_KEYS_PER_BLOCK` pipeline and per-block offset arithmetic (`block_index * N_PARAMS_PER_BLOCK`) cleanly scales the ansatz over multiple uploads/repeats.  
- Automated circuit metadata extraction  
  • Using `qml.queuing.AnnotatedQueue` to build a tape and compute `depth` and `gate_count` ensures accurate bookkeeping for performance logging and fair comparisons.  
- Consistent use of Adam backprop with early stopping  
  • All high-performing models employed Pennylane’s AdamOptimizer, minibatch L₂ loss, and validation-based early stopping/patience (∼75), which closed the generalization gap to zero.  

## Performance Analysis  
- Perfect test accuracies achieved by multiple ansatz topologies, but fewer parameters and lower depth accelerate convergence  
  • Gen 1 (ring entangler) converged in ~240 steps, Gen 2 (linear CRZ) in ~390 steps—both reach 1.00 test accuracy and zero gap, yet Gen 2 does so with 222 vs. 270/348 gates and 98 vs. 144/96 parameters, respectively.  
- Parameter efficiency plateau near 0.01–0.02 for all near-perfect models  
  • Despite varying depths (93–132) and parameter totals (98–144), parameter_efficiency_mean remains ~0.01, indicating overparameterization across the board once >90 trainable gates are used.  
- Lower gate count correlates with simpler convergence dynamics without sacrificing accuracy  
  • The shift from CZ-only to CRZ‐augmented chains (depth 93, gate_count 222) did not degrade accuracy but trimmed gate operations by ~20–36%, suggesting lean variational blocks are sufficient for this binary classification task.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Introduce block-level parameter sharing across repeats  
   Modify the training script so that all `apply_ansatz_block` calls use the same set of block parameters instead of distinct ones per upload/repeat. Concretely, set `N_PARAMS_PER_BLOCK` unchanged but define only one block index (e.g. always `offset=0`) in `apply_ansatz_block` and tie all repeats to it. This will collapse total circuit parameters from 98 to 16+2 (readout), testing whether the ansatz’s expressivity truly requires unique parameters per block and pushing parameter‐efficiency below the current ∼0.01 plateau.  

2. Alternate linear CRZ with CRX on every other edge  
   In the existing nearest-neighbor chain, replace every second `{"gate":"CRZ","wires":[i,i+1]}` entry with `{"gate":"CRX","wires":[i,i+1],"param":"crx_i(i+1)"}` (and add the new `crx` keys to `ANSATZ_SPEC`). Keep the same ordering of RY-CR*-RZ and maintain a single shared `rz_final`. This variation preserves gate count/depth while giving the ansatz mixed-axis entanglement, which may capture orthogonal correlations that pure CRZ missed.  

3. Increase feature-reupload frequency with shallower blocks  
   Change `N_UPLOADS` to 4 and `N_REPEATS` to 1, so the pipeline becomes four rounds of (feature map → one ansatz block) instead of three rounds of two repeats. Keep the ANSATZ_SPEC identical. By emphasizing more frequent data re-injections with a compact variational block, you lean into the proven benefit of interleaved uploads while preventing over-deep block stacking.  

4. Add a single long-range CRZ “skip” link with a shared parameter  
   Augment `ANSATZ_SPEC` by inserting, just before the final RZs, one `{"gate":"CRZ","wires":[0,4],"param":"crz_04"}` entry (and include `"crz_04"` in `PARAMETER_KEYS_PER_BLOCK`). This sparse, global entangler introduces non-local connectivity at minimal extra gate cost (one CRZ per block) and can help capture correlations between distant qubits without resorting to a fully connected or high-depth ring.  

5. Make the feature-map scale trainable per upload  
   Replace the fixed `FEATURE_SCALE = π/2` with a small trainable vector `feature_scales = params[:N_UPLOADS]` and, in each `feature_map` call, use `qml.IsingZZ(feature_scales[upload_index] * records[..., k], wires=…)`. Allocate only 3 extra parameters (one per upload), so overall `N_PARAMS` increases by 3. This lets the model learn optimal encoding strengths per re-upload, potentially reducing validation loss further while leveraging the robust feature-map+ansatz interplay seen in top performers.
