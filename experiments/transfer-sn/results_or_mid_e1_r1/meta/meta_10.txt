# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Parity-based parameter sharing with ring-CZ entanglement (Generation 3 “parity_tied_ring,” combined_score_raw = 0.89, train/val/test = 0.92/0.89/0.90, N_PARAMS = 50)  
  • Defines only eight param keys per block (rx_even_pre/odd_pre, ry_even_pre/odd_pre, rx_even_post/odd_post, ry_even_post/odd_post) shared across even/odd wires.  
  • Cuts N_PARAMS by >40% versus prior shared schemes (e.g., Gen 7’s 86 params) without losing accuracy.  
- Two-layer RX/RY rotations → ring-CZ → two-layer RX/RY per ansatz block, repeated over 3 uploads×2 repeats  
  • This structure consistently appears in top performers (Gen 3, Gen 7) and yields stable high expressivity (depth 126, gate_count 324)  
- Feature re-uploading layout (N_UPLOADS = 3, N_REPEATS = 2) remains robust  
  • All top programs retain 3 uploads × 2 repeats—modifying uploads delivered little benefit  
- Trainable gain/bias readout + early stopping  
  • Present in all high scorers (Gen 3, Gen 7, Gen 9), boosting validation/test by ~0.02  

## Ineffective Approaches

- Over-parameterized two-qubit controls and rich long-range gates (Gen 8 “symmetric_brick_longrange,” combined_score_raw = 0.70, gap = 0.11, N_PARAMS = 104)  
  • Added CRY/CRZ layers and circular CNOT ring without sharing harmed generalization  
- Excessive independent rotations (Gen 6 “hybrid_selective_share_ccontrol,” combined_raw = 0.85, gap = 0.05, N_PARAMS = 122)  
  • Depth 91, gate_count 288 but no accuracy gain over leaner ansätze  
- Deep symmetric ring blocks without targeted sharing (Gen 5 analogues, depth ≥ 126)  
  • Drove up gate counts with no test-accuracy improvements; parameter efficiency remained ≲0.01  

## Implementation Insights

- validate_ansatz_spec + key_to_position mapping  
  • Enables concise ANSATZ_SPEC definitions and automatic parameter sharing (e.g., parity sharing in Gen 3)  
- List-of-dict ANSATZ_SPEC is a powerful abstraction  
  • Rapidly swap between per-wire, pairwise, half-block, or parity sharing without rewriting apply_ansatz_block  
- Automated circuit_metadata via qml.tape.QuantumScript  
  • Yields depth/gate_count metrics in-line, guiding complexity vs. accuracy tradeoffs  
- Consistent use of trainable gain/bias and early stopping  
  • Simple readout calibration (2 params) delivers ~0.02 uplift on validation/test accuracy  

## Performance Analysis

- Parameter count vs. combined_score_raw  
  • Gen 3 (50 params) → 0.89, Gen 7 (86 params) → 0.88, Gen 9 (74 params) → 0.86, Gen 6 (122 params) → 0.85  
  • Highest accuracy at lowest N_PARAMS → best parameter efficiency (0.02 vs. ~0.01 for others)  
- Generalization gap  
  • Parity/shared schemes (Gen 3, Gen 7) gap ≈ 0.02; richer unshared schemes (Gen 6, Gen 8) gap ≥ 0.05  
- Convergence cost vs. parameter count  
  • Gen 7 (86 params) converges in ~540 steps; Gen 3 (50 params) ~1,140 steps—tradeoff between rapid training and peak accuracy  
- Depth/gate_count alone are weak predictors  
  • Gen 3 and Gen 8 share depth 126 but differ by 0.19 in combined_score_raw, underscoring the key role of parameter sharing and connectivity patterns

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Replace half of the fixed CZs with parameterized CRZ gates under parity‐based sharing.  For example, in each ring replace CZ on edges [(0,1),(2,3),(4,5),(6,7)] by CRZ gates all using a single key “crz_even,” and replace the other four CZs by CRZs with key “crz_odd.”  This adds only 2 extra params per block but leverages the proven expressivity‐per‐parameter gain seen in Gen 4’s parameterized entanglers while preserving the 40%+ compression of Gen 3.  

2. Insert a shared RZ rotation layer before each RX/RY pre‐layer using parity sharing.  Concretely, prepend to ANSATZ_SPEC each block with  
   {"gate":"RZ","wire":i,"param":i%2==0?"rz_even":"rz_odd"}  
   for i=0…7.  This adds 2 params per block, boosting local expressivity at minimal cost—echoing the small readout‐calibration gains that consistently yielded ~0.02 accuracy improvements.  

3. Alternate between local ring and global “cross” entanglement patterns across blocks.  In blocks with even index keep the standard nearest‐neighbor CZ/CRZ ring; in odd blocks swap to wires [(0,4),(1,5),(2,6),(3,7),(4,0),(5,1),(6,2),(7,3)].  Retain any param‐sharing keys for these entanglers.  This diversity in connectivity, inspired by Gen 4’s alternating long-range tests, may raise expressivity per gate without blowing up parameter count.  

4. Add trainable per‐upload feature scalings to the feature map.  Before calling qml.IsingZZ in feature_map, multiply each record[..., k] by a learnable scalar “feat_gain_u” where u is the upload index (0–2).  This introduces only 3 new parameters and lets the circuit learn to weight input dimensions analogously to the gain/bias trick at readout, potentially improving convergence speed and overall accuracy.  

5. Explore an even leaner rotation block by collapsing four parity‐tied pre‐rotations into two shared axes and mirroring them post‐entanglement.  For instance, use only RX with key “rx_parity” on all qubits in the pre‐layer (parity‐shared) and RY with key “ry_parity” in the post‐layer.  This cuts N_PARAMS_PER_BLOCK from 8→2, freeing a budget for two CRZ keys or the RZ layer above, and tests the limits of parameter efficiency demonstrated by the top parity‐tied circuits.
