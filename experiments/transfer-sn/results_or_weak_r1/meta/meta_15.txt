# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Coarse-grained parameter sharing across qubit groups (wires 0–3 vs 4–7) halved the unique parameters per block (6 vs 12) and delivered the top combined_score_raw = 0.90 in the Shared-parameter Re-uploading Ansatz (Gen 13), with test = 0.89 and gen_gap = 0.00.
- Building on the dual-ring CZ scaffold from prior best (Gen 11 raw = 0.89), G13 retained interleaved ring CZs (4 per ring) but removed all trainable two-qubit gates, boosting parameter efficiency to 0.02 without increasing depth.
- Three feature-uploads × two ansatz repeats (N_UPLOADS = 3, N_REPEATS = 2) consistently hit the sweet-spot depth (99–105) and gate count (≈276–300): G13 (depth 99, gates 276) outperformed deeper (>110) or shallower (<95) variants.
- Uniform use of L2 loss with gain/bias readout calibration plus Adam(0.03) and early stopping (patience = 75) produced zero std in accuracies (train/val/test std = 0.00) and convergence in ≈270 steps for G13.

## Ineffective Approaches

- Over-parameterized ansätze with >100 trainable weights (Gen 9:116 params, raw = 0.86; Gen 10:122 params, raw = 0.85) suffered gen_gaps ≈0.09, modest test ≤ 0.88, and parameter efficiency = 0.01.
- Adding parameterized two-qubit rotations (CRZ/CRX) layers increased depth (>111) and gate count (>348) without improving test accuracy (max raw = 0.86 for Gen 9).
- Mid-level sharing designs (~74 params in Gen 12 & Gen 15) achieved zero or low gen_gap but plateaued combined_score_raw at 0.87–0.89 and efficiency = 0.01, indicating limited expressivity per parameter.
- Circuits deeper than ~105 layers (e.g. Gen 9 depth 117) underperformed simpler-depth designs, confirming a narrow optimal depth corridor.

## Implementation Insights

- The validate_ansatz_spec → PARAMETER_KEYS_PER_BLOCK pipeline enforces a deterministic key order and offset indexing, simplifying repeated block application in apply_ansatz_block.
- Defining ANSATZ_SPEC with shared “ry_h”/“ry_h2” and “rz_pre_h”/“rz_pre_h2” keys lets the same spec drive multiple wires—coarse grouping requires only 2 lines of param definition per group yet cuts unique parameters in half.
- apply_ansatz_block’s use of a key_to_position map and block_index × N_PARAMS_PER_BLOCK offset supports arbitrary N_UPLOADS×N_REPEATS layouts without manual slicing, enabling easy re-uploading and repetition.
- Leveraging only fixed-feature IsingZZ mappings plus CZ entanglers decouples two-qubit trainable gates from the architecture, reducing code complexity and focusing expressivity into single-qubit rotations.

## Performance Analysis

- Combined_score_raw increased monotonically as N_PARAMS dropped from 122→116→74→38: Gen 10(0.85) < Gen 12(0.87) < Gen 15(0.89) < Gen 13(0.90), highlighting leaner ansätze.
- Zero generalization gap occurred only in models with strong sharing or coarse grouping: Gen 15 (74 params) and Gen 13 (38 params) both achieved gen_gap = 0.00, while richer models had gaps ≥0.05.
- Optimal depth/gate count lies in [95–105] layers and [270–300] gates: G13 at (99, 276) led the pack, whereas depths >110 (G9/G10) correlated with lower raw scores.
- Parameter efficiency (test_accuracy / N_PARAMS) doubled from ~0.01 in most designs to 0.02 in G13, underscoring the value of aggressive sharing plus re-uploading for expressivity per weight.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Merge the pre- and post-RZ parameters into a single coarse-grained RZ per half. In your ANSATZ_SPEC, replace both “rz_pre_h”/“rz_post_h” with one key “rz_h” (and likewise “rz_pre_h2”/“rz_post_h2”→“rz_h2”), applied at both positions. This cuts N_PARAMS_PER_BLOCK from 6→4 (total N_PARAMS→26) and tests whether a single Z-axis adjustment per group suffices, building on the fact that aggressive sharing drove Gen 13’s success.

2. Add two trainable feature-scale parameters to the fixed feature map. In feature_map, multiply FEATURE_SCALE by a learnable “fs_h” for feature pairs on qubits 0–3 and “fs_h2” for 4–7 before calling qml.IsingZZ. This introduces only 2 extra parameters and probes whether letting the model optimize the encoding strength per half-block boosts expressivity without deepening the circuit.

3. Introduce a shared-parameter RX rotation after each RY stage. Extend ANSATZ_SPEC by inserting 8 RX gates—wires 0–3 using “rx_h” and wires 4–7 using “rx_h2”—immediately after the existing RY layers. This adds just 2 new parameters per block and tests orthogonal rotation axes’ impact, leveraging the high efficiency of coarse-grouped single-qubit rotations seen in Gen 13.

4. Inject minimal cross-group entanglement via shared CRZ chords. After the two interleaved CZ rings in each block, append four CRZ gates connecting qubits [3,4], [2,5], [1,6], [0,7] all sharing a single “phi_cross” key. This lightweight entangler introduces one extra parameter per block and explores whether adding tunable cross-half coupling further enhances expressivity without bloating depth.

5. Hierarchically share parameters across repeats within each upload. Redefine your parameter keys to include an upload index (e.g. “ry_h_u0” for both repeats in upload 0, “ry_h_u1” for upload 1, etc.), so that the same set of 4–6 keys drives all N_REPEATS blocks per upload. This reduces total circuit parameters by ≈1/3 relative to fully distinct per-block keys, testing if higher-level sharing preserves the zero generalization gap observed in coarse-grouped designs.
