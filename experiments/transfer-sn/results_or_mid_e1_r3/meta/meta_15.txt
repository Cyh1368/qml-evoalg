# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Fully shared rotational layers combined with shared-CRZ entanglers on alternating diagonal/shifted qubit pairs.  
  • Example: “8-Qubit Shared-Parameter Ansatz Classifier” (Gen 9) uses 5 parameters per block (ry_0, crz_0, rz_0, crz_1, ry_1), repeated over 3 uploads×2 repeats, and achieves combined_score_raw = 0.92, test_accuracy = 0.93, generalization_gap = 0.00, depth = 87, gate_count = 276.  
- Three IsingZZ feature-map re-uploads interleaved with two ansatz repeats.  
  • Present in all top performers (Gen 9, Gen 13) to enrich the nonlinear embedding without overfitting, yielding train/validation/test accuracies ≈ 0.93.  
- Trainable output gain and bias calibration.  
  • Included in Gen 9 (combined = 0.92), Gen 11 (combined = 0.89), and Gen 13 (combined = 0.89), consistently tightening the train/test gap to ≤ 0.02.  
- Parameter sharing to compress each block to 5 parameters.  
  • Enables high parameter efficiency (~0.03) and expressivity: low-param blocks outperform unfactored designs with 122–146 params (which scored ≤ 0.84).  

## Ineffective Approaches  
- Excessive circuit depth (> 90) or gate count (> 300) without focused sharing.  
  • “8-Qubit Binary Classifier with IsingZZ Encoding” (Gen 10) had depth ≈ 129, gates ≈ 300, combined = 0.88.  
  • “CZ-Ring Layered” (Gen 11) used depth = 120 but only reached combined = 0.89.  
- Parity-split CRY mixing with 38 parameters.  
  • “8-Qubit Parity-Split CRY Ansatz” (Gen 14) scored combined = 0.88 and generalization_gap = 0.04, indicating that unfocused two-qubit patterns dilute parameter utility.  
- Mixing multiple two-qubit gates (CRX/CRY/CNOT/CZ) without strict sharing.  
  • Gen 6 and Gen 7 designs with 122–146 params and depth > 90 had generalization_gaps 0.07–0.08 and combined scores ≤ 0.85.  
- High gate-count CRZ rings without depth matching.  
  • “Multi-Upload CRZ Ring” (Gen 12) had gate_count = 324 but combined = 0.88, showing that more entanglers alone don’t boost performance.  

## Implementation Insights  
- Organize ANSATZ_SPEC as a list of gate dictionaries and validate via `validate_ansatz_spec()`.  
  • Ensures correctness before building the key‐to‐position map and computing offsets for shared parameters.  
- Compute block offsets via  
    offset = block_index × N_PARAMS_PER_BLOCK  
    key_to_position = {key: idx for idx, key in enumerate(PARAMETER_KEYS_PER_BLOCK)}  
  • Simplifies applying the same 5 parameters across each of the 6 ansatz blocks in `apply_ansatz_block()`.  
- Define exactly five shared parameters per block (`ry_0, crz_0, rz_0, crz_1, ry_1`), applied across all qubits.  
  • Enforces global coherence and reduces parameter dimensionality from ~30/block to 5/block.  
- Implement trainable readout calibration in `predict_batch()` as  
    raw = mean(Z-expectations)  
    output = gain * (raw – bias)  
  • Stabilizes training by rescaling model outputs and centering predictions.  

## Performance Analysis  
- Best combined_score_raw = 0.92 (Gen 9) aligns with depth = 87 and gate_count = 276.  
  • No other circuit in the 87–93 depth range surpassed combined = 0.89.  
- 32-parameter designs can reach test_accuracy = 0.93 when entanglement is structured and shared.  
  • Gen 13 (8-Qubit IsingZZ Ansatz) also uses 32 params and depth = 87 but scores combined = 0.89 with gap = 0.02.  
- Parameter efficiency (~test_accuracy / n_params) peaks at ~0.03 for Gen 9, Gen 10, Gen 13, but only Gen 9 translates that into the highest overall score.  
- Zero generalization gap achieved only by the fully shared CRZ ansatz.  
  • Other shared-parameter circuits (Gen 11 gap = 0.01; Gen 13 gap = 0.02) confirm that the exact CRZ alternating pattern is key to overfitting control.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Append a static CZ “ring” entanglement at the end of each ansatz block  
   After the final RY layer in ANSATZ_SPEC, inject CZ gates on wires (0,1), (1,2), …, (7,0). This costs no extra parameters, exploits CZ’s proven role in spreading correlations, and should boost expressivity while keeping depth in the 87–93 sweet-spot.  

2. Introduce upload-specific CRZ parameters for richer interleaved coupling  
   Rename “crz_0” and “crz_1” to “crz_0_u{k}” and “crz_1_u{k}” for k∈{0,1,2}, adding just 6 parameters (2 per upload). This preserves the alternating diagonal/shifted pattern that drove Gen 9’s zero generalization gap while giving the circuit flexibility to adjust entangling strength at each re-upload stage.  

3. Diversify single-qubit rotation axes with minimal overhead  
   Change the first shared RY layer to a shared RX (“rx_init”) and the final RY layer to a shared RX (“rx_final”), adding only 2 new parameters. Axis mixing (RX–RZ–RX) has been shown to increase expressivity in low-param designs without sacrificing the global coherence that underpins the current best program’s perfect generalization.  

4. Explore a denser re-upload pattern by trading repeats for uploads  
   Set N_UPLOADS=4 and N_REPEATS=1 so you still deploy four ansatz blocks but interleave four feature embeddings instead of three. This maintains the total block count (≈ 4) and depth (~90) while testing whether a more frequent nonlinear embedding further raises the combined score.  

5. Make the feature-map scale trainable per upload stage  
   Replace the fixed FEATURE_SCALE constant with a small vector of learnable parameters [scale_0, scale_1, scale_2] (one per upload). In feature_map(), use qml.IsingZZ(scale_upload * records[..., k], wires=[a, b]). This adds only 3 parameters and lets the circuit tune embedding strength at each IsingZZ re-upload, potentially reducing validation loss and tightening generalization.
