<DESCRIPTION>
The current circuit achieves excellent performance (93% test accuracy, 0.00 generalization gap) with only 32 parameters, but there is room for improvement through upload-specific entanglement tuning.

**Rationale:**
The data re-uploading architecture applies 3 feature uploads, each followed by 2 ansatz repetitions. Currently, the CRZ entanglement parameters ("crz_0" and "crz_1") are shared across all blocks. However, the quantum state evolves differently at each upload stage—after the first upload, the state carries residual information from previous gates, which could benefit from upload-stage-specific tuning of the entanglement strength.

**Key insight:**
By introducing upload-specific CRZ parameters (crz_0_upload0, crz_0_upload1, crz_0_upload2, crz_1_upload0, crz_1_upload1, crz_1_upload2), we allow each upload stage to learn its optimal entanglement coupling independently. This adds only 6 parameters (2 per upload stage) but enables the circuit to adapt the entanglement pattern to the state after fresh feature information is injected.

**Implementation strategy:**
Since the ANSATZ_SPEC is applied once per block, we can introduce multiple "virtual" copies with upload-specific parameter names in the spec template. By encoding the upload index into parameter names, the underlying framework (which allocates parameters by block_index × N_PARAMS_PER_BLOCK) naturally accommodates this without requiring external modifications—each block will pick its corresponding upload-stage parameter from the offset.

This approach:
- Adds 6 parameters (modest increase from 32 → 38)
- Reduces wasteful sharing (different uploads should use different coupling values)
- Maintains the block-based parameter indexing structure
- Expected to reduce the gap between training and test performance even further, potentially pushing accuracy closer to 1.0
- Follows the principle of per-upload expressiveness already used in the feature re-uploading scheme

def _build_ansatz_with_upload_crz(upload_index):
    """Construct ansatz block with upload-specific CRZ parameters."""
    block = list(_ANSATZ_BLOCK_TEMPLATE)
    crz_0_param = f"crz_0_upload{upload_index}"
    crz_1_param = f"crz_1_upload{upload_index}"
    
    # Insert first entanglement layer (diagonal pairs) after RY
    entangle_1 = [
        {"gate": "CRZ", "wires": [0, 1], "param": crz_0_param},
        {"gate": "CRZ", "wires": [2, 3], "param": crz_0_param},
        {"gate": "CRZ", "wires": [4, 5], "param": crz_0_param},
        {"gate": "CRZ", "wires": [6, 7], "param": crz_0_param},
    ]
    # Insert second entanglement layer (shifted pairs) after RZ
    entangle_2 = [
        {"gate": "CRZ", "wires": [1, 2], "param": crz_1_param},
        {"gate": "CRZ", "wires": [3, 4], "param": crz_1_param},
        {"gate": "CRZ", "wires": [5, 6], "param": crz_1_param},
        {"gate": "CRZ", "wires": [7, 0], "param": crz_1_param},
    ]
    return block[:8] + entangle_1 + block[8:16] + entangle_2 + block[16:]
