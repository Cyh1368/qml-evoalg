# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Collective single-qubit rotations with shared parameters plus dense CZ entanglement  
  – Program “8-Qubit Binary Classifier with Collective Rotation Ansatz” achieved a combined raw score of 0.93 (train/val/test = 0.96/0.95/0.94), generalization gap 0.02, and parameter efficiency 0.05 using only 20 trainable angles.  
- Dense (near-complete-graph) CZ connectivity outperforms sparse chains or rings  
  – The collective-rotation ansatz uses 36 CZ gates across all qubit pairs, surpassing the ring-CNOT architectures (combined scores 0.70 and 0.83) and layered RY/RZ/CZ (0.85).  
- Parameter sharing dramatically reduces over-parameterization  
  – Sharing three parameters per block (collective_ry, collective_rz, collective_rx) yields excellent expressivity with N_PARAMS = 20, versus 98–146 parameters in other models.  
- Fewer parameters accelerate convergence  
  – Collective-rotation ansatz converged in ~150 optimizer steps, compared to 540–750 steps for high-parameter variants (e.g. multi-upload dense CZ, layered RY/RZ/CZ).  

## Ineffective Approaches

- Over-parameterized layered rotations with many angles  
  – The 146-parameter “8-Qubit RY-RZ-CZ Layered Ansatz” scored 0.85 combined, but parameter efficiency was only 0.01 and generalization gap was 0.07, indicating overfitting and low return per parameter.  
- CNOT-only ring entanglement limits expressivity  
  – The “Layered RX/RY-CNOT Ansatz” (98 parameters, depth 81) achieved just 0.70–0.73 test accuracy with a generalization gap of 0.10.  
- Simple IsingZZ ansatz with CNOT entanglers underperforms  
  – The “8-Qubit IsingZZ Ansatz Classifier” scored 0.59 combined with a 0.15 generalization gap despite 96 circuit parameters, showing that adding gates without richer rotations fails to boost accuracy.  
- Dense CZ plus many single-qubit parameters still overfits  
  – The “Multi-Upload CZ Entanglement Ansatz” (146 parameters) achieved 0.83 combined but gap 0.06 and efficiency 0.01, underscoring that dense entanglement alone isn’t enough without parameter sharing.  

## Implementation Insights

- Ansatz specification via shared parameter keys simplifies parameter management  
  – Defining collective_ry/rz/rx in ANSATZ_SPEC yields N_PARAMS_PER_BLOCK = 3, collapsed across N_UPLOADS×N_REPEATS to 18 circuit angles plus gain/bias.  
- Use of Pennylane’s AnnotatedQueue for accurate depth/gate counting  
  – circuit_metadata reports depth 117 and gate_count 396 for the collective-rotation model, enabling precise architecture profiling.  
- Mean-of-PauliZ outputs with trainable gain/bias is robust across architectures  
  – All programs calibrate final prediction as gain×(mean Z – bias), but pairing this with a low-parameter ansatz delivered the best loss/accuracy trade-off in the collective design.  
- Early stopping on validation-loss with a small parameter set preserves generalization  
  – The best program restored weights at minimal validation loss, avoiding overfitting despite a moderately deep circuit.  

## Performance Analysis

- Dense CZ + collective rotations vs. layered RY/RZ/CZ  
  – Collective ansatz: combined 0.93; layered RY/RZ/CZ: combined 0.85 (Δ +0.08)  
- Parameter efficiency correlation  
  – Best program efficiency 0.05 vs. others all at 0.01, showing strong link between parameter sharing and return per parameter.  
- Generalization gap trends  
  – Collective ansatz gap 0.02; multi-upload CZ gap 0.06; layered RY/RZ/CZ gap 0.07; IsingZZ ansatz gap 0.15—denser parameter sharing yields tighter generalization.  
- Convergence speed vs. parameter count  
  – Collective design: ~150 steps to reach accuracy threshold; richer-parameter models require 3–5× more steps, illustrating benefit of compact parameterization.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Introduce qubit-specific offset parameters to the collective rotations. Keep the three block-level shared angles (collective_ry, _rz, _rx) but add one trainable “offset_i” per qubit that applies across all blocks (i.e. RY(angle + offset_i) on qubit i). This hybrid maintains the low parameter count while giving each qubit light local flexibility and may capture residual asymmetries missed by a fully collective ansatz.

2. Replace a subset of fixed CZ gates with a shared-parameter CRZ entangler. For example, swap every other CZ in the dense pattern for CRZ(shared_crz) and share that single parameter across all such edges per block. This adds richer, tunable two-qubit interactions without blowing up the parameter count and builds on the success of dense entanglement plus sharing.

3. Enforce cross-block parameter sharing for the collective angles. Instead of fresh collective_ry/_rz/_rx in each of the N_UPLOADS×N_REPEATS blocks, use the same three parameters across all blocks (N_PARAMS_PER_BLOCK = 3 total). This radical sharing could further improve generalization and convergence speed by collapsing N_CIRCUIT_PARAMS from 18 to 3, testing the lower bound of expressivity.

4. Interleave rotations and entanglers within each block. Redefine each ansatz block as [collective_rx → CZ layer → collective_rz → CZ layer → collective_ry] rather than grouping all rotations before/after entanglement. Evidence from layered RY/RZ/CZ patterns suggests that alternating rotations and entanglers can boost expressivity; here, parameter sharing preserves efficiency.

5. Rebalance feature-reupload depth versus ansatz repeats. Keep total blocks constant but test N_UPLOADS = 4, N_REPEATS = 1 (vs. 3×2) so features are re-encoded more often with shallower ansatz layers each time. This explores the trade-off between feature injection frequency and variational depth, leveraging the observed benefits of reuploading with minimal new parameters.
