# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Linear CZ entangler chains interleaved with pre- and post-RZ single-qubit rotations (Seed: “8-Qubit Layered Ansatz Binary Classifier”) achieved a strong fit (train/val/test = 94/89/87%) and raw score 0.85 with moderate depth (99) and gate count (270).  
- Hybrid mixtures of RX/RY/RZ rotations plus both CZ and parameterized CRY entanglers (Gen 5: “8-Qubit Hybrid Quantum Classifier”) matched the seed’s raw score (0.85) while nudging validation/test accuracy to 90/88% and narrowing the generalization gap to 6%, at depth 105, gate count 318.  
- Strategic parameter reuse across repeated layers (Gen 2: “8-Qubit CRY-RY Ansatz Classifier”) cut circuit parameters from 146→74, depth from 99→75, and gate count from 270→204, while maintaining raw score 0.82 and shrinking the gap to 4% (train/val/test = 92/88/88%).  
- Moderate circuit depth (75–105) with 120–220 parameters consistently delivered test accuracy ≥ 0.88, demonstrating that carefully balanced expressivity (rather than maximal parameter count) underpins best generalization.  

## Ineffective Approaches

- Deep, heavily parameterized star-ring entanglers with circular CNOT rings plus star-shaped CRY gates (Gen 1: “8-Qubit Circular RY-CNOT-RZ-CRY”) ballooned depth to 120 and gate count to 252, but collapsed validation/test to 67/69% (combined score –2.43) and a 15% generalization gap—clear overfitting.  
- Excessive depth/gate counts (≥ 300 gates in Gen 3 and Gen 5) offered only marginal accuracy gains while keeping parameter efficiency at 0.01, indicating diminishing returns from added entanglement complexity.  
- Custom cross-CNOT links layered into deep IsingZZ blocks (Gen 3: “8-Qubit IsingZZ Classifier”) yielded stable but lower test accuracy (82%) and raw score 0.84, suggesting complex entanglement topologies do not inherently boost generalization.  
- Simply increasing the number of repeats or uploading rounds without pruning depth or reusing parameters failed to reduce the generalization gap below ~6–7%.  

## Implementation Insights

- Encoding ANSATZ_SPEC as a list of gate-dicts with a centralized parameter-key ordering facilitates both dynamic circuit construction (apply_ansatz_block) and straightforward extraction of N_PARAMS_PER_BLOCK.  
- The use of qml.queuing.AnnotatedQueue plus QuantumScript metadata yields accurate circuit depth and gate-count metrics, essential for correlating topology to performance.  
- The seed’s balanced layout—3 feature-map uploads × 2 ansatz repeats, each with 16 single-qubit rotations and 7 CZ gates—achieves depth 99/gate count 270 and underpins its 87% test accuracy.  
- Implementing parameter reuse (mapping PARAMETER_KEYS_PER_BLOCK → offset indices) as in Gen 2 can halve circuit parameters while preserving expressivity, directly improving generalization gap.  

## Performance Analysis

- Depth vs. gap: reducing depth from 99 (seed, gap 7%) to 75 (Gen 2, gap 4%) corresponded with only a 2-point drop in raw score (0.85→0.82).  
- Parameter count vs. test accuracy: Gen 5’s 220+ parameters achieved test 88%, matching 74-parameter Gen 2, highlighting that smart reuse trumps sheer parameter volume.  
- Gate-count sweet spot: circuits with 200–270 gates (seed, Gen 2) consistently hit test 87–88% vs. >300 gates in Gen 5 only improving test by 1%.  
- Generalization gap floors near 3–4% when both depth and parameters are moderated—circuits deeper than ~100 layers tend to plateau or worsen gap.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Implement parameter tying across all ansatz blocks as in Gen 2 to halve the total circuit parameters. Concretely, collapse the block‐specific offsets in `apply_ansatz_block` so that each upload/repeat uses the same `ry_*`, `rz_pre_*`, and `rz_post_*` keys, reducing `N_PARAMS_PER_BLOCK` by reusing them globally. This should lower depth to ~75 and gate count to ~204 while preserving ≈0.82 raw score and shrinking the generalization gap toward 4%.

2. Introduce a small number of parameterized CRY entanglers interleaved with the CZ chain—e.g. after the existing CZ gates insert  
   `{"gate":"CRY","wires":[0,1],"param":"cry_0"}` and  
   `{"gate":"CRY","wires":[2,3],"param":"cry_1"}`  
   in each block. This hybrid CZ+CRY pattern, inspired by Gen 5, can nudge validation/test accuracy toward 90% without pushing depth beyond ~110 or gate count past ~318.

3. Diversify single‐qubit rotations by mixing RX and RY on the pre‐entanglement layer: replace every other `{"gate":"RY","wire":i}` with `{"gate":"RX","wire":i}` for qubits 0,2,4,6. Keep the 8 RZ pre/post rotations unchanged. This axis mixing boosts expressivity at minimal parameter cost, echoing the seed’s balanced layout while avoiding over‐parameterization.

4. Explore reducing the number of data uploads: set `N_UPLOADS=2` while keeping `N_REPEATS=2`. This change cuts the total depth to ≈66–75 and gate count to ≈180–200, targeting the depth–gap sweet spot identified (depth ~75 → gap ~4%) without altering the core ansatz structure.

5. Alternate entangling topologies between repeats to enrich connectivity without greatly increasing gates: in even `block_index` use the current linear CZ chain (pairs [0,1]→[6,7]); in odd `block_index` apply a “ladder” pattern—CZ on [0,1],[2,3],[4,5],[6,7] in one set and on [1,2],[3,4],[5,6],[7,0] in the next. This two‐pattern approach retains gate count ~270 but injects more balanced entanglement, leveraging moderate complexity that previously improved generalization.
