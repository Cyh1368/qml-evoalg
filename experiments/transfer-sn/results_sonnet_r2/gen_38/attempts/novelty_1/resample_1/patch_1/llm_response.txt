share_block_params_across_repeats

<DESCRIPTION>
Building on the parameter-sharing trend seen in prior improvements (independent RY→shared RY, independent RZ pre/post→shared), this edit applies the recommended architectural change: share ansatz block parameters across the two repeats within each upload by computing `offset = upload_index * N_PARAMS_PER_BLOCK` instead of `block_index * N_PARAMS_PER_BLOCK`. This halves circuit parameters (43 params/upload → 43*3=129 total minus readout, actually with current spec N_PARAMS_PER_BLOCK=14, so previously 14*6=84 circuit params, now 14*3=42 circuit params + 2 readout = 44 total), testing whether stronger weight tying further reduces the generalization gap while retaining expressivity through the 3 independent data-reuploading stages. This is consistent with the trend from the seed (110 params, gap 0.06) to the current best (86 params, gap 0.03) — fewer, better-shared parameters seem to improve generalization. Halving parameters again should continue this trend and may also speed convergence since there are fewer parameters to fit with the same effective circuit depth (depth and gate count remain unchanged since gate structure doesn't change, only parameter reuse).
