tie_params_across_uploads

<DESCRIPTION>
Currently N_CIRCUIT_PARAMS = N_PARAMS_PER_BLOCK * N_UPLOADS * N_REPEATS, giving each of the 6 blocks (3 uploads × 2 repeats) its own independent parameter set. This gives many parameters (170 total) but risks overfitting to the training data re-encoding pattern rather than learning a generalizable transformation, and slows convergence since gradients must be learned separately for each upload stage.

Weight sharing across uploads is a well-known regularization technique in data re-uploading circuits (analogous to recurrent weight sharing in classical sequence models): if the same transformation is meant to be applied after each re-upload of the same feature map, tying the ansatz block parameters across uploads reduces the effective parameter count by 3x (from 6 independent blocks to 2 shared ones), which should reduce the generalization gap and can also speed up/improve convergence because the optimizer has a smaller, better-conditioned parameter space to search over.

I implement this by changing how `apply_ansatz_block` computes its parameter offset: instead of using the full `block_index` (which ranges over all N_UPLOADS * N_REPEATS calls), we now use `block_index % N_REPEATS`, so that the same repeat's parameters are shared across all 3 uploads. This reduces N_CIRCUIT_PARAMS by a factor of N_UPLOADS (from 6 blocks worth to 2 blocks worth), while keeping the qualitative structure of applying p=2 repeats of the ansatz block after each upload.
