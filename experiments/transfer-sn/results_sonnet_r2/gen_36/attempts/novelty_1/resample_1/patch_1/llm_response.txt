share_block_params_across_repeats

<DESCRIPTION>
The current model has a 0.07 train-test generalization gap with 116 params, indicating overfitting. The recommendation suggests tying parameters across the two repeats within each upload (using `upload_index * N_PARAMS_PER_BLOCK` instead of `block_index * N_PARAMS_PER_BLOCK`), which halves the effective circuit parameter count (from 114 to 57 circuit params + 2 readout = 59 total) while keeping the same circuit depth/expressivity (repeats still apply the block twice, adding nonlinearity via repeated non-commuting rotations, but now reusing the same angles). This should reduce overfitting (smaller gap) and parameter count, at the cost of some capacity — testing whether this improves the combined score given train_accuracy is far above validation/test accuracy in the current candidate. This changes only the offset computation used in `apply_ansatz_block` and `circuit_z_expectations`/`circuit_metadata`, so N_CIRCUIT_PARAMS must also be updated to reflect only N_UPLOADS copies instead of N_UPLOADS*N_REPEATS copies.
