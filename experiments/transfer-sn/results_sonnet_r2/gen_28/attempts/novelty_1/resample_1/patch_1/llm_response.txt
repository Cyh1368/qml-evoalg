share_block_params_across_repeats

<DESCRIPTION>
The current apply_ansatz_block indexes parameters using a global block_index (0..5) times N_PARAMS_PER_BLOCK, giving each of the 6 blocks (3 uploads x 2 repeats) fully independent parameters. This is parameter-heavy (28 params/block x 6 = 168 circuit params) and likely contributes to overfitting (train 0.94 vs test 0.87, gap 0.08).

Recommendation applied: tie the two repeats within each upload to share the same parameter vector, changing the effective per-upload parameter count while keeping the block structure (RY/RZ pre-rotation, CRZ/CZ entangling ring, RZ post-rotation) unchanged. This is implemented by changing the offset calculation in `apply_ansatz_block` from `block_index * N_PARAMS_PER_BLOCK` to `(block_index // N_REPEATS) * N_PARAMS_PER_BLOCK`, and correspondingly reducing `N_CIRCUIT_PARAMS` from `N_PARAMS_PER_BLOCK * N_UPLOADS * N_REPEATS` to `N_PARAMS_PER_BLOCK * N_UPLOADS`.

This halves circuit parameters (168 -> 84, total with readout 170 -> 86), which should reduce the generalization gap and improve parameter efficiency, while still allowing the two repeats per upload to build up additional entangling depth (since gates are applied twice with the same angles, e.g., a repeated CRZ ring effectively doubles the entangling frequency deterministically). This directly matches the given potential recommendation and is expected to tighten train/test gap without losing expressivity substantially, since re-uploading structure (l=3) still provides ample capacity.
