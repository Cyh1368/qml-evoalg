reduce_repeated_block_params_via_wire_reuse

<DESCRIPTION>
Since I cannot modify the fixed offset logic outside the EVOLVE-BLOCK (it uses `block_index * N_PARAMS_PER_BLOCK`, not something I can edit), I instead achieve an equivalent effect—reducing overfitting by shrinking the effective free-parameter count per block—directly within the ANSATZ_SPEC. I reuse the same parameter names for the pre-rotation and post-rotation RZ layers across qubit pairs (halving unique RZ parameters from 8+8=16 down to 4+4=8), and reuse CRZ parameters across the ring (2 unique instead of 4). This cuts N_PARAMS_PER_BLOCK substantially (from 28 to 16 per block), so total circuit parameters drop from 168 to 96 (plus 2 readout = 98), directly reducing the train/test generalization gap and improving parameter efficiency, while preserving the same gate structure/depth/connectivity (same op count, same entangling ring topology). This tests whether tighter intra-block parameter sharing (analogous to sharing across repeats) yields the same generalization benefit through a route compatible with the editable region.
