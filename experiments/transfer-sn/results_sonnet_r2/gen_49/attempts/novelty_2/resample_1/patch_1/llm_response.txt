distance2_ring_dropout

<DESCRIPTION>
The current best ansatz uses a dual-ring (distance-1 and distance-2 CRZ) entangling layer per block, applied p=2 times per upload for l=3 uploads (98 params, generalization gap 0.05). To further reduce overfitting/generalization gap without adding parameters or gates, I introduce a lightweight stochastic "entanglement dropout" mechanism: the distance-2 (next-nearest-neighbor) ring is randomly skipped during training with probability p_drop (e.g. 0.15) per forward pass, while always being applied at evaluation time. This is implemented via a module-level TRAINING flag that the training loop toggles, and a per-call Bernoulli draw inside `apply_ansatz_block` gating the distance-2 CRZ gates (identified by their param names crz_c/crz_d). This regularizes the reliance on long-range entanglement, encouraging the nearest-neighbor ring to carry more of the classification signal robustly, which should narrow the train-test gap while leaving the parameter count and evaluation-time expressivity unchanged.

Since we cannot modify the fixed training loop, we implement this by making `apply_ansatz_block` itself stochastic based on a global flag that this evolve block controls, defaulting False (i.e., always apply, matching current behavior) unless explicitly toggled. To keep changes self-contained within the EVOLVE-BLOCK and not touch the fixed training loop, we set the flag via an environment variable read once at import time, with the drop being applied inside `apply_ansatz_block` for the distance-2 ring gates only, using a fresh random draw per block invocation drawn from a local RNG seeded from the current global step counter maintained by an internal counter incremented each call. This keeps determinism reasonable for reproducibility across runs while still providing stochastic regularization during training.
