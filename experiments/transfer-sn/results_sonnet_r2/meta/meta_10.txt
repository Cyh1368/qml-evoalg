# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns
- Chain-of-CZ entanglement with sandwiching single-qubit rotations  
  – The current best classifier (146 params, depth 99, gate_count 270) interleaves per-qubit RY→RZ pre-rotations, a linear CZ chain, then RZ post-rotations in each block and achieves a combined score of 0.85 (train 0.94/val 0.89/test 0.87, gap 0.07).  
- Fixed IsingZZ feature-map re-uploads  
  – All top-scoring circuits (combined ≥ 0.85) including the best program and the 8-qubit reuploading variational classifier (170 params, depth 120, combined 0.85) use three uploads of a fixed two-qubit IsingZZ map interleaved with variational blocks, striking a balance between expressivity and overfitting.  
- Output gain/bias calibration  
  – Trainable gain and bias at the readout stage, present in the best program and in other high-scoring variants (e.g., Gen 5), stabilizes decision thresholds and helps maintain a low generalization gap (~0.07–0.08).  
- Moderate depth/parameter budget “sweet spot”  
  – The best model’s 99-layer circuit with 146 parameters outperforms deeper (≥ 114) or higher-param (≥ 170) architectures in combined score, demonstrating that controlled complexity yields more robust generalization than simply adding layers or parameters.  

## Ineffective Approaches
- Over-parameterized ansätze without pruning  
  – The 8-qubit reuploading variational classifier (Gen 3/5) with 170 params and 276 gates matches the best program’s combined score (0.85) but incurs a larger generalization gap (0.08 vs. 0.07) and lower parameter efficiency.  
- Replacing CZ with trainable two-qubit rotations (CRX/CRZ)  
  – The “Trainable CRZ Ring Ansatz” (206 params, depth 124) slightly improves raw test accuracy (0.89) but drops combined score to 0.78, indicating that extra entangling parameters increase circuit depth and hurt overall performance.  
- Closed-ring CNOT entanglement  
  – The 8-Qubit Closed-Ring RY-RZ-RX classifier (146 params, combined 0.69) shows that richer connectivity alone cannot compensate for the loss of the simple CZ-chain structure, leading to lower accuracy and efficiency.  
- Shared-parameter long-range skips  
  – The Fixed CZ-Ring with Shared CRZ Skip Ansatz (152 params, combined 0.77) kept parameter count modest but failed to surpass the 0.90 validation threshold, suggesting that over-constraining expressivity limits performance.  

## Implementation Insights
- Strict ANSATZ_SPEC validation and deterministic parameter ordering  
  – The best program’s zero SPEC_ERRORS and clearly ordered PARAMETER_KEYS_PER_BLOCK enable error-free validation and simplify `apply_ansatz_block`, preventing misaligned gate–parameter mappings.  
- Early-stopping with restore-best-weights  
  – Validation-loss patience (75 steps) and weight restoration prevented overfitting, directly contributing to the low generalization gap (0.07) of the best classifier.  
- Batched expectation evaluations via autograd backprop  
  – Using `qml.qnode(..., diff_method="backprop")` and stacking Z-expectations across 8 qubits yields stable gradients (std ≈ 0.00) and smooth convergence (~750 steps) in the best model.  
- Parameter-offset indexing for block reuse  
  – Computing `offset = block_index * N_PARAMS_PER_BLOCK` with a pre-built key→index map minimizes Python overhead inside loops and ensures correct parameter assignment across repeated blocks.  

## Performance Analysis
- Combined score vs. circuit complexity  
  – The best model (146 params, depth 99) achieves 0.85 combined, outperforming both the 170-param/120-depth variants (Gen 3/5, combined 0.85) in efficiency and the 206-param CRZ ring (combined 0.78) in overall score.  
- Test‐accuracy trade‐offs  
  – Although the Trainable CRZ Ring Ansatz reaches 0.89 test accuracy, its increased depth (124) and parameters (206) reduce its combined performance by 0.07, underscoring the expressivity–complexity trade-off.  
- Generalization gap consistency  
  – Both the best program and richer ansätze (e.g., CRZ ring) achieve a gap of ~0.07, but the simpler chain-CZ structure attains this with 20% fewer parameters and 20% fewer gates.  
- Parameter efficiency plateau  
  – All valid models report efficiency ≈ 0.01, but only the best program converts this efficiency into the top combined score, highlighting that minimizing unnecessary parameters (146 vs. ≥ 170) is key to maximizing performance.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Replace each CZ entangler in a block with a single shared-parameter CRZ gate  
   – In your ANSATZ_SPEC, swap all CZ entries for CRZ gates using one new parameter key per block (e.g. `"param": "crz_block_{i}"`). This adds just one trainable angle per block controlling the entire linear chain’s phase, keeping depth and gate count fixed while testing if a tunable entangler phase can boost test accuracy without widening the generalization gap.  

2. Insert a sparse long-range CZ link in only odd-indexed blocks  
   – In `apply_ansatz_block`, after the standard CZ chain, conditionally append `qml.CZ(wires=[7,0])` when `block_index % 2 == 1`. This mutation preserves the simple chain-of-CZ structure in half the blocks but introduces a periodic ring-link that may capture end-to-end correlations at zero extra parameters in the even blocks.  

3. Move to per-qubit output gains and biases  
   – Extend the readout calibration from a single scalar gain and bias to 8 gains and 8 biases by slicing `params[N_CIRCUIT_PARAMS: N_CIRCUIT_PARAMS+8]` and `params[N_CIRCUIT_PARAMS+8: N_CIRCUIT_PARAMS+16]`. Then compute predictions as `mean_i [g_i·(⟨Z_i⟩ – b_i)]`. This adds 14 parameters over the 2-param scheme (net +14), allowing the model to weight each qubit’s contribution individually and potentially tighten the generalization gap further.  

4. Tie ansatz parameters across uploads for stronger regularization  
   – Instead of allocating distinct block parameters for each of the 3 uploads (i.e. 6 blocks), share a single set of `N_PARAMS_PER_BLOCK` weights across all upload repeats. Concretely, compute `offset = (block_index % N_REPEATS) * N_PARAMS_PER_BLOCK`, so that the two repeats within each upload and across uploads reuse the same parameters. This reduces total parameters by two-thirds in the circuit body, testing whether weight sharing can improve parameter efficiency and generalization.  

5. Alternate the CZ chain direction in even-indexed blocks  
   – Define two versions of the linear CZ chain in ANSATZ_SPEC: one ascending (`[0,1],[1,2],…`) and one descending (`[7,6],[6,5],…`). In `apply_ansatz_block`, when `block_index % 2 == 0` apply the descending chain spec, otherwise the ascending. This bidirectional entanglement pattern has zero impact on parameter count/depth but may enhance expressivity by mixing forward and backward information flow.
