# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Parameter sharing via identical param keys in ANSATZ_SPEC  
  • The ShinkaEvolve seed program (combined 0.86, 110 params) reuses each “rz_pre_i” key for both pre- and post-RZ rotations, halving unique parameters versus prior best (146 params → 110 params) while boosting the combined score from 0.85 to 0.86.  
- Pure ring-CRZ entanglement on a linear chain  
  • The seed program’s alternating CRZ-only ring (no CZ) on 8 qubits delivers train/val/test = 0.94/0.88/0.88 with a narrow gap (0.06), outperforming mixed CZ/CRZ layouts (e.g. Gen 25’s 8-Qubit Ring-Entangled QC scored only 0.84 with gap 0.08).  
- Triple IsingZZ feature-map re-uploads  
  • All top circuits (seed program, Gen 6, Gen 17, the 8-Qubit Ring Ansatz Binary Classifier Gen 24) use N_UPLOADS = 3, stabilizing validation accuracy at ≥0.88 and ensuring expressivity without overfitting.  
- Trainable readout gain and bias  
  • Adding two calibration parameters consistently yields generalization gaps of ~0.06–0.08 (seed program gap 0.06; Gen 24 gap 0.02), confirming output calibration as a reliable regularizer.  

## Ineffective Approaches  
- Mixing CZ with CRZ entanglers  
  • Gen 25’s alternating CRZ/CZ ring (110 params) underperformed pure-CRZ designs: combined 0.84 vs. 0.86 for the seed program, with higher gap (0.08 vs. 0.06) and no accuracy gain.  
- Over-parameterized ansätze  
  • The 8-Qubit Re-Uploading Ansatz Classifier (Gen 21, 194 params) reached only combined 0.79, and the Layered IsingZZ Ansatz (Gen 22, 170 params) 0.83, showing diminishing returns beyond ~150 params.  
- Extra two-qubit rotations (CRX/CRY)  
  • Incorporating CRX/CRY gates in Gen 22 did not improve test accuracy (0.87) or gap, indicating these gates add complexity without new expressivity.  
- Richer entanglement topologies  
  • Alternating CZ/CRZ or adding CZ gates increased depth/gate count but failed to boost combined scores over pure CRZ rings.  

## Implementation Insights  
- Reusing parameter keys in ANSATZ_SPEC  
  • Duplicating “rz_pre_i” entries in the spec and deriving unique keys via `validate_ansatz_spec` → `PARAMETER_KEYS_PER_BLOCK` halves the number of free parameters automatically.  
- Dynamic offset + key-to-position lookup  
  • Building a `{key: index}` map inside `apply_ansatz_block` lets each block fetch its shared or unique parameters without manual index arithmetic, simplifying block reuse.  
- Backpropagation on default.qubit QNode  
  • Using `@qml.qnode(..., diff_method="backprop")` yields near-zero gradient variance and stable convergence (~150 steps to threshold 0.90) in the seed program.  
- Automated metadata via AnnotatedQueue  
  • Capturing operations and computing depth through `qml.queuing.AnnotatedQueue` + `QuantumScript.from_queue` provides deterministic gate counts and depth metrics for fair benchmarking.  

## Performance Analysis  
- Combined score vs. parameter count  
  • The seed program’s 0.86 combined score exceeds the previous best 0.85 (Gen 6/17) despite only 110 params (vs. ≥146), demonstrating smart parameter sharing outperforms brute-force scaling.  
- Parameter efficiency gains  
  • Test-accuracy-per-parameter: seed program ≈0.88/110≈0.008 vs. previous best ≈0.87/146≈0.006, a ~30% boost in param efficiency.  
- Depth vs. generalization trade-off  
  • Raising depth from 99 to 120 (seed vs. prior best) reduced the generalization gap from ~0.07 to 0.06, showing depth penalties can be offset by parameter efficiency.  
- Performance plateau beyond ~150 params  
  • Circuits with >150 params (Gen 21/22/23) did not exceed combined 0.83, whereas compact designs (seed program, Gen 24) hit 0.86, highlighting the importance of ansatz compression.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Alternate CRZ‐ring direction every other upload  
   In your `circuit_z_expectations` loop, detect `upload_index % 2 == 1` and, for those uploads, reverse the wire order when applying the CRZ ring in `apply_ansatz_block` (i.e. use `[7,6], [6,5], …, [0,7]` instead of ascending). This zero‐cost bidirectional entanglement has been shown in other pure‐CRZ rings to diversify correlation pathways and may boost expressivity without adding parameters.  

2. Share block parameters across repeats within each upload  
   Change your offset calculation in `apply_ansatz_block` from  
     `offset = block_index * N_PARAMS_PER_BLOCK`  
   to  
     `offset = (block_index // N_REPEATS) * N_PARAMS_PER_BLOCK`  
   so that the two repeats in each upload share the same parameter vector. This ties weights more strongly (halving circuit parameters from 110→56+2 readout) and tests whether tighter parameter sharing further reduces the generalization gap, as seen with the seed program’s shared “rz_pre_i” keys.  

3. Inject a sparse long-range CRZ link in odd uploads  
   After your nearest‐neighbour CRZ loop, add for `upload_index % 2 == 1` a single `qml.CRZ(params[offset + key_to_position["crz_long"]], wires=[0, 4])` and append `"crz_long"` to `ANSATZ_SPEC` (only one key). This introduces just one extra trainable global entangler per odd upload to capture nonlocal features, probing if sparse long-range coupling improves accuracy without blowing up parameter count.  

4. Give each feature-map reupload its own CRZ strengths  
   Replace your global `"crz_a"`/`"crz_b"` keys in `ANSATZ_SPEC` with per-upload keys `"crz_a_u{u}"`, `"crz_b_u{u}"` for `u=0,1,2`. This adds only 4 parameters (from 110→114) but lets each upload independently tune its ring-entanglement strengths, building on the pattern that specialized feature-map parameters can lift expressivity.  

5. Per-upload readout gain and bias calibration  
   In `predict_batch`, slice out `gains = params[N_CIRCUIT_PARAMS : N_CIRCUIT_PARAMS+N_UPLOADS]` and `biases = params[N_CIRCUIT_PARAMS+N_UPLOADS : N_CIRCUIT_PARAMS+2*N_UPLOADS]` (6 vs. 2 params). Compute each upload’s raw mean `raw_u`, then form `pred = ∑_u gains[u] * (raw_u - biases[u])`. This multi-upload readout calibration extends the reliable trainable gain/bias regularizer, allowing per-upload thresholding that may shrink generalization gaps further.
