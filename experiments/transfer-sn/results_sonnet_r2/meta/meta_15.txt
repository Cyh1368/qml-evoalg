# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns

- Chain‐of‐CZ entanglement “sandwiched” by single‐qubit rotations  
  • The current best program (146 params, depth 99, gate_count 270) applies per‐qubit RY → pre‐RZ → linear CZ chain → post‐RZ in each block, achieving a combined score of 0.85 (train 0.94/val 0.89/test 0.87).  
  • This structure outperforms ring‐CRZ and closed‐ring variants (e.g., Gen 6 and Gen 10) by delivering comparable train accuracy but lower generalization gap and higher test accuracy with fewer gates.

- Fixed two-qubit IsingZZ feature‐map re-uploads  
  • Three uploads of the IsingZZ map are used consistently in the best program and all ≥ 0.85 combined‐score circuits (e.g., Gen 6’s CRZ ansatz also scores 0.85).  
  • This reuse of a non-trainable, expressive feature map balances circuit expressivity against overfitting.

- Trainable readout gain and bias calibration  
  • Including two readout parameters (gain, bias) at the end improves decision thresholds and helps maintain a modest generalization gap (~0.07 in the best program versus 0.12 in Gen 6).

- Controlled circuit complexity (“sweet spot” at ~100 depth, ~146 parameters)  
  • Reducing depth from 120 (Gen 6/Gen 14) to 99 while pruning parameters from ≥ 152 to 146 yields the highest combined score (0.85) and highest test accuracy (0.87).  
  • Models above this complexity (Gen 15: 170 params, depth 123, combined 0.84; Gen 11: 182 params, combined 0.78) underperform despite added layers.

## Ineffective Approaches

- Replacing fixed CZ with parameterized CRZ/CRX entanglers  
  • Gen 6’s CRZ-based blocks (156 params, depth 120) match train accuracy (0.98) but suffer a large gap (0.12) and no combined-score improvement over the best.  
  • Gen 10’s ring‐CRZ ansatz (146 params, depth 114, combined 0.79) yields moderate overfitting (gap 0.09) and lower test accuracy (0.86).

- Over-parameterized ansätze without pruning  
  • Gen 15 (170 params, depth 123) slightly lowers combined score to 0.84 despite minimizing gap (0.02).  
  • Gen 11 (182 params, depth 123) yields only 0.84 test accuracy and combined 0.78, showing extra parameters do not translate to better generalization.

- Deep circuits with mixed CZ/CRZ/CZ-ring entanglement  
  • Gen 14’s mixed‐CZ/CRZ approach (152 params, depth 120) delivers only combined 0.79, indicating that richer entanglement topologies can hurt parameter efficiency.

- Closed-ring or skipping entanglement patterns  
  • Closed-ring RY-RZ-RX (combined 0.69) and shared-parameter long-range skips (combined 0.77) underperform, showing that more connectivity does not compensate for the simplicity of linear CZ chains.

## Implementation Insights

- Strict ANSATZ_SPEC validation & deterministic parameter ordering  
  • The best program reports SPEC_ERRORS = 0 and uses `PARAMETER_KEYS_PER_BLOCK` to map params→gates, preventing misalignment and runtime errors.

- Parameter‐offset indexing for block reuse  
  • Computing `offset = block_index * N_PARAMS_PER_BLOCK` and a pre‐built `key_to_position` map reduces Python overhead in `apply_ansatz_block`, enabling consistent gate‐parameter assignments across repeated blocks.

- Autograd backpropagation on default.qubit  
  • Using `@qml.qnode(..., diff_method="backprop")` with stacked Z‐expectations across all qubits yields stable gradients (std ≈ 0.00) and smooth convergence in ~750 steps.

- Early stopping with weight restoration  
  • Validation‐loss patience = 75 and restoring best weights controls overfitting, contributing to the best program’s low generalization gap (0.07) and highest test accuracy.

## Performance Analysis

- Best program vs. top performers  
  • Current best (146 params, depth 99) achieves combined 0.85 and test 0.87, outperforming Gen 6 (156 params, depth 120, combined 0.85 but test 0.86, gap 0.12) and Gen 15 (170 params, depth 123, combined 0.84, test 0.85).

- Depth/parameter vs. generalization gap trade-offs  
  • Circuits deeper than 114 (Gen 10–15) show diminishing returns: deeper models hit combined ≤ 0.84 despite gaps as low as 0.02 (Gen 15).  
  • The best program’s moderate gap (0.07) paired with higher test accuracy underlines the efficacy of controlled complexity.

- Parameter efficiency plateau at ~0.01  
  • All valid models report efficiency ≈ 0.01, but only the best translates this into the top combined score, emphasizing that minimizing unnecessary parameters (146 vs. ≥ 152) is key.

- Test‐accuracy gains from simplifying ansatz  
  • Reducing layer count from 120 to 99 while preserving the feature-map reuploads and readout calibration yields a +0.02 lift in test accuracy (from 0.85 in Gen 15 to 0.87 in the best).

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Alternate CZ‐chain direction per upload  
   In `apply_ansatz_block`, compute  
     `upload_idx = block_index // N_REPEATS`  
   and, if `upload_idx % 2 == 1`, apply the CZ chain in descending order (wires=[[7,6],[6,5],…,[1,0]]) instead of the default ascending chain. This swaps forward/backward entanglement flow every other upload at zero extra parameters, exploiting bidirectional correlations shown to boost expressivity without raising depth.  

2. Inject sparse long‐range CZ links in odd blocks  
   After applying the standard linear CZ chain in `apply_ansatz_block`, add:  
     `if block_index % 2 == 1: qml.CZ(wires=[7,0])`  
   This periodic “end‐to‐end” coupling in half the blocks preserves the simple chain topology overall while capturing global correlations, building on the current best’s low‐overfitting CZ backbone.  

3. Share block parameters across the two repeats within each upload  
   Change the block‐offset logic to  
     `offset = (block_index // N_REPEATS) * N_PARAMS_PER_BLOCK`  
   so that both repeats in each upload reuse the same `N_PARAMS_PER_BLOCK` weights. This halves the circuit‐body parameters (from 144 to 72), testing whether weight tying further improves generalization at controlled expressivity.  

4. Parameterize every third CZ as a CRZ gate  
   In `ANSATZ_SPEC`, replace the CZ entries at positions 2, 5, and 8 of the chain with  
     `{"gate":"CRZ","wires":[i,i+1],"param":"crz_chain_{i}"}`  
   (one new key per block, e.g. `crz_chain_2`). This injects a single trainable entangler phase into each block’s chain, yielding minimal param growth (+6 total) to probe if slight tunability in the backbone can lift test accuracy without widening the gap.  

5. Calibrate outputs per upload with individual gains and biases  
   Instead of a single global gain/bias, allocate `2 * N_UPLOADS = 6` readout parameters:  
     `gains = params[N_CIRCUIT_PARAMS : N_CIRCUIT_PARAMS+3]` and  
     `biases = params[N_CIRCUIT_PARAMS+3 : N_CIRCUIT_PARAMS+6]`,  
   then compute per‐upload means `raw_u = mean_z(upload_u)` and combine as  
     `sum_u gains[u] * (raw_u - biases[u]) / N_UPLOADS`.  
   This tests whether per‐upload decision thresholds can further reduce the generalization gap observed with scalar calibration.
