<DESCRIPTION>
The current program uses a fixed FEATURE_SCALE = π/2 for encoding all 28 binary features via IsingZZ gates. This is a critical hyperparameter that directly controls the amplitude of data injection into the quantum circuit.

**Observation from prior programs:**
- Program 1 (score 0.91): Fixed FEATURE_SCALE, 26 params, test_accuracy 0.93
- Program 2 (score 0.92): Same fixed FEATURE_SCALE, 26 params, test_accuracy 0.91
- Current (score 0.90): Fixed FEATURE_SCALE, 32 params, test_accuracy 0.90

The current program has MORE parameters (32 vs 26) but LOWER test accuracy (0.90 vs 0.93), suggesting the ansatz is overfitting or the feature encoding is suboptimal.

**Proposed improvement:**
Make FEATURE_SCALE trainable by introducing a single global scalar parameter `phi_scale` that multiplies the fixed π/2 baseline. This allows the optimizer to learn the optimal data-encoding amplitude during training, decoupling the ansatz structure from the feature-map strength.

**Benefits:**
1. **Adaptive feature encoding**: The circuit learns how strongly to inject data, potentially improving generalization
2. **Minimal parameter overhead**: Only 1 new parameter (phi_scale), keeping total params reasonable
3. **Better feature-ansatz coupling**: Different ansatz structures may benefit from different encoding strengths
4. **Addresses overfitting**: By learning the encoding strength, we can reduce the train-test gap (currently 0.04)

**Implementation:**
- Add `phi_scale` as a trainable parameter in the readout params section
- Modify `feature_map()` to use `phi_scale * FEATURE_SCALE` instead of just `FEATURE_SCALE`
- Initialize `phi_scale` to 1.0 so the default behavior matches the current fixed scale
- Update N_READOUT_PARAMS from 2 to 3 (gain, bias, phi_scale)

This is a low-risk, high-impact change that leverages the observation that feature-map strength is a critical but currently fixed hyperparameter.
</DESCRIPTION>
