<DESCRIPTION>
The current program has 110 parameters with poor generalization (gap of 0.04, test accuracy 0.87 vs prior 0.93). The recommendation to make the feature-map strength trainable is well-motivated because:

1. **Separate Concerns**: The fixed feature map (FEATURE_SCALE = π/2) is applied identically across all data uploads, while the ansatz parameters are trained independently per upload. A trainable scale factor lets the circuit learn optimal encoding amplitudes.

2. **Parameter Efficiency**: Adding a single global "phi_scale" parameter is extremely cheap (1 parameter total) compared to the current 110 parameters. This leverages the separation of data-upload and variational layers.

3. **Overfitting Mitigation**: The current model has 110 parameters but only needs 26 (per prior runs) to achieve 0.93 test accuracy. The trainable scale adds adaptive feature encoding that may reduce the need for excessive ansatz parameters, improving generalization.

4. **Prior Evidence**: The seed program (26 params, 0.93 test accuracy) used shared parameters heavily and had minimal depth. The current program (110 params, 0.87 test accuracy) increased parameters without improving performance. A single trainable scale factor applied at feature encoding time can help the smaller ansatz learn better.

5. **Implementation**: Replace the constant `FEATURE_SCALE * records[..., k]` with `phi_scale * records[..., k]` in the feature_map function, and add phi_scale to the parameter vector. This is a minimal, surgical change that respects the fixed training loop and feature-map structure.

Expected outcome: Better validation/test accuracy, reduced train-test gap, and improved parameter efficiency by leveraging learned feature injection strength.
