The recommendation suggests introducing three per-upload amplitude scalars ("lambda_0", "lambda_1", "lambda_2") that dynamically weight the variational blocks across the three feature-map/upload cycles. This lightweight mechanism (adding only 3 parameters) can sharpen convergence and boost test accuracy by allowing the optimizer to learn which upload stages contribute most to the final prediction.

**Rationale:**
1. Prior search results show 0.93 test accuracy with 32 params and 0.92 with 20 params. The current program has 26 params and 0.93 test accuracy.
2. Adding 3 global lambda scalars (one per upload) is parameter-efficient and echoes role-based block scaling from prior searches.
3. Each lambda multiplies all block parameters within its corresponding upload cycle, enabling adaptive weighting of early vs. late variational blocks.
4. This can improve convergence speed (currently 270 steps mean) and reduce the validation loss (currently 0.32).
5. The scalars are initialized near 1.0 to avoid disrupting the current good performance while allowing fine-tuning.

**Implementation:**
- Add three new parameters: "lambda_0", "lambda_1", "lambda_2" to the initialization.
- Modify `apply_ansatz_block()` to scale parameters by the appropriate lambda before applying gates.
- Ensure the lambdas are initialized to ~1.0 so the circuit starts in a familiar regime.
