# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Layered RY→RZ→CZ→RZ block structure with three IsingZZ feature‐map uploads and two ansatz repeats (N_UPLOADS=3, N_REPEATS=2) yields top performance.  
  • “Layered 8-Qubit Reuploading Ansatz” (current seed) achieves combined score 0.85, test 0.85, gap 0.05, converging in ~720 steps—outperforming Generation 6 (score 0.84) and Generation 8 (score 0.78).  
- Fixed two-qubit IsingZZ encoding across 28 feature pairs provides a robust, expressive input layer.  
  • Present in all ≥0.84-score models (Gen 0, Gen 4, Gen 12, and current seed).  
- Two-phase RZ rotations (shared “rz_pre” before CZ chains and “rz_post” after) stabilize gradient flow and reduce parameter redundancy.  
  • The current best program uses just two RZ parameters per block yet matches higher-param designs (e.g., Gen 12’s 146 params) in accuracy.  
- Gain–bias readout calibration plus validation‐loss early stopping with best‐weight restoration enforces reproducible convergence (zero std deviation across runs).  

## Ineffective Approaches  
- Over-parameterized CRY/CRZ entanglers and long-range controlled rotations increase depth and parameters without boosting generalization.  
  • Gen 6 (shared CRY & CRZ, 158 params) attains score 0.84 (gap 0.08), Gen 8 (rich CRZ/CRY, 194 params) only 0.78 (gap 0.10).  
- Excessive depth reduction undermines expressivity: Generation 5’s shallow circuit (depth 81, 222 gates) scores 0.78 despite lower resource use.  
- Parity-based parameter sharing without accompanying CZ chain enhancements can stabilize performance but fails to surpass top patterns—Gen 7 (shared CRZ, 152 params) only 0.77.  

## Implementation Insights  
- Compact parameter key maps—using shared “rz_pre”/“rz_post” and a single “cry_a” per block—slash N_PARAMS_PER_BLOCK to 17 and total N_PARAMS to 68, maximizing parameter efficiency (0.01).  
- Chained nearest‐neighbor CZ entanglement plus cross‐block CZ edges ([0–2,1–3,…,5–7]) in the current seed program enhances qubit connectivity without heavy use of parametrized two-qubit gates.  
- Validating ANSATZ_SPEC upfront (validate_ansatz_spec) ensures gate dictionaries are correct and avoids runtime spec errors, leading to stable device execution.  
- Leveraging Pennylane’s backprop through qml.IsingZZ feature map and qml.AdamOptimizer permits efficient gradient flow across both data-encoding and variational layers.  

## Performance Analysis  
- Depth ≥114 and gate count ≥318 correlate with top combined scores (current seed: depth 126, gates 330 → score 0.85). Lower-depth designs fall to ≤0.78.  
- Generalization gap ≤0.07 is a reliable predictor of ≥0.85 combined score. The current program’s gap 0.05 is the smallest observed.  
- Models with ~70–110 parameters (seed 68, Gen 4 110) match or exceed those with ≥146 parameters, underscoring redundancy in over-parameterized designs.  
- Convergence around 700–750 steps for deep CZ-chain circuits versus ~330 steps for rich-entanglement models signals a trade-off: richer ansätze train faster but generalize worse.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Introduce parity‐based sharing for the RY rotations. Replace the eight per‐block parameters `ry_0`…`ry_7` with two keys, e.g. `ry_even` applied to qubits 0,2,4,6 and `ry_odd` applied to 1,3,5,7. Generation 4 showed that halving RY parameters in this way preserved test accuracy (>0.84) while cutting N_PARAMS_PER_BLOCK from 16 to 2, improving parameter efficiency.  

2. Tie each qubit’s pre‐ and post‐CZ RZ angles into a single per‐wire parameter. Instead of separate `rz_pre` and `rz_post` on each wire, use one key `rz_wire_k` for both rotations on qubit k. This halves the Z‐rotation count per block from 16 to 8 while retaining the two‐phase correction concept that stabilizes gradients in the current best program.  

3. Recycle a single block’s parameters across all uploads and repeats. Define one parameter set of size N_PARAMS_PER_BLOCK and apply it at every block_index, rather than independent params for each upload/repeat. This echoes the fixed IsingZZ backbone’s robustness and will test how much expressivity is inherent in the RY→RZ→CZ→RZ structure alone, potentially reducing total N_PARAMS from 68 to 17 without sacrificing depth.  

4. Increase ansatz depth via a third repeat per upload (N_REPEATS=3, N_UPLOADS=3). Keeping the same block order, this raises depth from ~126 to ~189 and gate count from ~330 to ~495. Since depths ≥114 correlated with top performance in the seed program, this variant probes whether additional CZ‐chain blocks can push test accuracy above 0.85 while maintaining a gap ≤0.07.  

5. Alternate CZ‐chain patterns between successive blocks to broaden connectivity. In odd‐indexed blocks use the current nearest‐neighbor plus cross‐block edges, and in even‐indexed blocks switch to simple linear CZ chains (0–1,2–3,…,6–7). This enriches qubit coupling pathways without adding parametrized two‐qubit gates, leveraging the proven generalizability of CZ entanglement while exploring new connectivity layouts.
