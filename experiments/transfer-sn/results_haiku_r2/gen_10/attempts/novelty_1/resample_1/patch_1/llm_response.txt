<DESCRIPTION>
The recommendation proposes implementing full block parameter recycling: instead of having N_PARAMS_PER_BLOCK × N_UPLOADS × N_REPEATS unique parameters, define only N_PARAMS_PER_BLOCK parameters and reuse them across all 6 block applications (3 uploads × 2 repeats per upload).

**Rationale:**
1. **Parameter efficiency**: Reduces total circuit parameters from 110×N_PARAMS_PER_BLOCK to just N_PARAMS_PER_BLOCK, which aligns with the proven success of the second prior program (68 params, 0.85 test accuracy).

2. **Leverage fixed backbone**: The fixed IsingZZ feature uploads already provide strong data-dependent correlation structure. A single shared ansatz block applied repeatedly can learn generic transformations that work across all re-uploads without needing per-upload specialization.

3. **Regularization through structure**: Parameter sharing acts as an implicit regularization, reducing overfitting risk. Prior program 2 showed that heavy parameter sharing (only 10 unique params) achieved validation_accuracy=0.87 with test_accuracy=0.85 and lower generalization_gap=0.05 vs. current 0.07.

4. **Faster convergence**: Fewer parameters converge faster in Adam optimization; prior program 2 converged in 720 steps vs. current 540. Reduced parameter space can balance convergence speed.

5. **Improved generalization**: The second prior program achieved slightly lower test loss (0.50 vs 0.45 currently, but with only 68 params vs 110). Full recycling reduces the parameter-accuracy ratio, potentially improving the `parameter_efficiency` metric crucial to the combined score.

**Implementation:**
Modify `apply_ansatz_block` to ignore `block_index` and always use offset=0, so all block applications share the same parameter set. This requires minimal code change and maintains the fixed training loop, feature map, and measurement pipeline.
</DESCRIPTION>
