# GLOBAL INSIGHTS SCRATCHPAD

The following are global insights about optimization approaches and their effectiveness:

## Successful Algorithmic Patterns  
- Parity-tied single-qubit rotations with CZ ring entanglement  
  • Generation 5’s “parity_tied_ring_block” tied RY/RX/RZ parameters across even/odd qubits (6 unique keys), interleaved with a linear CZ ring.  
  • Achieved combined_score_raw 0.87 (train 0.90, val 0.89, test 0.86) using only 38 parameters, improving on Generation 4’s 56-parameter design (combined 0.86).  
- Three re-uploads × two ansatz repeats  
  • Retaining N_UPLOADS = 3 and N_REPEATS = 2 preserved expressivity while controlling overfitting.  
  • Yielded a small generalization gap (0.04) and stable convergence (~270 steps), matching earlier observations that this layout balances depth and variance.  
- Trainable gain and bias calibration  
  • Decoupling a two-parameter readout layer (gain, bias) consistently sharpened decision boundaries across top performers.  
- Early stopping with best-weight restoration  
  • Across Generations 4–5, validation-loss early stopping (patience = 75, min_delta = 1e-4) prevented overtraining and locked in models with minimal generalization gap.  

## Ineffective Approaches  
- Fully independent per-qubit parameters  
  • Generations 6 (“ShinkaEvolve”), 7 (“hybrid_crz_cz_connectivity”), and 8 (“circular_entangled_ry_rz_ry”) each used 140+ parameters, depth 111+ and gate counts ≈264–300.  
  • Despite high training accuracy (up to 0.96), they suffered generalization gaps of 0.10–0.12 and low parameter efficiency (≈0.01), test accuracies ≤0.85.  
- Excessive entanglement patterns without sharing  
  • Gen 7’s mixed CRZ/CZ blocks and Gen 8’s custom CZ-chain+CRX design added depth (≈111) but only marginally improved validation accuracy (0.87→0.89) at the cost of heavier circuits.  
- Over-parameterized RY/RZ alternation  
  • Earlier linear CZ-chain models (Gen 0/1) reached high training fit but low combined_score_raw (≤0.71–0.84) and large gaps (0.07–0.15), showing diminishing returns beyond ~60 parameters.  

## Implementation Insights  
- ANSATZ_SPEC parameter sharing via string keys  
  • Defining six keys (“ry_even”, “ry_odd”, “rx_even”, “rx_odd”, “rz_even”, “rz_odd”) collapsed 32–56 per-block parameters down to 6, yielding N_PARAMS = 6×3×2+2 = 38.  
  • The `key_to_position` mapping mechanism ensures consistent parameter ordering with minimal code overhead.  
- Leveraging pennylane’s AnnotatedQueue for metadata  
  • Extracting depth (96) and gate_count (270) confirms that moderate circuit size correlates with top combined_score_raw.  
- Fixed IsingZZ feature map re-uploaded three times  
  • Reusing `feature_map(records)` 3× maintains encoding fidelity; combining with lightweight blocks boosts representation while capping gate count.  
- Autograd interface with pnp arrays  
  • Using `pnp.array(..., requires_grad=True)` and `qml.AdamOptimizer` ensures efficient backpropagation and stable parameter updates even in shared-parameter regimes.  

## Performance Analysis  
- Combined_score_raw progression  
  • Gen 4 (“symmetry_shared_low_param_block”): 0.86 with 56 parameters, depth 81, gate count 252, gap 0.06.  
  • Gen 5 (“parity_tied_ring_block”): 0.87 with 38 parameters (–32%), depth 96 (+18%), gate count 270 (+7%), gap 0.04 (–33%).  
- Parameter efficiency doubling  
  • Efficiency (test_acc / n_params) rose from ≈0.015 in Gen 4 to 0.023 in Gen 5, confirming that tighter parameter sharing pays dividends.  
- Trade-off between depth and generalization  
  • Small depth increase (+15) in Gen 5 did not harm generalization; indeed, test accuracy held at 0.86 versus earlier deep designs (depth 111–126) which dropped to 0.81–0.85.  
- Convergence speed vs. expressivity  
  • Gen 5 converged in ~270 steps, slower than Gen 4’s ~60 steps but still an order of magnitude faster than 720–750 steps for over-parameterized models, striking a favorable expressivity-vs.-training-cost balance.

# META RECOMMENDATIONS

The following are actionable recommendations for the next program generations:

1. Introduce a shared CRX layer per ansatz block. After your CZ ring in ANSATZ_SPEC, insert  
   `{"gate": "CRX", "wires": [0,1], "param": "crx_parity"}, …` for the four parity pairs (0–1, 2–3, 4–5, 6–7), all using the single key `"crx_parity"`.  
   Evidence: Gen 4’s CRZ sharing halved parameters while preserving entanglement; adding one extra shared two-qubit rotation should boost expressivity with only one extra parameter per block (→44 total), likely improving combined_score_raw without a major generalization penalty.

2. Interleave two shared‐parameter entangling patterns within each block. Extend ANSATZ_SPEC so that after your CZ ring you apply a parametric CRZ on “shifted” neighbors—pairs (1–2, 3–4, 5–6, 7–0)—all keyed by `"crz_shift"`. Keep your original CZ ring unmodified, so each block now has both the fixed CZ and one shared CRZ, adding just one new key per block.  
   Evidence: Alternating adjacency and next-neighbor couplings captures richer correlation structure (cf. Gen 7’s mixed CRZ/CZ) while shared keys cap parameter count; this should increase expressivity at modest depth cost.

3. Refine single-qubit rotation sharing into four groups. Replace your even/odd RY/RX/RZ keys with group-of-two keys: `"ry_01"`, `"ry_23"`, `"ry_45"`, `"ry_67"` (and similarly for `"rx_*"` and `"rz_*"`), applying each to the corresponding qubit pair.  
   Evidence: Gen 4’s two‐group sharing improved bias–variance; a finer four-group split (12 circuit parameters per block) strikes a balance between the current 6-key scheme and fully independent rotations and may close residual underfitting gaps.

4. Swap the upload/repeat ratio to 2 re-uploads × 3 ansatz repeats. In the program constants set `N_UPLOADS=2, N_REPEATS=3` (leaving ANSATZ_SPEC unchanged).  
   Evidence: The 3×2 layout in Gen 5 converged in ~270 steps with good generalization; increasing depth via more repeats but fewer re-uploads may boost expressivity per overall gate count while retaining sharing‐induced regularization.

5. Split readout calibration by parity. Instead of a single `gain` and `bias`, introduce `gain_even`, `gain_odd`, and a shared `bias`. Compute raw_even = mean〈Z〉 over even wires and raw_odd over odd wires, then output `gain_even*raw_even + gain_odd*raw_odd - bias`.  
   Evidence: Trainable gain/bias sharpen decision boundaries; per-parity calibration adds only two extra parameters (→40 total) but can adapt differently to systematic shifts in even vs. odd qubit signals, potentially reducing generalization gap.
