add_ring_entanglement_and_crz_layer

<DESCRIPTION>
The current ansatz block uses only a linear chain of CZ gates for entanglement, which limits information mixing between distant qubits (e.g., qubit 0 and qubit 7 are only connected through 6 hops). This can hurt expressivity and generalization. I propose:

1. Close the entanglement chain into a ring by adding a CZ between qubit 7 and qubit 0, giving every qubit two entangling neighbors instead of the endpoints having only one.
2. Replace the fixed CZ gates with parametrized CRZ gates sharing parameters in a "brick-like" pattern (same param per gate to keep parameter count controlled), so the entangling strength becomes trainable rather than fixed at maximal (CZ = CRZ(pi)). This gives the optimizer more flexibility to learn how strongly to couple neighboring qubits, which should improve trainability and reduce the train/test gap while adding only 1 extra parameter per block (the shared CRZ angle) plus one for the ring closure link.

This keeps the same gate count/depth roughly the same, and only marginally increases parameter count per block (10 -> 12 params per block, well within budget), while giving the optimizer control over entanglement strength and better connectivity via a ring topology.
